# 03 - 侵蚀 / 水文 / 地貌演化 算法调研

> 调研对象：把「噪声地形」改造成「像地球的大陆」的侵蚀、水文与地貌演化（LEM）类算法与工具。
> 目标项目：Minecraft 1.7.10 模组「塔洛斯经纬」——X 轴无限非周期、Z 轴 2000 万周期代表纬度、运行时 (x,z,seed) 直接求值、块级 16x16 精度、Java、性能接近纯噪声。
> 硬指标：内海数 = 0（或极少）、无散落小岛、海岸线分形维数 D≈1.2~1.4、陆地占比可标定、地球式**双峰高程**（大陆台地 ≈ +0.3 km / 深海盆地 ≈ -4 km）。

## 0. 三条总纲（先读这个，再看条目）

**总纲 1：侵蚀算法几乎都不是 O(1) 的，但「侵蚀的产物」通常是低维的。**
除极少数例外（解析解、域扭曲代理），所有真实侵蚀都是迭代式 PDE 或图松弛：需要全流域的汇流累积（flow accumulation），汇流是**全局依赖**。这直接违反「零预计算 / 内存里不存全局地图」。因此真正能搬进 1.7.10 运行时的用法只有三种：

- **(a) 离线 / 有限范围烘焙**：在 2048²~8192² 的低分辨率控制网格上跑侵蚀，把产出压成若干 2D 控制场（例如「地势起伏度」「河谷密度」「准平原化程度」），运行时双线性采样 + 程序化噪声补细节。这些控制场本质上是「更聪明的 continent mask」。
- **(b) 当作参数标定工具，而不是运行时算子**：用侵蚀模型离线跑出「陆地占比 × 双峰高程 × D 值」的相图，反推运行时噪声的参数（坡度、ridge 权重、海岸带衰减半径），运行时只跑噪声。这是性价比最高的一条。
- **(c) 用 O(1) 代理**：域扭曲（domain warp）+ 坡度门控噪声 + 沿「到海岸距离」的单调下降约束，可在纯噪声里伪造出约 70% 的侵蚀观感（见 §7.6、§8.6）。

**总纲 2：双峰高程分布几乎不可能由侵蚀单独产生。**
双峰（+0.3 km 大陆台地 / -4 km 深海盆地）本质是**地壳厚度 + 均衡（isostasy）**的产物，侵蚀只负责把大陆台地内部雕出山脉与盆地、把大陆坡切出峡谷。所以运行时管线里，双峰必须来自「构造 / 掩膜层」，侵蚀层的职责是：(i) 让大陆台地**内部**有合理起伏而不是白噪声；(ii) 保证**任何内陆洼地都能排水到海**（内海 = 0）；(iii) 抬高海岸线分形维数。

**总纲 3：「内海 = 0」的真正技术名字叫 depression filling / breaching。**
这不是侵蚀问题，而是**水文条件化（hydrologic conditioning）**问题。已有成熟且高效（O(n log n)、可并行、可局部化）的算法：Priority-Flood 及其变体。这是本清单里**最容易直接落地**的一类，见 §6。

## 1. 粒子 / 液滴式水力侵蚀（Droplet / Particle-based Hydraulic Erosion）

> 共同特征：把水离散成一粒粒「水滴」，每粒水滴在高度场上做「下落 → 冲刷 → 搬运 → 沉积 → 蒸发」的固定循环。**每粒水滴只访问局部邻域**，因此天然可并行、易 GPU 化、易局部化。这是「能在运行时跑」的唯一一大类真实侵蚀。
> **对本项目的关键含义**：液滴算法是**局部**的（作用半径约数十格），所以理论上可以在区块（chunk）生成时用「chunk + halo」的方式本地跑 N 粒水滴；只要水滴的随机种子由 (chunkX, chunkZ, seed) 决定，就是确定性的、可无限外推的。代价是 chunk 边界会出现侵蚀不连续——这是本类算法在无限世界上**唯一真正的工程难点**。

### 1.1 Hans Theobald Beyer — Implementation of a Method for Hydraulic Erosion (2015)
- **链接**：参考实现 erodr（C，MIT）https://github.com/henrikglass/erodr ；论文 PDF 社区镜像 https://www.dropbox.com/scl/fi/m3ylcbvfdk6nue4czxr68/Beyer-implementation-of-a-methode-for-hydraulic-erosion.pdf?rlkey=xx9illjh1gag7kwdvuywt9h5k&e=1&dl=0
- **原理一句话**：在高度场上撒随机水滴，每滴水沿最陡下降方向移动，按「速度 = f(坡度, 水量)」携带沉积物，坡度缓则沉积、坡度陡则冲刷，最后蒸发并把残余沉积物留在原地。
- **类别**：粒子式水力侵蚀（droplet erosion）。
- **输出范围**：有限地图（在给定高度场数组上原地修改）；代码本身不含坐标概念，可改造为无限。
- **实时性**：运行时 O(1) 求值——是（但常数大：实际是「每 chunk 一次性付 O(chunk 面积 × 水滴数)」）。
- **双峰高程**：否。只雕琢已有地形，不生成大陆 / 盆地两级台地。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：均不产生。仅在**已有大陆坡**上刻出海底峡谷雏形。
- **内海与孤岛**：不处理内海（水滴汇入洼地即停，洼地仍是洼地）；会在缓坡上沉积出小丘，可能加剧孤岛感。
- **语言 / 依赖 / 许可证 / star**：C（erodr，MIT，约 51★，2025 年仍有提交）；原论文为 FAU 学士论文，无正式 DOI。
- **可借鉴点**：
  1. **参数极少的调参入口**：全部旋钮只有惯性 inertia、沉积容量 sediment capacity、蒸发 evaporation、侵蚀半径 erosion radius、最大寿命 max lifetime、重力 gravity 六个，极适合做「一个浮点参数 = 一种地貌风格」的预设（缓丘 / 峡谷 / 幼年山地）。
  2. **erodr 是纯 C、近单文件实现**，最容易逐行翻译成 Java（无 SIMD、无第三方依赖），建议作为第一版原型的参考实现。
  3. **关键改造（接缝问题）**：不要按 chunk 独立跑水滴。改为「按**全局格坐标**哈希洒水滴」——水滴初始位置 = hash(seed, i) 映射到无限平面，每滴水只在半径 R 内改写高度；查询某方块高度时，遍历所有可能影响它的水滴集合。当 R 远小于 chunk 尺寸（例如 R=8 格、chunk=16 格）时，每区块只需检查 3×3 邻域内的水滴，可做到 O(1) 且**完全无缝**。
  4. 若嫌上述太贵，退化为「每 chunk 局部跑水滴 + 只在 chunk 内部生效（halo 只读不写）」，接缝处用 8~16 格线性淡出权重混合，视觉上几乎不可见。

### 1.2 Sebastian Lague — Hydraulic-Erosion（Unity / Compute Shader）
- **链接**：https://github.com/SebLague/Hydraulic-Erosion
- **原理一句话**：Beyer 式液滴侵蚀的 GPU 化版本，每帧在 compute shader 里发射数十万水滴，用「侵蚀 / 沉积刷子（brush）」在纹理上做核卷积沉降。
- **类别**：粒子式水力侵蚀（GPU 实现 + 教学可视化）。
- **输出范围**：有限地图（固定分辨率 RenderTexture）。
- **实时性**：运行时 O(1) 求值——是（GPU 并行）；CPU 单线程复刻明显变慢。
- **双峰高程**：否。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：均不产生。
- **内海与孤岛**：不处理。
- **语言 / 依赖 / 许可证 / star**：C# / HLSL，Unity，MIT，约 1041★（2024 仍有提交）。
- **可借鉴点**：
  1. **刷子（brush）实现**是最大的工程启发：把「沉积」写成对一个预计算圆形权重核的加权叠加，而不是逐格散射——每粒水滴的写入因此连续、缓存友好。Java 里可用一张 16×16 float 权重表 + 逆距离查找表复刻。
  2. **参数面板即调参区间**：sedimentCapacityFactor / minSedimentCapacity / erodeSpeed / depositSpeed / evaporateSpeed / gravity / maxDropletLifetime / initialWaterVolume / inertia，可直接照搬为项目的常量命名空间。
  3. **注意**：它是 GPU 纹理原地迭代，**不是确定性可外推**的；作为「观感参考」和「参数标定」用途远大于运行时算法。

### 1.5 dandrino — terrain-erosion-3-ways（三种主流算法的并排参考实现）
- **链接**：https://github.com/dandrino/terrain-erosion-3-ways （核心文件 https://github.com/dandrino/terrain-erosion-3-ways/blob/master/river_network.py ）

- **可借鉴点**：

  2. **三种算法的观感差异**（液滴 → 圆润冲沟；河道网络 → 树枝状深谷；坡面扩散 → 平缓准平原）是把「地形风格」参数化的最佳教学材料。
  3. 代码里「从每个洼地找最低出流点」就是简化版 depression breaching，可直接改写成 Java 的 fillDepressions() 工具函数用于离线阶段。

## 2. 网格 / GPU 水力侵蚀（Shallow-water / Virtual-pipes / Velocity-field）

> 共同特征：把高度场当成规则网格，用**显式有限差分**同时演化「水高 + 悬移质」两个场，水按虚拟管道（virtual pipes）或浅水方程在格间流动，流速决定挟沙能力，挟沙不足则冲刷、过量则沉积。
> **对本项目的关键含义**：这类算法需要 **N 次全局迭代**（每步都要遍历整张图），是「最不能进运行时」的一类；但它们是**离线烘焙**的主力，也是「水体 / 河谷 / 冲积扇」观感的源头。

### 2.1 Mei, Decaudin, Hu — Fast Hydraulic Erosion Simulation and Visualization on GPU (Pacific Graphics 2007)
- **链接**：https://hal.sorbonne-universite.fr/LJK_GI/inria-00402079v1 （HAL 全文）
- **原理一句话**：把「水层 + 悬移质层」两场放在 GPU 上用多重网格显式迭代，水按虚拟管道交换、按流速挟沙，几十步内即可看到河道自发涌现。
- **类别**：网格水力侵蚀（虚拟管道，GPU）。
- **输出范围**：有限地图（GPU 纹理原地迭代）。
- **实时性**：需离线全局模拟——每次迭代都是全图遍历；GPU 上可交互，CPU 上不可。
- **双峰高程**：否。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生；但会自发形成**树枝状水系与冲积平原**，是「大陆内部像地球」的关键。
- **内海与孤岛**：**不处理，反而会制造内海**——水会积在局部洼地里形成湖泊，且蒸发后留下沉积。这是本项目必须警惕的副作用。
- **语言 / 依赖 / 许可证 / star**：论文无开源代码；被 Houdini / Gaea / World Machine 等广泛实现。
- **可借鉴点**：
  1. **两场（水高 + 悬移质）+ 虚拟管道**的结构极简，是「离线烘焙器」最容易实现的一版：Java 里用 float[] 表示两个场，迭代 200~500 步即可。
  2. **关键洞察**：Mei 类算法在**有出海口的斜坡上**表现最好。若你的底图已经是「大陆台地 → 大陆坡 → 深海盆地」，跑 Mei 就能自动得到水系 + 海底峡谷；若底图有内陆洼地，它会先变成千湖之国。所以**必须先做 §6 的 depression filling，再跑 Mei**。
  3. **多重网格（multigrid）加速**是它真正的贡献：先在 1/4 分辨率上迭代收敛，再上采样做残差修正，可把迭代次数降一个数量级。离线烘焙 8192² 时非常有用。

### 2.2 Št'ava, Beneš, Brisbin, Krivánek — Interactive Terrain Modeling Using Hydraulic Erosion (SCA 2008)
- **链接**：https://www.cs.purdue.edu/cgvlab/www/publications/Stava08SCA/ ；EG Digital Library 条目 https://diglib.eg.org/items/60afda0c-a666-4df8-90dd-9b80afc554c2/full
- **原理一句话**：用「虚拟管道 + 悬移质」模型做交互式地形编辑，用户刷一笔山脊，侵蚀会自动把坡面调整成合理的水系与坡折，并支持「侵蚀后再雕刻」的来回编辑。
- **类别**：网格水力侵蚀（虚拟管道，交互式）。
- **输出范围**：有限地图。
- **实时性**：需离线全局模拟（但论文证明中等分辨率下可交互）。
- **双峰高程**：否。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。
- **内海与孤岛**：**论文专门讨论了「如何避免侵蚀产生的伪洼地」**，并给出把水排向边界的处理，是内海问题的重要参考。
- **语言 / 依赖 / 许可证 / star**：论文；无官方开源实现。
- **可借鉴点**：
  1. **「雕刻 → 侵蚀 → 再雕刻」的来回编辑范式**，启发本项目不必一次算完：可以先生成基础高度场，用侵蚀把不合理的地方（陡崖、封闭洼地）修掉，再叠加细节噪声。
  2. 论文对**稳定性条件**（CFL 数、管道通量钳制）的描述，是 Java 实现时避免数值爆炸的直接依据。
  3. 其「边界排水」设定（把地图边缘当出海口）在无限世界里不成立，**必须替换为「海岸线排水」**——即只允许水流向低于海平面的格子。

### 2.3 Beneš, Forsbach — Layered Data Representation for Visual Simulation of Terrain Erosion (SCCG 2001)
- **链接**：https://www.cs.purdue.edu/cgvlab/www/publications/Benes01SCCG/

- **输出范围**：有限地图。
- **实时性**：需离线全局模拟（早期 CPU 实现，很慢）。

## 3. 河道下切 / 坡面演化物理模型（Stream Power Law 与 LEM）

> 共同特征：把地貌演化写成一条偏微分方程——抬升 = 河道下切（stream power）+ 坡面扩散（hillslope diffusion）+ 搬运 / 沉积。这是**地质学界公认的「地球表面为什么长这样」的方程**，也是把噪声变成「真大陆」的理论依据。
> **对本项目的关键含义**：LEM 是「双峰高程」之外真正决定**大陆内部形态**的东西。它们几乎全部需要全局迭代，但其中的**河道下切项（stream power）对地形的塑造可以用一个静态代理近似**：地形起伏度与「到出海口的水力距离」负相关。这条规律是本项目最值得榨取的免费午餐。

### 3.1 Braun & Willett (2013) — O(n) 隐式并行 stream power 求解
- **链接**：https://www.sciencedirect.com/science/article/pii/S0169555X12004618 （Geomorphology 180-181, 170-179）
- **原理一句话**：把 stream power 方程离散成「沿河道从下游向上游逐个格点求解」的隐式格式，只需按汇流顺序遍历一次，就得到无条件稳定的 O(n) 解——这是让 LEM 从「跑一夜」变成「跑几秒」的里程碑。
- **类别**：河道下切 / stream power law（数值方法）。
- **输出范围**：有限地图（但算法本身是 O(n) 一次遍历，**性质上最接近可局部化**）。
- **实时性**：需离线全局模拟（每个时间步 O(n)，但需要多步；单步比显式格式便宜一到两个数量级）。
- **双峰高程**：否（需要抬升场提供双峰）。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生；但会在给定抬升场上生成**与抬升速率正相关的高程**，即「构造 → 地形」的正确映射，是生成山脉与高原的正确方式。
- **内海与孤岛**：不直接处理，但隐式格式天然向下游搬运，能显著减少内陆洼地。
- **语言 / 依赖 / 许可证 / star**：算法；参考实现见 §3.2（fastscapelib-fortran，Fortran + Python，GPL-3.0，约 26★）。
- **可借鉴点**：
  1. **「按汇流顺序自下而上遍历一次」的思想可用于离线烘焙的加速**：先算 D8 / D∞ 流向，再按拓扑序解一次，比跑 1000 步显式迭代快得多。这是离线烘焙 8192² 网格能在一分钟内完成的关键。
  2. **对本项目最直接的价值 = 标定**：用 fastscape 跑小规模实验，找出「抬升速率 K、可蚀性 m/n 指数、扩散系数」与「最终地形起伏 / 河谷密度 / 海岸线分形维数」的关系表，然后把这些数字写死成运行时噪声的参数。
  3. 隐式格式的稳定意味着**可以用很大的时间步**，因此「跑 100 步就收敛」是可能的——这为「离线烘焙一张 2048² 控制场只需几秒」提供了理论保证。

### 3.2 Fastscape / fastscapelib（Braun、Cordonnier 等）
- **链接**：官网 https://fastscape.org/ ；组织 https://github.com/fastscape-lem ；Python 前端 https://github.com/fastscape-lem/fastscape ；Fortran 核心 https://github.com/fastscape-lem/fastscapelib-fortran ；文档 https://fastscape.readthedocs.io/en/latest/
- **原理一句话**：把 §3.1 的隐式 stream power、Erosion-Deposition（Davy-Lague）、坡面扩散等算子做成可组合的库，用 xarray 做前端，几十行就能拼出一个 LEM。
- **类别**：LEM 框架 / 库。
- **输出范围**：有限地图（规则网格，可开边界 / 周期边界）。
- **实时性**：需离线全局模拟。
- **双峰高程**：否（需要外部抬升场；但它支持任意 uplift 网格，因此可以喂入「双峰掩膜」）。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生；但 Erosion-Deposition 算子会生成**冲积平原与沉积盆地**，有助于形成大陆架式的平缓边缘。
- **内海与孤岛**：提供 flow routing（含洼地处理），是内海问题的参考实现。
- **语言 / 依赖 / 许可证 / star**：Python + Fortran；fastscape 为 BSD-3-Clause（约 76★），fastscapelib-fortran 为 GPL-3.0（约 26★，注意 GPL 传染性）。
- **可借鉴点**：
  1. **最推荐作为本项目的离线标定工具**：Python 生态，几行代码就能生成 1024² 地形并统计高程直方图、陆地占比、海岸线分形维数，直接回答「我的参数能不能达成 D≈1.2~1.4」。
  2. **注意 GPL-3.0**：fastscapelib-fortran 是 GPL，**不能把它的代码搬进闭源模组**；只能用来生成/标定数据（数据本身不受 GPL 约束，但仍建议只借鉴参数与结论）。
  3. fastscape 支持 **periodic boundary**，这正好对应本项目 Z 轴 20000 km 周期的纬度环——做标定时应打开周期边界，否则南北边缘会失真。

### 3.4 Badlands / pyBadlands（Salles 等，2019）
- **链接**：论文 https://gmd.copernicus.org/articles/12/2571/2019/ ；代码 https://github.com/badlands-model/badlands
- **原理一句话**：在非规则三角网格上耦合「构造抬升 + 河道 / 坡面侵蚀 + 沉积物输运 + 地层记录」的源-汇（source-to-sink）模型，能把侵蚀产物真正沉积到海底形成大陆架 / 深海扇。
- **类别**：LEM / 源-汇耦合模型。
- **输出范围**：有限地图（三角网格）。
- **实时性**：需离线全局模拟。
- **双峰高程**：**部分**——因为它同时模拟抬升与沉积，长期演化会自然形成「高台地 + 深盆地」的两级分布，是本清单里最接近双峰的一类。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：**大陆架与大陆坡是它的核心输出**（沉积物堆积形成陆架、陆坡自然形成）；岛弧 / 海沟 / 洋中脊不产生（那是构造模块的事）。
- **内海与孤岛**：通过沉积填充洼地，间接减少内海。
- **语言 / 依赖 / 许可证 / star**：Python（+ C 扩展、MPI），LGPL-3.0，约 192★。
- **可借鉴点**：
  1. **「沉积物去哪儿」这一维是纯侵蚀算法缺的**：大陆架之所以平坦、大陆坡之所以陡，很大程度是沉积物堆积的结果。运行时可用一个极廉价的代理：**在「到海岸距离」小于某阈值处把高度往海平面附近的平台压平**（模拟陆架），超过阈值后按陡坡下降（模拟陆坡）。
  2. LGPL-3.0 对模组不友好（动态链接义务），**只用于离线生成控制场，不要嵌代码**。
  3. 用 Badlands 跑一次「有陆架 vs 无陆架」的对照，可以直接量出陆架对海岸线分形维数 D 的影响。

- **原理一句话**：把 LEM 从区域尺度推广到**全球尺度**（球面 / 大网格、非规则网格、并行），并在同一框架里耦合侵蚀、沉积、挠曲均衡与海平面。

- **双峰高程**：**是（最有希望的一类）**——因为耦合了挠曲均衡（flexure）与沉积，长期演化后大陆与洋盆会自然分成两级。

### 3.6 LSDTopoTools / MuddPILE
- **链接**：软件主页 https://simon-m-mudd.github.io/software/LSDTopoTools/ ；LEM 文档 https://www.geos.ed.ac.uk/~smudd/LSDTT_docs/html/model.html ；MuddPILE https://lsdtopotools.github.io/LSDTT_documentation/LSDTT_MuddPILE.html ；代码 https://github.com/LSDTopoTools/LSDTopoTools2
- **原理一句话**：面向真实 DEM 的「地形分析 + 流域尺度 LEM」工具链，强项是**从真实 DEM 里提取河道、计算 χ（chi）与陡峭指数**，从而反演抬升率。
- **类别**：DEM 分析 + LEM（流域尺度）。
- **输出范围**：有限地图（真实 DEM 或合成 DEM）。
- **实时性**：需离线全局模拟 / 需全局预计算缓存。
- **双峰高程**：否。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。
- **内海与孤岛**：有完整的洼地处理与流域划分。
- **语言 / 依赖 / 许可证 / star**：C++，GPL-3.0，约 37★。
- **可借鉴点**：
  1. **χ（chi）变换是本项目最值得偷的概念**：χ = ∫(A0/A)^(m/n) dx 沿河道积分，它把「河道高程」变成一条**与抬升率线性相关、且空间上可比较**的坐标。在运行时，可以用一个廉价的近似 χ（到出海口的水力距离）来驱动地形起伏，从而让山脉高度沿河道自然平缓变化，而不是噪声式跳变。
  2. **「用真实 DEM 反演参数」的工作流可以直接用来标定本项目**：拿一块真实大陆（例如东亚或北美）的 DEM，用 LSDTopoTools 算出它的 χ、陡峭指数、河谷密度与海岸线分形维数，然后调节运行时噪声去匹配这些统计量。这比凭感觉调更有说服力。
  3. GPL-3.0，只做离线分析。

### 3.7 TopoToolbox 2 / 3（Schwanghart & Scherler）
- **链接**：官网（含文档与教程） https://topotoolbox.github.io/ ；TopoToolbox 2 论文（Earth Surface Dynamics 2, 1-7, 2014） https://authors.library.caltech.edu/records/bp613-2f385 ；TopoToolbox 3 代码 https://github.com/TopoToolbox/topotoolbox3
- **原理一句话**：MATLAB 上的 DEM 水文与地形分析工具箱，主打「从 DEM 自动提取河流网络（STREAMobj）并沿河道做剖面 / 陡峭指数 / χ 分析」。
- **类别**：DEM 水文分析工具箱。
- **输出范围**：有限地图。
- **实时性**：需全局预计算缓存（对整张 DEM 建流向图）。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。
- **内海与孤岛**：有成熟的洼地填充 / 河流网络提取。
- **语言 / 依赖 / 许可证 / star**：MATLAB（v3 需 MATLAB R2021b+），GPL-3.0，约 24★。
- **可借鉴点**：
  1. **STREAMobj 的「河道按拓扑排序，可做沿程运算」的数据结构**极适合抄成 Java 的离线工具：先建流向图，再沿河道做一次扫描，就能得到全图的水力距离 / χ，最后导出成一张 2D 控制场。
  2. **注意 MATLAB 授权**：只能用于离线分析，产出的数据可以自由使用。

### 3.8 CHILD（Tucker 等）— Channel-Hillslope Integrated Landscape Development
- **链接**：模型条目 https://czo-archive.criticalzone.org/calhoun/models/model_details/child-model/ ；论文（Tucker, Lancaster, Gasparini, Bras，1999/2001）
- **原理一句话**：最早把「河道（stream power）+ 坡面（非线性扩散）+ 土地滑移」统一在**不规则三角网 + 随机降雨事件**上的 LEM，是后来所有 LEM 的祖师爷之一。
- **类别**：LEM（事件驱动、非规则网格）。
- **输出范围**：有限地图。
- **实时性**：需离线全局模拟。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。**内海与孤岛**：不专门处理。
- **语言 / 依赖 / 许可证 / star**：C/C++（历史版本），公开但许可证需自行确认；已基本停止维护。
- **可借鉴点**：
  1. **「随机降雨事件」而非「恒定降雨」的驱动方式**：这提示地形的不均匀性可以来自**时间维的随机性**而不是空间维的噪声，是「用噪声伪造侵蚀」的一个理论支撑。
  2. **非规则网格上做汇流**的思路在无限世界里没有直接用处（本项目的自然网格是方块），**可借鉴度低**，仅作历史脉络收录。

### 3.9 Davy & Lague (2009) — 河道侵蚀 / 输运方程再审视
- **链接**：https://agupubs.onlinelibrary.wiley.com/doi/10.1029/2008JF001146 （JGR Earth Surface 114, F03007）
- **原理一句话**：指出经典 stream power 只适用于「基岩河道」，真实的冲积河道应为「输运受限」形式——挟沙量由流量与坡度共同决定，超过则沉积、不足则冲刷，从而统一解释河道下切与冲积平原。
- **类别**：河道侵蚀 / 输运理论。
- **输出范围**：理论 + 有限地图模拟。
- **实时性**：需离线全局模拟。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：其输运-沉积统一框架是**大陆架沉积**的理论基础。
- **内海与孤岛**：沉积项会填充洼地，间接减少内海。
- **语言 / 依赖 / 许可证 / star**：论文；已被 fastscape / Landlab 的 ErosionDeposition 组件实现。
- **可借鉴点**：
  1. **E/D（侵蚀-沉积）统一公式给了「上下游不同地貌」的开关**：同一个噪声场，在上游参数下变成峡谷、下游参数下变成冲积平原。运行时可以用「到海岸距离」作为这个开关，成本几乎为零。
  2. 这条规律是本项目实现「大陆内部有平原也有山地」的最廉价手段：**用同一个 fBm 噪声，但让它的权重随「到海岸距离」变化**（近海 → 平原，内陆 → 山地）。

### 3.10 Terra Antiqua（QGIS 插件，古地理重建）
- **链接**：插件页 https://plugins.qgis.org/plugins/terra_antiqua/ ；论文（Earth-Science Reviews, 2023）
- **原理一句话**：在 QGIS 里把「古地理重建」流程化：输入板块边界与古高程控制点，用插值 + 侵蚀 / 沉积规则生成古地形与古水深图。
- **类别**：古地理 / 古地形重建工具（GIS 工作流）。
- **输出范围**：有限地图。
- **实时性**：需离线全局模拟 / 需全局预计算缓存。
- **双峰高程**：**是**——因为它显式区分陆地与洋壳，输出天然是两级。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：显式支持被动大陆边缘 / 大陆架 / 海沟等地貌单元的标注与重建，是本清单里**地貌单元最齐全**的工具。
- **内海与孤岛**：通过人工编辑与规则化处理。
- **语言 / 依赖 / 许可证 / star**：Python（QGIS），GPL（QGIS 插件惯例）。
- **可借鉴点**：

  2. **推荐把这张分类表作为本项目地貌层设计的骨架**，侵蚀算法只负责给每个区提供「内部纹理」。

## 4. 热力侵蚀 / 崩塌（Thermal Erosion / Talus）

> 共同特征：不模拟水，只模拟「坡度超过休止角就崩塌」。每格只看 8 邻域，**天然 O(1)、天然可局部化、天然并行**。
> **对本项目的关键含义**：这是本清单里**唯一可以无痛进运行时**的侵蚀算子。它单独看效果有限，但配合「让山坡有稳定坡度、让海岸有崖和滩」的需求，性价比极高。

### 4.1 Musgrave, Kolb, Mace — The Synthesis and Rendering of Eroded Fractal Terrains (SIGGRAPH 1989)
- **链接**：https://dl.acm.org/doi/abs/10.1145/74334.74337
- **原理一句话**：在分形地形（fBm / ridged multifractal）上叠加两类侵蚀——**热力侵蚀（按休止角崩塌）与水力侵蚀（按流量挟沙）**，第一次让程序化地形摆脱「纯噪声感」。
- **类别**：分形地形 + 热力 / 水力侵蚀（奠基性论文）。
- **输出范围**：有限地图。
- **实时性**：需离线全局模拟（1989 年的算力，但热力部分可 O(1)）。
- **双峰高程**：否。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生；但热力侵蚀会产生**稳定的山坡坡度与山前冲积裙**。
- **内海与孤岛**：不处理。
- **语言 / 依赖 / 许可证 / star**：论文；Musgrave 的后续著作《Methods for Realistic Landscape Imaging》(1993) 含更完整的算子描述。
- **可借鉴点**：
  1. **Musgrave 的 ridged multifractal 公式本身，是本项目「山脉层」的最佳基础**（ridge = (1 - |noise|)²，乘权重、按 octave 衰减），比普通 fBm 更像山。
  2. **「热力 + 水力」两段式结构**可以直接照搬为运行时的两级后处理：热力每 chunk 实时跑 2~4 次迭代；水力只在离线阶段跑。
  3. 论文里「用侵蚀历史（erosion history）作为渲染参数」的思路，可以变成 Minecraft 的**生物群系 / 方块选择依据**（侵蚀强度高的地方露岩石、低的地方积土壤）。

### 4.2 Jákó & Tóth (2011) 的热力部分
- 见 §2.6。**这是把热力侵蚀真正写成 GPU 可跑代码的第一批工作之一**，其「threshold + 按比例分配」的伪代码可直接翻译成 Java。
- **可借鉴点（补充）**：热力侵蚀的**阈值 maxDelta 决定了「崖」的观感**——阈值大 → 平缓丘陵；阈值小 → 到处都是碎石坡。在 Minecraft 尺度（1 格 = 1 m）里，建议 maxDelta 取 1.5~3 格，迭代 2~3 次，只在陆地且坡度 > 30° 处启用。

### 4.3 Scape terrain editor（OGRECave/scape）
- **链接**：https://github.com/OGRECave/scape
- **原理一句话**：一个开源的 C++ 地形编辑器，内含「高度场 + 材质层 + 热力 / 水力侵蚀 + 分形细化」的完整编辑管线，可保存 / 加载管线为脚本。
- **类别**：地形编辑器（含侵蚀算子）。
- **输出范围**：有限地图。
- **实时性**：需全局预计算缓存（编辑器式管线，多步串联）。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。
- **内海与孤岛**：不专门处理。
- **语言 / 依赖 / 许可证 / star**：C++（Qt / OGRE），BSD-2-Clause，约 56★（2021 后基本停更）。
- **可借鉴点**：
  1. **BSD-2 = 可自由抄代码**，是本清单里许可证最好的图形学地形编辑器。
  2. **「把地形管线序列化成脚本」的设计**值得抄：本项目可以把「噪声 → 掩膜 → 热力 → 河谷代理」的每一步写成一个可在配置文件里重排的算子，方便离线快速试参数。

## 5. 以水文 / 河流网络为骨架的地形生成（Graphics 学派）

> 共同特征：不满足于「先生成地形再侵蚀」，而是**先生成河流网络与流域图，再由河道剖面反推地形**。这是图形学界对「让大陆像地球」最直接的答案。
> **对本项目的关键含义**：这类方法产出的是**「参数化的河谷」而非「烘焙好的高度场」**，因此**有希望通过程序化重建河道而保持无限可外推**——是本清单里理论价值最高的一类。

### 5.1 Génevaux, Galin, Guérin, Peytavie, Beneš — Terrain Generation Using Procedural Models Based on Hydrology (ACM TOG / SIGGRAPH 2013)
- **链接**：https://www.cs.purdue.edu/cgvlab/www/publications/Genevaux13ToG/ ；作者页 https://cgvlab.github.io/cgvlab/www/publications/Genevaux13ToG/
- **原理一句话**：先在平面上按生长规则造出**互相连通的河流网络**，为每条河算一条从源头到出海口的**凹形纵剖面**，再把河道周围的山坡按「离河道越远越高」抬起来，于是地形自动具备合理的分水岭、河谷与出海口。
- **类别**：水文驱动的地形生成（procedural river network）。
- **输出范围**：有限地图（论文为自己的地图边界生成一条完整的河网）。**但其数据结构是「树 / 图」，理论上可以按需局部生成**。
- **实时性**：需全局预计算缓存（河网必须整体一致）。
- **双峰高程**：否。但**它天然消灭内海**——河网的每一个叶子节点都是出海口，所有水都流得出去。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生；出海口处会自然形成**河口湾 / 三角洲**雏形。
- **内海与孤岛**：**这是本清单里对内海处理最彻底的一类**：河网是连通的树，不存在封闭洼地；同时「每条河都必须入海」保证陆地连通、无孤岛。
- **语言 / 依赖 / 许可证 / star**：论文 + C++ 原型（学术代码，通常不公开或不明确许可）。
- **可借鉴点**：
  1. **最重要的可借鉴点＝「用河网定义大陆连通性」**：本项目可以直接规定「每个大陆块内、每个点都必须能沿下降路径走到海」，做法是在大陆掩膜上定义一个**解析的汇流势函数**：势 = f(到最近海岸的加权距离) + 微小噪声。只要地形高度主要由这个势决定，内海与孤岛就**在构造上不可能出现**，无需任何迭代求解。这是零预计算路线下最靠谱的方案。
  2. **河道的凹形纵剖面（concave-up profile）可以用一条解析曲线近似**：h(s) = h0 - k·(s/L)^θ（s 为沿河距离，θ≈0.4~0.6）。运行时只要估出「到海岸的近似水力距离 s」，就能算出让河谷自然凹下去的高度修正项，O(1)。
  3. **河网的「生长规则」可作为离线阶段的随机种子驱动**：用与噪声同一个 seed 造河网，就能保证同一 seed 下无限世界里每一块大陆的河网风格一致。

### 5.2 Cordonnier, Braun, Cani, Beneš, Galin, Guérin, Peytavie — Large Scale Terrain Generation from Tectonic Uplift and Fluvial Erosion (CGF / EG 2016)
- **链接**：https://hal.science/hal-01262376v1 ；Wiley https://onlinelibrary.wiley.com/doi/10.1111/cgf.12820
- **原理一句话**：把「抬升场（uplift）」与「河流下切（§3.1 的 O(n) 隐式 stream power）」耦合起来迭代，抬升场用少量用户涂鸦（山脊线、高原块）与噪声合成——几秒钟就能得到**有山脉、有高原、有树枝状水系、有冲积平原**的大尺度地形。
- **类别**：构造 + 河流侵蚀耦合的 LEM（图形学版）。
- **输出范围**：有限地图（但目标就是「大尺度」，常见 4096²~16384²）。
- **实时性**：需离线全局模拟（但论文证明可在秒级完成，是**最适合做离线烘焙**的一个）。
- **双峰高程**：**部分**——抬升场可以人为设成「大陆整体抬升 + 洋盆不抬升」，于是输出天然两级；论文本身关注山地地形。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生；但有**大陆坡式的陡降**（在抬升场边缘）。
- **内海与孤岛**：默认有洼地填充 / 边界排水处理。
- **语言 / 依赖 / 许可证 / star**：论文；作者主页有代码页 https://www-sop.inria.fr/members/Guillaume.Cordonnier/code.html （含 Fastscape 等）。
- **可借鉴点**：
  1. **「抬升场用少量控制特征 + 噪声合成」正是本项目 continent mask 该有的形态**：与其用一张巨大的烘焙图，不如用「若干椭圆高原 / 山脊折线 + 噪声扰动」解析地描述大陆，这样 X 轴无限外推时只要按 x 重复/演化这些控制特征即可。论文的 uplift 合成方式可直接借用。
  2. **秒级收敛意味着离线烘焙可行**：可以在构建期对 2048² 网格跑 200 步得到控制场，打包进模组资源（约几 MB），运行时双线性采样。
  3. 论文的「侵蚀让地形自相似 / 让山脊线平滑」的结论，可以用来论证「为什么运行时的噪声必须做坡度门控与平滑」。

### 5.3 Cordonnier, Galin, Gain, Beneš, Guérin, Peytavie — Authoring Landscapes by Combining Ecosystem and Terrain Erosion Simulation (SIGGRAPH 2017)
- **链接**：https://www.cs.purdue.edu/cgvlab/www/publications/cordonnier2017authoring/ ；ACM https://dl.acm.org/doi/abs/10.1145/3072959.3073667
- **原理一句话**：在侵蚀模型里加入**植被 / 生态系统**（植被改变可蚀性与径流），实现「森林保护山坡、裸地加速侵蚀」的双向反馈，从而能生成沙漠 / 草原 / 森林等不同地貌风格。
- **类别**：侵蚀 + 生态耦合。
- **输出范围**：有限地图。
- **实时性**：需离线全局模拟。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。**内海与孤岛**：不处理。
- **语言 / 依赖 / 许可证 / star**：论文；无公开代码。
- **可借鉴点**：
  1. **「用气候 / 植被调制侵蚀强度」= 本项目里用 Z 轴纬度调制地貌**：同一个大陆掩膜，在赤道带是茂密丘陵、在副热带是沙漠台地、在高纬是冰蚀谷。运行时只需把「侵蚀代理强度」乘以一个纬度函数（用 Z 轴周期即可），零成本地让全球地貌有纬度分带。这与本项目的 Z 轴纬度设计天然契合。
  2. 论文的「生态-侵蚀反馈」也可以简化成「生物群系 → 侵蚀参数字典」，运行时查表。

### 5.4 Tzathas, Gailleton, Steer 等 — Physically-based Analytical Erosion for Fast Terrain Generation (CGF / EG 2024)
- **链接**：https://hal.science/hal-04525371v1 （HAL 条目，含 PDF）
- **原理一句话**：**解析地**求解稳态 stream power 方程——给定排水面积与流量，河道剖面的稳态高度有闭式解，于是不需要迭代成千上万步，直接一次算出侵蚀后的地形。
- **类别**：河道侵蚀（解析解 / 免迭代）。
- **输出范围**：有限地图（但仍需知道排水面积）。
- **实时性**：**介于两者之间**——不需要时间步迭代，但需要每点知道其上游汇水面积（全局依赖）。论文的目标是「秒级生成」。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。
- **内海与孤岛**：解析解要求已知出海口，等于隐含地解决排水问题。
- **语言 / 依赖 / 许可证 / star**：论文（EG 2024 Full Paper）；实现可能随作者的 FastFlow / GraphFlood 生态发布，使用前需确认许可证。
- **可借鉴点**：
  1. **「解析解」是本项目最想要的东西**：它把「需要 N 步迭代」压缩成「一次闭式求值」。如果本项目要保留任何形式的运行时侵蚀，这是唯一数学上站得住的方向。
  2. **可退化为「每 chunk 解析求解」**：把 chunk 当成一个小流域（用 chunk 内的最低点当出海口），用解析公式一次性算出 chunk 内每格的稳态高度。虽然是近似（跨 chunk 的水系不连续），但成本 O(chunk 面积)、无迭代、可并行。
  3. **论文对「稳态假设」的讨论**直接告诉你哪些地貌无法用解析解表达（例如冰川谷、风成地貌），避免踩坑。

## 6. 洼地处理与流向路由（Depression Filling / Flow Routing）——内海 = 0 的正解

> 共同特征：不改变地形的「风格」，只保证「水一定能流出去」。这是本项目「内海数 = 0」这条硬指标的唯一可靠技术手段。
> **对本项目的关键含义**：即使完全不做侵蚀，也**必须**实现本节的某一个算法（哪怕只在 chunk 级别近似），否则噪声产生的一阶洼地会变成成千上万个内陆湖。

### 6.1 Barnes, Lehman, Mulla — Priority-Flood: An Optimal Depression-Filling and Watershed-Labeling Algorithm for DEMs (Computers & Geosciences, 2014)
- **链接**：arXiv 全文 https://arxiv.org/abs/1511.04463 ；作者实现（C++，**未标注许可证**） https://github.com/r-barnes/Barnes2013-Depressions
- **原理一句话**：把 DEM 边界（或海洋）全部塞进一个**优先队列**，每次弹出最低点，把它的未访问邻居抬到「不低于当前点」的高度后入队——一次 O(n log n) 遍历即可保证全图无洼地，且抬升量在某种意义上最小。
- **类别**：水文条件化（洼地填充 / 分水岭标注）。
- **输出范围**：有限地图（但其变体 Priority-Flood + ε 与「部分填充 / 定向填充」可以只在局部窗口内运行）。
- **实时性**：需全局预计算缓存（经典形式），但存在 O(n) 变体（用基数排序 / 单调队列替代堆）以及可并行的分层版本。
- **双峰高程**：否。但**它会保护双峰**：只抬升洼地，不动大陆与洋盆的整体分布。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生；**但它会填平海沟**，这是要注意的副作用——若要用海沟地貌，应把海沟排除在填充范围外，或先填充后叠加海沟。
- **内海与孤岛**：**这是本算法存在的理由**。填充后内海数严格为 0（所有内陆洼地都能排水到边界 / 海洋）。孤岛不由它解决（孤岛是掩膜层的事，但「无内海」会让孤岛更容易被识别与移除）。
- **语言 / 依赖 / 许可证 / star**：C++（约 15★，2016 后停更）、被 RichDEM 完整吸收（见 §6.3）。**仓库未标注许可证，直接拷代码有风险**；算法本身公开（论文），照论文自己实现最安全。
- **可借鉴点（本清单最高优先级）**：
  1. **局部化改造方案（可直接写代码）**：区块生成时取「区块 + 半径 R 的 halo」（例如 R = 64 格）作为窗口；把窗口内所有「低于海平面且连通到窗口边界以下」的格子视为**海**，作为优先队列的种子；跑一次窗口内的 Priority-Flood；只取中心 16×16 的结果写回。当 R 足够大（≥ 最长一阶洼地直径）时，结果与全局填充几乎一致。成本 O(R² log R) 每区块，R=64 时约 4096 格，完全可接受。
  2. **更省的做法（零 halo）**：只在「大陆掩膜内部」做填充，且用**确定性的优先级定义**（例如以「到海岸的近似距离 + 高度」为键）代替队列，使结果只依赖当前格与其邻域——这样每个方块可以独立 O(1) 求出填充后的高度。这正是把 Priority-Flood 变成**纯函数**的技巧：把「排水顺序」替换为一个全局可解析的单调势函数。
  3. **「填充量」本身是极好的地形素材**：填充高度差大的地方就是「湖 / 干盐湖 / 湿地」，可直接映射成 Minecraft 的湖泊、盐滩、沼泽——**内海问题反而变成地貌多样性来源**。若想要少量内海，只要保留填充量最大的前 N 个即可精确控制内海数量——这是「内海数 = 常数」的唯一精确实现方式。
  4. 论文里的 **watershed labeling** 可顺带给出流域边界，用于把大陆切分成若干「河系」，运行时按河系分配噪声参数。

### 6.2 Barnes, Lehman, Mulla — An Efficient Assignment of Drainage Direction over Flat Surfaces in Raster DEMs (Computers & Geosciences, 2014)
- **链接**：RichDEM 文档（含完整算法说明与出处） https://richdem.readthedocs.io/en/latest/flat_resolution.html ；ACM 条目 https://dl.acm.org/doi/10.5555/2745549.2745642 ；源码 https://github.com/r-barnes/richdem/blob/master/docs/flat_resolution.rst
- **原理一句话**：Priority-Flood 填充后会造出大片**平地**，平地上「哪边是下游」不唯一；本算法用两次广度优先扫描（从低处 / 从高处）给每格分配一个梯度化的流向，使水流在平地上也能确定性地流出去。
- **类别**：水文条件化（平地流向分配）。
- **输出范围**：有限地图。
- **实时性**：需全局预计算缓存（两次 BFS）。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。
- **内海与孤岛**：**与 §6.1 配合才能保证内海 = 0**——只填充不分配流向，水仍会滞留在平地上。
- **语言 / 依赖 / 许可证 / star**：见 RichDEM（GPL-3.0）。
- **可借鉴点**：
  1. **在 Minecraft 里，「平地流向」可以退化成一个纯装饰问题**：只要填充后的高度严格单调（每格与邻居至少有 ε 的高差），就不需要真的模拟流向。因此推荐做法是 **Priority-Flood + ε（每步强制加一个极小增量）**，用 1/256 格的高度差就能让流向唯一，同时肉眼不可见。
  2. **ε 的取值要与 Minecraft 的高度量化匹配**：1.7.10 的高度是整数方块，所以必须在量化**之前**完成填充，或使用「方块下方的亚格高度场」来承载 ε。

### 6.3 RichDEM（Barnes）
- **链接**：https://github.com/r-barnes/richdem ；文档 https://richdem.readthedocs.io/en/latest/ ；算法清单 https://richdem.readthedocs.io/en/latest/publications.html
- **原理一句话**：高性能 C++/Python 地形与水文分析库，把 Priority-Flood（含 O(n) 变体）、平地流向、D8/D∞/MFD 流向、汇流累积、地形属性一网打尽，且明确标注每个算法出自哪篇论文。
- **类别**：水文分析库（本清单的瑞士军刀）。
- **输出范围**：有限地图。
- **实时性**：需全局预计算缓存（离线工具）。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。
- **内海与孤岛**：**内海处理能力最全**（fill / breach / flat resolution / watershed labeling 齐备）。
- **语言 / 依赖 / 许可证 / star**：C++（Python 绑定），GPL-3.0，约 324★。
- **可借鉴点**：
  1. **强烈建议作为离线烘焙链的第一环**：Python 一行调用即可对 8192² 控制网格做填充 + 流向 + 汇流累积，产出「汇流面积」场。**汇流面积场是驱动后续所有侵蚀与河谷代理的核心输入**。
  2. **GPL-3.0 → 只能离线用**，不能把 C++ 代码嵌进模组。但算法由论文公开，可自行实现局部版本。
  3. 它的文档把「fill vs breach vs hybrid」的取舍讲得很清楚：**breach（在障碍上开一道口子）比 fill（抬高洼地）更能保留原始地形**；若本项目要保留噪声的起伏感，应优先用 breaching。

### 6.4 Cordonnier, Bovy, Braun — A Versatile, Linear Complexity Algorithm for Flow Routing in Topographies with Depressions (Earth Surface Dynamics 7, 549-562, 2019)
- **链接**：https://esurf.copernicus.org/articles/7/549/2019/ ；HAL PDF https://hal.science/hal-02136750v1/file/A_Versatile_Linear_Complexity_Algorithm_for_Flow_Routing_in_Topographies_with_Depressions.pdf
- **原理一句话**：**不填充洼地**，直接在带洼地的地形上做 O(n) 的水流路由（用图 / 栈的一次线性扫描），同时给出「无洼地化」与「流向」两件事，速度比 Priority-Flood 更快且不需要堆。
- **类别**：流向路由（线性复杂度，容忍洼地）。
- **输出范围**：有限地图。
- **实时性**：需全局预计算缓存（但 O(n) 常数极小，是最快的选择之一）。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。
- **内海与孤岛**：**保留洼地但保证有出流路径**——恰好对应「少量内海 + 有排水」的中间态，对「内海数 = 0 或极少」的措辞最友好。
- **语言 / 依赖 / 许可证 / star**：论文 + 被 Fastscape（BSD-3-Clause）实现。
- **可借鉴点**：
  1. **O(n) 无堆实现意味着可以在更大的 halo 上跑**：如果 §6.1 的 R=64 不够，本算法允许把 R 提到 256 而成本几乎线性增长。
  2. **「不填充、只给流向」的哲学对本项目很重要**：Minecraft 里内陆湖是好看的（少量内海甚至加分），真正要避免的是「每个噪声洼地都变成湖」。用本算法可以保留少数大洼地当湖、消灭其余——通过「只保留深度 / 面积超过阈值的洼地」精确控制。
  3. 论文随附伪代码极为清晰，是自研 Java 版本的最佳蓝本。

### 6.5 Tarboton (1997) — D-infinity 流向与上游面积
- **链接**：TauDEM 官方文档 https://hydrology.usu.edu/taudem/taudem5/help/DInfinityFlowDirections.html ；论文页 https://digitalcommons.usu.edu/cee_facpub/2507/
- **原理一句话**：把流向从「8 个方向选一个（D8）」推广到「连续角度（D∞）」，消除 D8 的棋盘伪影，让汇流面积分布更自然。
- **类别**：流向算法。
- **输出范围**：有限地图。
- **实时性**：需全局预计算缓存（汇流累积需要全图遍历）。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。
- **内海与孤岛**：不处理内海（需配合填充）。
- **语言 / 依赖 / 许可证 / star**：TauDEM（C++，约 275★，GitHub 标注许可证为 other，需自行确认），文档托管在 USU。
- **可借鉴点**：
  1. **D∞ 的「按角度把流量分给两个相邻格」只有十几行**，是自研汇流累积的最短路径。离线阶段需要汇流面积时，用 D∞ 而不是 D8 会让河谷走向自然得多。
  2. **运行时含义**：若要做「局部汇流累积」，D∞ 的连续性使「按 chunk 边界截断」的误差比 D8 更小。

### 6.6 pysheds
- **链接**：https://github.com/pysheds/pysheds
- **原理一句话**：Python 的流域划分与流向计算库（D8 / D∞ + 洼地填充），API 简洁到几行代码即可完成「填洼 → 流向 → 汇流 → 流域」。
- **类别**：水文分析库（Python）。

- **实时性**：需全局预计算缓存。
- **双峰高程 / 地貌要素**：不产生。**内海与孤岛**：内建 fill_depressions / fill_pits。
- **语言 / 依赖 / 许可证 / star**：Python（NumPy / Numba），GPL-3.0，约 901★。
- **可借鉴点**：**离线原型最快的起点**，比 RichDEM 更易上手，适合快速验证「填充参数 → 内海数量」的关系。

### 6.7 WhiteboxTools
- **链接**：https://github.com/jblindsay/whitebox-tools
- **原理一句话**：Rust 编写的地理空间分析平台，水文工具极齐全（BreachDepressionsLeastCost、FillDepressions、D8/D∞/MFD 流向、wetness index 等）。
- **类别**：地理空间 / 水文分析平台。
- **输出范围**：有限地图。
- **实时性**：需全局预计算缓存。
- **双峰高程 / 地貌要素**：不产生。**内海与孤岛**：**BreachDepressionsLeastCost 是本清单里最优雅的「消灭内海但保留地形」工具**。
- **语言 / 依赖 / 许可证 / star**：Rust，MIT，约 1205★（**许可证友好**）。
- **可借鉴点**：
  1. **MIT = 可以读代码、移植算法**（Rust → Java 成本不高，且算法都来自公开论文）。
  2. **Least-cost breaching 的思路可直接在 Minecraft 里用**：与其抬高一整片洼地（会毁掉地形），不如沿最低成本路径开一条窄谷到下游——在方块世界里这正好就是「一条河」。**这是「内海 = 0」与「地形好看」兼得的最佳方案**。
  3. 建议离线阶段跑一遍，把「决口路径」导出成河谷掩膜。

### 6.8 GRASS GIS（r.watershed / r.terraflow）与 SAGA GIS

## 7. 早期经典 / 冷门学术（图形学侵蚀可视化谱系）

> 收录理由：这些是最早一批「用侵蚀让程序化地形变真」的工作，其中的**思路**至今没有被超越，而且因为年代早，算法往往更简单、更容易移植。

### 7.1 Kelley, Malin, Nielson — Terrain Simulation Using a Model of Stream Erosion (SIGGRAPH 1988)
- **链接**：https://dlnext.acm.org/doi/10.1145/378456.378519
- **原理一句话**：最早把「降雨 → 坡面流 → 河流搬运 → 沉积」写成离散模型并用它生成地形的工作之一；用**流量累积**决定冲刷强度，是 stream power 在图形学的鼻祖。
- **类别**：河道侵蚀（开创性）。
- **输出范围**：有限地图。
- **实时性**：需离线全局模拟。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。**内海与孤岛**：不处理。
- **语言 / 依赖 / 许可证 / star**：论文（ACM 付费墙）。
- **可借鉴点**：
  1. **「流量累积 → 冲刷强度」的映射用一条查表曲线就能实现**，运行时可用「到海岸距离」替代流量累积，得到 O(1) 的近似。
  2. 作为本项目的**引用来源**：说明「用侵蚀生成地形」有近 40 年历史，方法论成熟。

### 7.2 Chiba, Muraoka, Fujita — An Erosion Model Based on Velocity Fields for the Visual Simulation of Mountain Scenery (J. Visualization and Computer Animation, 1998)
- **链接**：https://onlinelibrary.wiley.com/doi/abs/10.1002/(SICI)1099-1778(1998100)9:4%3C185::AID-VIS178%3E3.0.CO;2-2
- **原理一句话**：不从物理方程出发，而是直接从**高度场的梯度（流速场）**出发，按「流速快的方向被冲刷得更多」的规则迭代，得到布满沟壑的山地。
- **类别**：水力侵蚀（速度场启发式）。
- **输出范围**：有限地图。
- **实时性**：需离线全局模拟。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。
- **内海与孤岛**：不处理。
- **语言 / 依赖 / 许可证 / star**：论文（Wiley 付费墙）。
- **可借鉴点**：
  1. **最原始的「坡度门控」侵蚀**：侵蚀量 ∝ |∇h|。这是**唯一一个可以逐点 O(1) 求值的真实侵蚀算子**（因为它不需要流量累积）——非常适合作为运行时的细节层。
  2. 具体做法：在 fBm 高度场上，额外减去 k·|∇h|·noise，就能得到沟壑感。**成本约等于多采一次噪声**，强烈建议尝试。

### 7.3 Nagashima — Computer Generation of Eroded Valley and Mountain Terrains (The Visual Computer, 1998)
- **链接**：https://www.semanticscholar.org/paper/Computer-generation-of-eroded-valley-and-mountain-Nagashima/10dd1c856931862ee19873fffb76dd1a7c1a7d1b
- **原理一句话**：用「谷壁后退 / 谷底拓宽」的几何规则模拟山谷演化，把分形地形改造成有明确谷底与谷壁的「V 形谷」景观。
- **类别**：几何式侵蚀（山谷演化）。
- **输出范围**：有限地图。
- **实时性**：需离线全局模拟（但局部规则较简单）。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不产生。**内海与孤岛**：不处理。
- **语言 / 依赖 / 许可证 / star**：论文（Springer / Visual Computer）。
- **可借鉴点**：
  1. **「V 形谷」的解析剖面可以直接写成距离函数**：h = h0 - k·|d|（d 为到谷轴的距离），把谷轴定义成一条程序化曲线即可 O(1) 求值。这是把「河谷」变成可无限外推的解析特征的经典做法。
  2. 与本项目「零预计算」的约束完美契合，**可借鉴度：高**。

### 7.4 冷门补充：Zhan & Chen 等 — Eroded Terrain Simulation Based on Improved Hydraulic Erosion Algorithm
- **链接**：https://www.semanticscholar.org/paper/Eroded-terrain-simulation-based-on-improved-erosion-Zhan-Chen/90e4ccc4c7ab28081155e11897661a1a97791822
- **原理一句话**：在经典水力侵蚀上做工程改进（通常是稳定性与参数自适应），属于「应用型改进」论文。
- **类别**：水力侵蚀（改进实现）。
- **输出范围**：有限地图。**实时性**：需离线全局模拟。**双峰高程 / 地貌要素 / 内海**：均不涉及。
- **语言 / 依赖 / 许可证 / star**：论文（中文期刊 / 会议），**无公开代码**。
- **可借鉴点**：可借鉴度低。仅在需要「参数自适应」的具体技巧时参考；因无代码与许可证信息，**不建议投入时间**。

## 8. 商业 / 独立工具与游戏工业实践

> 收录理由：这些工具被大量游戏与影视项目验证过，**它们的参数面板就是「人类可调的侵蚀参数空间」的现成总结**。即使不能抄代码，抄参数与工作流也非常值钱。

### 8.1 Wilbur（Joe Slayton，免费ware，地形编辑器）
- **链接**：官网 http://www.fracterra.com/wilbur.html ；教程《Fun With Wilbur》 http://www.fracterra.com/FunWithWilburVol1/index.html
- **原理一句话**：面向制图师的地形编辑器，核心是一组**水文工具**：Fill Basins（填洼）、Incise Flow（按汇流下切）、Precipitation / River Erosion（降雨侵蚀）、Erode（热力 / 水力）、以及分形噪声合成。
- **类别**：地形编辑器（水文 + 分形）。
- **输出范围**：有限地图（导入导出 heightmap）。
- **实时性**：需全局预计算缓存（桌面工具，分钟级）。
- **双峰高程**：否（但可显式编辑海平面，因此能人工构造两级）。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不直接产生；**Incise Flow 能刻出极像地球的树枝状水系与海底峡谷**。
- **内海与孤岛**：**Fill Basins 是它的招牌功能之一**，社区教程《How to avoid filling unwanted basins on Wilbur?》专门讨论「如何只填一部分洼地」——这正是「内海数可标定」的实践答案，见 https://www.cartographersguild.net/printthread.php?page=1&pp=10&t=51314
- **语言 / 依赖 / 许可证 / star**：Windows 桌面软件，免费但**闭源**；不可嵌入，仅可离线使用。
- **可借鉴点**：
  1. **Wilbur 的工具链顺序就是本项目离线烘焙的推荐顺序**：分形合成 → Fill Basins（去内海）→ Incise Flow（刻河谷）→ Precipitation（细化支流）→ Erode（热力收尾）。
  2. **Incise Flow 的算法本质是「多流向汇流 + stream power 一次下切」**，是「用最小代价得到最像地球的水系」的工业级答案；其参数（Flow Amount / Amount / Exponent）可与 §3.9 的 m/n 指数对应。
  3. **社区教程中「保留部分洼地」的技巧可直接照搬成阈值逻辑**：只填「深度小于 X 或面积小于 Y」的洼地，其余保留成湖。**这条直接给出「内海数 = 常数」的实现方式**。
  4. 闭源，**只能用于离线生成与学习，不能拷贝代码**。

### 8.2 World Machine（商业地形生成器）
- **链接**：官网 https://www.world-machine.com/ ；侵蚀改进说明 https://www.world-machine.com/blog/2019/07/3026-erosion-improvements/
- **原理一句话**：节点式的程序化地形生成器，把「分形、侵蚀、河流、沉积、遮罩、选择」做成可组合的节点图；其 Erosion / River 节点是工业界使用最广的侵蚀实现之一。
- **类别**：节点式地形生成器（含侵蚀）。
- **输出范围**：有限地图（tiled build 可拼大图，但仍是烘焙）。
- **实时性**：需全局预计算缓存（离线烘焙，分钟到小时级）。
- **双峰高程**：否（靠用户手工搭掩膜）。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不直接产生。
- **内海与孤岛**：有 Create Water / Fill 类节点可做填洼与水面。
- **语言 / 依赖 / 许可证 / star**：Windows 桌面软件，**闭源商业**（有免费版但功能受限）；另有 Geoglyph 文档中公开了部分节点语义（https://geoglyph-docs.readthedocs.io/en/latest/Devices/RiverErosion/ ）。
- **可借鉴点**：
  1. **「RiverErosion 节点」的属性表就是一份现成的参数规格书**（flow rate、channel depth、deposition 等），可照抄成 Java 的配置类。
  2. **节点图的「mask 驱动」思想**：所有侵蚀节点都接受一张 mask 输入，只在 mask 内生效。**这正是本项目最需要的机制**——用大陆掩膜 / 纬度掩膜控制侵蚀强度，实现「不同地区不同地貌」。
  3. 闭源，不可嵌入。

### 8.3 Gaea（QuadSpinner，商业地形工具）
- **链接**：官网 https://quadspinner.com/ ；侵蚀文档 https://docs.quadspinner.com/Guide/Using-Gaea/Erosion.html ；热力侵蚀节点文档 https://docs.gaea.app/reference/nodes/simulate/thermal2
- **原理一句话**：面向影视 / 游戏的高端地形工具，把侵蚀拆成 **Erosion（水力）/ Thermal（热力）/ Debris（碎屑）/ Snow / Frost** 等专门节点，并强调「选择性侵蚀（selective erosion）」。
- **类别**：地形生成 / 侵蚀模拟工具。
- **输出范围**：有限地图（高分辨率烘焙）。
- **实时性**：需全局预计算缓存（GPU 加速，但仍是离线）。
- **双峰高程**：否。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不直接产生。
- **内海与孤岛**：有专门的「湖泊 / 填充」类节点。
- **语言 / 依赖 / 许可证 / star**：闭源商业（Windows）；文档公开。
- **可借鉴点**：
  1. **「选择性侵蚀（selective erosion）」= 用掩膜限制侵蚀发生的位置**，这与 §8.2 的 mask 思想一致，是本项目运行时最该采纳的机制。
  2. **Thermal2 节点的参数文档（talus angle、repose 等）是热力侵蚀调参的现成参考**，可直接映射到 Minecraft 的方块坡度。
  3. 其 2025 年新增的「Frost（冰缘）侵蚀」提示了**纬度带地貌（本项目 Z 轴）**的实现方向：在高纬用「冰蚀」参数替代「水蚀」参数。

### 8.4 World Creator（商业实时地形工具）
- **链接**：官网 https://www.world-creator.com/
- **原理一句话**：GPU 实时的地形生成器，主打「无限尺寸世界 + 实时侵蚀滤镜」，其 Erosion 滤镜可在毫秒级对当前视图重算。
- **类别**：实时地形生成 / 侵蚀滤镜。
- **输出范围**：宣传为**无限尺寸**（游戏内实测仍受内存限制）。
- **实时性**：**运行时 O(1) 求值（GPU 实时滤镜）**——是本清单里少见的「实时侵蚀」商业实现。
- **双峰高程**：否（靠手工掩膜）。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不直接产生。
- **内海与孤岛**：有水位 / 湖泊工具。
- **语言 / 依赖 / 许可证 / star**：闭源商业（Windows / macOS）。
- **可借鉴点**：
  1. **它的存在证明了「实时侵蚀滤镜」在工程上可行**：其做法是「多层噪声 + 若干次轻量滤镜 + 只在可视区域计算」，与本项目「按区块按需计算」的思路一致。
  2. **「无限尺寸」的宣传语值得警惕**：实际仍需在内存里维护可编辑的全局高度图，**并不能证明它满足本项目的零预计算约束**。
  3. 闭源，**仅作可行性论据**。

### 8.5 Terragen（Planetside Software，商业景观渲染器）
- **链接**：技术博客《Terrain Techniques – Detail, Warp, Erode》 https://planetside.co.uk/blog/terrain-techniques-detail-warp-erode/
- **原理一句话**：以「分形地形 + 位移（displacement）+ 域扭曲（warp）+ 侵蚀」为核心的地形管线，其「先 warp 再 erode」的层次被广泛模仿。
- **类别**：景观渲染 / 地形生成（含侵蚀）。
- **输出范围**：有限地图（渲染器）。
- **实时性**：需全局预计算缓存。
- **双峰高程**：否。**大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：不直接产生。
- **内海与孤岛**：不专门处理。
- **语言 / 依赖 / 许可证 / star**：闭源商业。
- **可借鉴点**：
  1. **官方博客把「Detail（细节噪声）/ Warp（域扭曲）/ Erode（侵蚀）」明确分成三层**，这是最清晰的运行时分层模板：低频控制场 + 域扭曲 + 侵蚀代理。
  2. **域扭曲是 O(1) 的**，且能让噪声看起来「被水流改写过」，是本项目最便宜的侵蚀代理（见 §8.6）。

### 8.6 Inigo Quilez — Domain Warping（域扭曲，技术文章）
- **链接**：https://iquilezles.org/articles/warp/
- **原理一句话**：把噪声的坐标用另一个噪声去偏移（f(p) → f(p + a·g(p))），得到有「流动感」的分形图案，视觉上极像被水力侵蚀过的地形。
- **类别**：程序化噪声技巧（侵蚀的 O(1) 代理）。
- **输出范围**：**无限程序化**（纯函数，逐点求值）。
- **实时性**：**运行时 O(1) 求值**（代价 = 多采几次噪声）。
- **双峰高程**：否（不影响大尺度分布，只改纹理）。
- **大陆架 / 坡 / 岛弧 / 海沟 / 洋中脊**：均不产生。
- **内海与孤岛**：不影响。
- **语言 / 依赖 / 许可证 / star**：技术文章（无代码仓库，公式可直接实现）。
- **可借鉴点**：
  1. **这是零预计算约束下最实用的「假侵蚀」**：把高度场写成 h = fBm(p + warp·fBm2(p))，其中 warp 强度随坡度增大，就能得到沟壑感。
  2. **配合「沿到海岸距离的单调衰减」**：让 warp 强度与「离海岸越远越强」，可在海岸带保持平滑（有利于 D 值控制），在内陆产生褶皱。
  3. 成本：约 2~3 倍噪声开销，**完全满足「性能接近纯噪声」的硬约束**。

### 8.7 Azgaar's Fantasy Map Generator（FMG，开源 Web 地图生成器）

- **原理一句话**：在 2D 高度图上做「填洼 → 流向 → 河流 → 湖泊 → 洋流」，并把河流作为文明 / 生物群系的骨架；工作区里已存在 .tmp-fmg 目录，说明本项目已在使用它。

- **输出范围**：有限地图。
- **实时性**：需全局预计算缓存（浏览器内秒级）。

### 8.8 WorldSynth（Minecraft 世界生成器，节点式，含侵蚀模块）

### 9.1 推荐管线（三层结构，兼顾硬约束）

### 9.2 五个「立刻可写代码」的具体结论

1. **内海 = 0 的纯函数解法**：把地形高度定义为 H(x,z) = 海平面 + g(d(x,z)) + A(d)·n(x,z)，其中 d 是「到最近海岸的解析距离」（可用与大陆掩膜同一套椭圆 / 折线的距离场求出），g 是单调递增曲线，A(d) 是随 d 增长的噪声幅度。**只要 g 单调且 d 的定义保证「沿 d 减小方向一定能到海」，内海在构造上就不可能出现。** 这是零预计算下唯一严格保证。
2. **双峰必须来自 L0**：把大陆掩膜内的目标高度设成 +0.3 km 附近的台地、洋盆设成 -4 km 附近的盆地，中间用一段陡峭的「大陆坡」过渡曲线连接（过渡带宽度 ≈ 100~200 km 的映射尺度）。侵蚀层只在这条曲线的两侧加纹理。
3. **海岸线分形维数 D 主要由 L0 的掩膜边界决定**，侵蚀只能把它抬高约 0.05~0.15。若 D 目标 1.2~1.4，应主要通过「大陆掩膜边界用 fBm 扰动」而不是靠侵蚀来命中。**建议在离线阶段用盒计数法（box counting）对候选参数批量测 D**。
4. **热力侵蚀（§2.6 / §4）是唯一可以无条件进运行时的真实侵蚀算子**，优先实现它；它同时能修掉噪声产生的锯齿状海岸与过陡山坡。
5. **能抄代码的许可证白名单（MIT / BSD）**：erodr（MIT）、SebLague/Hydraulic-Erosion（MIT）、jobtalle/HydraulicErosion（MIT）、dandrino/terrain-erosion-3-ways（MIT）、Landlab（MIT）、WhiteboxTools（MIT）、Scape（BSD-2）、TerraForged（MIT）、WorldSynth（MIT）。
   **只能离线用、不可嵌代码的**：RichDEM / pysheds / GRASS / fastscapelib-fortran / Badlands / goSPL / LSDTopoTools（GPL 或 LGPL）。
   **许可证缺失、只可读思路**：Barnes2013-Depressions、weigert/SimpleErosion、weigert/SimpleTectonics、Creepsy/hydraulic-erosion。
