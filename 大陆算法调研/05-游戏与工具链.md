# 05 · 游戏 / 编辑器 / 开源工具链里的「类地大陆」生成算法

> 调研对象：**塔洛斯经纬（Talos Loom）** —— Minecraft 1.7.10 无限世界类地大陆生成器。
> 硬约束回顾：X 轴无限非周期；Z 轴周期 20,000,000 = 纬度；零预计算、零离线烘焙，运行时按 (x,z,seed) 直接 O(1) 求值；不存全局地图。
> 目标：1 块或少数几块**互相连通**的大陆（内海数 = 0 或极少）、无散落小岛、海岸线分形维数 D ≈ 1.2~1.4、陆地占比可标定；具备大陆架 / 大陆坡 / 深海盆地 / 山脉 / 岛弧；Java 实现，性能接近纯噪声。

## 阅读约定（重要）

# 一、4X / 策略游戏的地图脚本

## 01 Freeciv / Freeciv21 地图生成器族（gen2~gen6）

- **链接**：
  - 主仓库：https://github.com/longturn/freeciv21
  - 高度图：https://github.com/longturn/freeciv21/blob/master/server/generator/height_map.cpp
  - 岛屿：https://github.com/longturn/freeciv21/blob/master/server/generator/islands.cpp
  - 断裂/陆块：https://github.com/longturn/freeciv21/blob/master/server/generator/fracture_map.cpp
  - 高度场常量：https://github.com/longturn/freeciv21/blob/master/server/generator/height_map.h
- **一句话原理**：Freeciv 同时提供多套彼此独立的高度图算法（纯随机+平滑 / 逐块生长岛屿 / **菱形-方形伪分形** / 圆盘扩张陆块），再由**百分位排名归一化**统一映射到 0~1000 的高度层级，最后按温度带铺设地形。
- **类别**：开源 4X 游戏（Civ2 血统）内置地图生成器；纯整数网格算法，可逐行读源码。
- **输出范围**：**有限地图**（xsize × ysize），但拓扑可设为 TF_WRAPX / TF_WRAPY —— 即**支持在 X 或 Y 方向环绕**，这一点与塔洛斯经纬的 Z 周期直接同构。
- **实时性**：**需离线全局模拟**。高度场是整张 int 数组（height_map[MAP_INDEX_SIZE]），生成后还要跑平滑、极地压平、大陆编号划分、气候与地貌铺设，无法单点 O(1) 求值。
- **地球式双峰高程**：**弱**。hmap_max_level = 1000，hmap_shore_level（海平面）与 hmap_mountain_level 是两个显式阈值；adjust_int_map() 会把高度**按排名**缩放到 [0, max]，文档写明「最低的 20% 地块取值低于 0.2 × max」——这是一种**强制直方图整形**，能得到「一大片浅海底 + 一大片陆地台地」的近似双峰，但峰形由排名决定而非由地球测高曲线决定。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**没有显式建模**。海洋只有 hmap_shore_level 一个台阶；没有陆架坡度函数、没有海沟、没有洋中脊。唯一与「弧」沾边的是 fracture 生成器把地图边缘的陆块整体下沉成海洋（edge 标记）。
- **内海与孤岛**：**处理得比较认真**，是本条目的核心价值：
  - make_pseudofractal_hmap()（generator 5，菱形-方形）用 div = 6 个初始块「一般能得到一整块大陆」，代码注释明确写着增加 div 会增加岛屿数量，并直接和开局点设置（startpos）挂钩：MAPSTARTPOS_ALL/DEFAULT → 一块大陆；VARIABLE → div += 5；SINGLE → div += 玩家数。**「用分块粒度直接控制大陆/岛屿数量」是可以照抄的参数化思路。**
  - islands.cpp 的 gen2~4 用 make_island(islemass, starters, ...)：给每个岛一个**质量预算**，从种子点 create_island() 向外生长，用 checkmass 校验，还带 min_specific_island_size 阈值——**小于阈值的碎岛直接被放弃**，这正是「无散落小岛」的经典工程解法。
  - fracture_map.cpp：num_landmass = 20 + 15 * get_sqsize()，沿地图四边每 5 格布一个 edge=true 的陆块（会被下沉成洋），其余陆块用 circle_bresenham() 逐圈扩张半径（for (rad = 1; rad < xsize >> 1; rad++)）争夺格子，最终高度还要和 local_ave_elevation(ptile) 比较（大于 1.20 倍判为山、大于 1.10 倍判为丘）。
- **语言 / 依赖 / 许可证 / star**：C++ / Qt、Lua（Freeciv21 用 Qt + Lua 规则）/ 源文件 SPDX 头写明 **GPL-3.0-or-later** / star 未取到。
- **对本项目的可借鉴点**：
  1. **百分位阈值定海平面**（adjust_int_map + 排名归一化）：想在无限世界里标定陆地占比，可以把「高度场的分位数」当作标定旋钮——离线标定一次得到常数，运行时用一个固定的高度阈值即可，陆地占比 ≈ 常数。这比「随便定个海平面」可控得多。
  2. **分块粒度 = 大陆数量的控制杆**（div）：在噪声域里，「低频噪声的波长」就是大陆数量；把 div 从 6 调到 16，就是从一块泛大陆变成群岛。塔洛斯经纬应该**只暴露一个波长参数**来保证「1 块或少数几块大陆」。
  3. **岛屿质量预算 + 最小面积剔除**（make_island / min_specific_island_size）：无限世界没有全局连通性判定，但可以做**局部版**：对低频掩码做形态学开运算（先腐蚀再膨胀），天然消掉小于结构元素的孤岛；或要求「陆地像元必须落在低频掩码的局部极大附近」，用掩码的解析形状保证连通。
  4. **X/Y 环绕支持**是「Z 周期」的现成参考：注意 freeciv 里 wrap 方向的所有距离计算都必须用环面距离，否则会出现接缝。塔洛斯经纬如果直接对 z 取模，所有纬度相关量（温度、气候带）必须走三角函数而非线性差值。
  5. **fracture 的「边缘陆块下沉」技巧**：想让无限世界永远不出现「贴着边界的畸形大陆」，可以显式定义边界，而塔洛斯的边界就是南北极——在极区强制下沉/冰盖，符合地球直觉。

## 02 Unciv（Civ5 的开源 Kotlin 重写）

- **链接**：
  - 陆块生成：https://github.com/yairm210/Unciv/blob/master/core/src/com/unciv/logic/map/mapgenerator/MapLandmassGenerator.kt
  - 高程生成：https://github.com/yairm210/Unciv/blob/master/core/src/com/unciv/logic/map/mapgenerator/MapElevationGenerator.kt
  - Perlin 实现：https://github.com/yairm210/Unciv/blob/master/core/src/com/unciv/logic/map/mapgenerator/Perlin.kt
- **一句话原理**：用一份标准 Perlin 噪声（noise3d，默认 octaves=3、persistence=0.5、lacunarity=2.0、scale=10.0）生成高程，再做**带符号幂重分布**（powSigned，指数为 1 - elevationExponent）拉开高差，最后用**元胞自动机**把山丘连成山脉；陆块形状则由 12 种命名模板（pangaea / innerSea / continentAndIslands / twoContinents / archipelago / perlin / fractal / lakes / boreal / smallContinents / spiral / fourCorners）各自的一段过程式代码决定。
- **类别**：开源 4X 手游的**方法级参考实现**，Kotlin 可读性极好。
- **输出范围**：**有限地图**（六边形网格，含 MapShape.flatEarth 等形状），有 tile.latitude / tile.longitude 概念但地图本身有限。
- **实时性**：**需离线整图迭代**。cellularMountainRanges() / cellularHills() 各跑 5 轮全图邻域统计，是典型的全局迭代；单点无法 O(1) 求值。
- **地球式双峰高程**：**弱**。幂重分布能把「大部分低地 + 少数高山」拉开，但本源仍是单峰 fBm；海平面由 waterThreshold 决定，并通过 retryLoweringWaterLevel() **反复降低水位直到水域占比 ≤ 70%**（最多重试 30 次，步长 0.02 * max(1, 水占比/0.7) * sqrt(retry)）。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**无**。地形只有「水 / 平地 / 丘陵 / 山脉」四档，没有海底分层。
- **内海与孤岛**：
  - **有专门的 innerSea 地图类型**——说明「内海」在 4X 里被当作一种**要有意生成或有意避免**的形态，其代码结构值得读（先铺一圈陆地再挖中心水域）。
  - 岛屿数量由地图类型硬编码控制（continentAndIslands vs smallContinents vs archipelago），**没有全局连通性检查**，因此散岛是靠模板设计避免的，不是靠算法保证的。
- **语言 / 依赖 / 许可证 / star**：Kotlin（libGDX）/ **Mozilla Public License 2.0**（LICENSE 原文核实）/ star 未取到。
- **对本项目的可借鉴点**：
  1. **powSigned 幂重分布是「单峰 → 类双峰」最便宜的一招**：把约在 [-1,1] 的噪声输出 e 取 sign(e) * |e|^p，p 大于 1 时低地被压平、高地被拉开。塔洛斯经纬可以在**大陆掩码**上先做这一步：mask^2.5 会把「大片接近 0.5 的中间态」推向海洋或陆地两端，直接减少海岸线附近的碎岛和内海。代价与一次 pow 相同，性能可忽略。
  2. **「重试直到水占比达标」在无限世界不能照搬**，但可以**把重试换成离线标定**：离线统计一次掩码分布，求出让陆地占比等于目标值的阈值常数，运行时只做一次比较。这就是「零运行时迭代」的等价物。
  3. **元胞自动机连山**（5 轮、邻域计数：相邻山数为 0 则降级、为 1 则升级）：规则集本身很小，如果愿付「块级邻域查询」的代价（3×3 块而非全图），可以做到近似 O(1) 的局部 CA，把噪声里的孤立山峰连成山链。但它天然不是无状态的，需要定义确定性邻域以免破坏可重复性。
  4. **mapSpecificElevationOffset**（boreal 地图 +0.03）展示了「地图预设 → 少量数值加减」的廉价差异化，塔洛斯经纬可以用同样手法做「大陆预设 / 群岛预设」而不用改算法。

## 03 Civilization IV —— PerfectMongoose.py（板块构造派，本调研**最贴近塔洛斯经纬**的一条）

- **链接**：
  - 源码（AdvCiv 维护版）：https://github.com/f1rpo/AdvCiv/blob/master/PrivateMaps/PerfectMongoose.py
  - 同族（Caveman2Cosmos）：https://github.com/caveman2cosmos/Caveman2Cosmos/blob/master/PrivateMaps/C2C_World.py
- **一句话原理**：**先在网格上真的模拟一次板块构造**——随机播撒板块种子、让它们竞争生长成板块、给每个板块一个基准高度与倾角，再沿**板块边界**按「距离场 + 板块夹角」加一段 **ripple（波动）公式**（岛弧/洋脊的来源），最后把它与一张**被扭曲的 Perlin 山脉图**混合，并用边缘衰减强制四周成洋。
- **类别**：商业游戏（Civ4）的 Python 地图脚本；因为地图脚本是纯 Python，**数学细节 100% 可读**，是本次调研中信息密度最高的一条。
- **输出范围**：**有限地图**（hmWidth × hmHeight），支持 WrapX / WrapY（AddWaterBands() 明确写了「wrap 方向不能加水带」，说明环面逻辑被认真处理过）。
- **实时性**：**需离线全局模拟**（板块生长是 BFS 式扩张，还带 "endless loop in plate growth" 的死循环保护）。**但它的每个子步骤几乎都能改造成 O(1)**，见「可借鉴点」。
- **地球式双峰高程**：**是（本调研中少数明确构造双峰的实现）**：
  - 代码注释原文：Weight of the mountain elevation map versus the coastline elevation map（mountainFreq = 0.078，mountainWeight = 0.8）——它**显式维护两张图**：一张「海岸线/大陆台地」图（低频）和一张「山脉」图（高频），再按权重叠加：data[i] = (tVal + ((mountainMap[i] * 2.0) - 1.0) * mountainWeight)。
  - 板块高度图 plateHeightMap 负责**大片等高的台地**（plateStagger、plateStaggerRange、plateHeightMap[i] = avg），这正是「大陆台地约 +0.3 km」的数学对应物。
  - 海平面由 CalculateSeaLevel() 用**百分位阈值**决定：land = landPercent * SeaLevelFactor；seaLevelThreshold = FindThresholdFromPercent(data, length, land, True)——**陆地占比是输入参数而不是结果**。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**有「类岛弧/洋脊」机制，没有显式海沟**：
  - 板块边界处计算 distanceList[plateID]（到各板块的距离场），再按两侧板块的 angle 求 angleDifference，套 ripple 公式（含 cos(rippleFrequency * distance) 与距离归一化项），然后 plateHeightMap[i] += avgRipple - avgRipple * PRand.random() * plateNoiseFactor。**「离板块边界越近，高度按余弦波动抬升/下降」**，这就是岛弧 + 洋中脊的统一生成式。
  - 山脉图由 GenerateTwistedPerlinMap() / GenerateMountainMap() 生成，含 **domain twisting（把 Perlin 采样坐标按另一张噪声扭曲）**——这正是让山脉「自然蜿蜒」而不是「一团一团的斑」的关键技巧。
  - 边缘衰减 GetAttenuationFactor()：南/北/东/西各有一段 *AttenuationRange，在边缘把高度乘以 factor + (d/range)*(1-factor)，**强制地图四周是海**。
- **内海与孤岛**：
  - FillInLakes() 专门填湖（**内海消除**的正面实现）；
  - AddWaterBands() 在非 wrap 方向**加一圈强制为 0 高度的水带**；
  - 板块生长用 isSeedBlocked() + plateSeedRerollExp = 8 让种子分布更均匀，避免「一块大陆全挤在一角」；
  - raiseOnly = True：每个象限至少有一个板块被标记为只升不降，用来**强制地图上有稳定的陆地骨架**。
- **语言 / 依赖 / 许可证 / star**：Python 2（Civ4 BTS 地图脚本运行环境），无外部依赖 / 仓库 LICENSE 未取到（AdvCiv 是 Civ4 模组，条款未核实）/ star 未取到。
- **对本项目的可借鉴点**（逐条，尽量可直接写成代码）：
  1. **「两张图混合」的配方直接可用，且可以做成 O(1)**：h(x,z) = base(x,z) + w_m * (mountain(x,z)*2-1)，其中 base 是**低频大陆掩码**（决定台地/深海两峰），mountain 是**高频扭曲噪声**（决定山脉纹理）。只要保证 base 的分布是双峰的，山脉图随便用什么 fBm 都不会破坏双峰性。
  2. **用百分位阈值把「陆地占比」变成输入**：离线对 base 的分布做一次数值积分（或直接假设高斯/Logistic 分布用解析分位数），求出阈值 t 使 P(base > t) = 目标陆地占比。运行时只做一次比较——**零成本标定**。
  3. **岛弧/洋脊的低成本替身（关键创新点）**：不需要真的模拟板块。用**一张低频 Voronoi/Cellular 噪声**得到「板块 id」与「到最近边界的距离 d」（Worley 噪声的 F2−F1 天然就是边界距离场，O(1) 可求值），再算 arc(x,z) = A * exp(-d/λ) * cos(2π d / P + φ(cellId))，叠加到 base 上。这就在 O(1) 内得到了「沿板块边界成串的岛弧 + 洋中脊」，且 exp(-d/λ) 保证它不会污染深海盆地内部。
  4. **GetAttenuationFactor() 的边缘衰减函数**可以整体搬来做**极区处理**：塔洛斯的「边缘」是 z 到两极，把衰减函数的 y 换成 |latitude| 即可（并且因为 z 是周期的，衰减函数必须以周期方式拼接）。
  5. **plateStagger（板块 ID 取模 × 步长）**：给每个板块一个**离散的高度档位**，再平滑。这是「大陆台地」的廉价实现：档位化天然产生平坦台面，平滑后得到台地而不是斜坡。塔洛斯经纬可以用 floor(voronoiId % N) 做同样的事。
  6. **FillInLakes() + raiseOnly 对应「内海数 = 0」**：与其事后填湖，不如**在掩码层面做形态学闭运算的解析版**——对低频掩码取 max 与 min 的局部滤波（可用两层不同频率的噪声近似），保证陆地骨架连通。
  7. **domain twisting（扭曲域）**：这是提高「自然感」性价比最高的一招——用一张极低频噪声去偏移采样坐标（x' = x + 30*noise(x,z)）。塔洛斯经纬几乎零成本就能把「噪声斑块」变成「蜿蜒海岸线」，对海岸线分形维数 D 落在 1.2~1.4 有明显帮助。

## 04 Civilization V —— PerfectWorld3（Cephalo）

- **链接**：https://forums.civfanatics.com/threads/perfectworld3.399952/
- **一句话原理**：作者原话：「This map script uses various manipulations of Perlin noise to create landforms, and generates climate based on a simplified model of geostrophic and monsoon wind patterns.」——即 Perlin 噪声的多种变换造地形 + **简化地转风与季风环流**造气候带 + 沿等高线生成河流（并填洼以保证河流入海）。
- **类别**：商业 3A（Civ5）的 Lua 地图脚本；**「气候驱动」流派的代表**。
- **输出范围**：有限地图。
- **实时性**：**离线整图**（含全局洼地填充；作者原话是如果洼地没填干净就让地图崩溃，以免生成坏图，说明该步骤必须全局一致）。
- **地球式双峰高程**：**弱**——地形本身是「Perlin 的多种变换」，没有显式的台地/盆地双峰构造；但大陆样式（continent art styles）与气候模型让它看起来更像地球。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**部分有**——有「山脉范围整理（Cleaned up the mountain ranges）」、河流入海、雨影；没有海沟/洋脊的显式机制。
- **内海与孤岛**：有「所有玩家出生在最大陆块（like they do in Terra）」的选项，说明**最大连通陆块被显式计算过**；河流按「每个六边形顶点都有河，只有水量超过阈值的可见」实现（作者原话），这是一种非常巧妙的水文可视化。
- **语言 / 依赖 / 许可证 / star**：Lua（Civ5 地图脚本 API）/ 论坛发布，条款未核实 / star 不适用。
- **对本项目的可借鉴点**：
  1. **气候模型外包给风带**：原作者用「地转风 + 季风」解释降水（雨影效应截图被作者当作卖点）。对塔洛斯经纬来说，**纬度是天然输入**（z 轴就是纬度），所以「温度 = f(|纬度|) − 海拔递减；降水 = 风带 + 雨影」这套**不需要全局模拟**，全部可以写成 O(1)：风带用 cos(3π * latitude) 之类的周期函数，雨影用沿风向对高度做一次短程差分。
  2. **雨影的 O(1) 实现**：precip(x,z) = base(lat) - k * max(0, h(x,z) - h(x - L*windx, z - L*windz))，即只采样**上风方向一点**的海拔差，避免任何扫描。
  3. **「只有水量超过阈值的河可见」**：把河流当作**隐式场**而不是几何体，非常适合无限世界——不需要河流网络数据结构，只要每个块算一个「水量」标量并决定是否生成河床。
  4. **注意它的失败模式**：全局填洼是它最大的工程债（会崩溃）。塔洛斯经纬若要河流，必须选**不依赖全局拓扑**的方案（例如：河流 = 陡度 + 水量阈值，允许断流）。

# 二、模拟 / 沙盒游戏的世界生成

## 05 Dwarf Fortress 世界生成

- **链接**：
  - 官方 Wiki 世界生成：http://www.dwarffortresswiki.org/index.php/World_generation
  - 高级参数（侵蚀周期等）：https://new.dwarffortresswiki.org/index.php?title=Advanced_world_generation
- **一句话原理**：Toady 自己的描述被 Wiki 原样引用——「先把基础场（**elevation, rainfall, temperature, drainage, volcanism, wildness**）**按可变大小的网格播种**，然后 **filled in fractally**（分形填充）；随后进入**侵蚀与河流阶段**（小海洋被抽干、从山侧反复放测试河流下切），最后按雨影与地形降水重算降雨、按海拔重算温度。」——**分形插值 + 水力侵蚀的经典组合**。
- **类别**：商业模拟游戏（C++），世界生成是它最著名的「重 CPU」环节。
- **输出范围**：**有限**（网格尺寸、区域数、拒绝重试次数都可参数化；世界生成后是一张固定大小的区块网格）。
- **实时性**：**需离线全局模拟**，且是**本清单里最重的**：Wiki 高级参数里有「让世界在跑河流阶段花多久把高峰侵蚀成山坡」的项，侵蚀循环数可以开到极大；生成过程中世界会因为参数不满足而被**整个拒绝并重来**（rejection count）。
- **地球式双峰高程**：**弱-中**。「海洋 / 岛屿大小」是显式参数，海拔是分形场 + 侵蚀的结果，没有地球测高曲线的显式建模；但**侵蚀本身会自然造出准平原（低地台地）与深海**两面。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**无显式建模**，但流程里有三个可借鉴的对应物：Small oceans are dried out（内海消除）、it locates edges of mountain sides where it can run test rivers（山坡识别）、volcanoes are placed respecting the hot spots in the volcanism field（热点火山 = 洋中脊/热点岛链的雏形）。
- **内海与孤岛**：**明确处理**——「小海洋被抽干」是官方流程的一部分；海洋大小与岛屿大小都是世界生成参数；世界会因为「生物群系不满足范围要求」等原因被拒绝重生成。这印证了一件事：**「内海数 = 0」在工程上通常靠事后填小水域，而不是靠一次生成就对**。
- **语言 / 依赖 / 许可证 / star**：C++ / 闭源商业软件（有免费版）/ star 不适用。
- **对本项目的可借鉴点**：
  1. **「多场分开播撒再各自分形填充」的架构**：elevation / rainfall / temperature / drainage / volcanism / wildness 是**六个独立标量场**，各自有自己的频率与分形阶数。塔洛斯经纬应照抄这个结构：h（高程）、t（温度）、p（降水）、v（火山/构造活跃度）各一个噪声，互不耦合；生物群系是它们的函数，而不是反过来。
  2. **侵蚀的「非全局化」改造**：DF 的河流侵蚀需要全局流向，但**热力侵蚀（thermal erosion）是纯局部的**：delta = k * (h(x) - h(x+dx) - talusAngle)，只采样邻域。塔洛斯经纬可以在块内/块间做 1~2 次**确定性热力侵蚀**（每次只查 8 邻域，固定迭代次数保证可重复），得到自然的山坡碎屑坡，而完全不破坏 O(1)。
  3. **「抽干小海洋」的局部替身**：对低频掩码做**开运算（腐蚀→膨胀）**只保留足够大的水域；在无限世界里可用形态学算子的解析近似（两次不同阈值的比较）实现，避免全局连通性搜索。
  4. **「参数不满足则拒绝整个世界」**：在无限世界里不能拒绝世界，但可以**拒绝单个块并降级**——例如某个块算出来是「孤立小岛」，就把它的掩码往下压到海平面以下。这就是「局部拒绝采样」，成本一次比较。

## 06 RimWorld 行星生成

- **链接**：https://rimworldwiki.com/wiki/World_generation
- **一句话原理**：生成一颗**有限球面行星**（可选覆盖度与种子），每个像元携带 **elevation / temperature / rainfall / hilliness / swampiness** 等标量层；温度受**纬度**强烈影响（Wiki 原话：The coordinates of a map tile includes its latitude which affects its temperature range and amount of daylight）。
- **类别**：商业模拟游戏（C#，Unity）。
- **输出范围**：**有限球面**（有 coverage 滑杆，可只生成行星的一部分球面）。
- **实时性**：**离线一次**（生成后存进存档；不是每次查询重新求值）。Wiki 未公开噪声实现细节，**具体噪声类型未核实**（网上常见的「Perlin 分层」说法本次未能取得可验证的一手来源，故不写入结论）。
- **地球式双峰高程**：**否**（Wiki 对 elevation 的描述只有「离海平面多高、越高越冷」，无测高曲线/台地构造）。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**无**（没有海底深度分层概念）。
- **内海与孤岛**：无显式机制。
- **语言 / 依赖 / 许可证 / star**：C# / Unity / 闭源商业软件（有反编译镜像 https://github.com/Chillu1/RimWorldDecompiled ，其许可证与版本未核实）/ star 不适用。
- **对本项目的可借鉴点**：
  1. **「纬度 → 温度 → 可居住性」的链式气候**是塔洛斯经纬**最值得仿照的一层**：因为 z 轴已经是纬度，t = cos(lat) - k*elevation 这类公式天然 O(1)，且能免费得到极地冰盖、赤道雨林。RimWorld 证明**「一层气候 + 一层海拔」就足以让玩家感到真实**，不需要真的模拟气候。
  2. **coverage（只生成一部分球面）**：对应「不生成整个世界也能玩」的产品化思路；塔洛斯经纬的对应物是「Z 周期内的任一纬度带都能独立成图」。
  3. **反例价值**：RimWorld 的地形是**有限且一次性**的，所以它可以支付「全局生成 + 存盘」的代价来换丰富度。塔洛斯经纬不能，因此**凡是依赖「看一眼全局再决定」的 RimWorld 式设计都不能用**——这是一个明确的负面清单项。

## 07 Terasology

- **链接**：
  - 仓库：https://github.com/MovingBlocks/Terasology
  - 世界生成架构文档：https://deepwiki.com/MovingBlocks/Terasology/9-world-generation
- **一句话原理**：**Facet 管线**——地形不是「一个生成器函数」，而是一组 **Facet（世界数据切片：surface height、biome、ore 等）**，由若干 **FacetProvider 顺序求值**（每个 Provider 可以依赖前面 Provider 的 Facet，且可以声明自己「需要邻域数据」），最后由 **Rasterizer** 把 Facet 转成方块。社区可见引擎自带的 PerlinFacetedWorldGenerator。
- **类别**：开源体素游戏引擎（**Java**，与塔洛斯经纬同语言）。
- **输出范围**：**无限程序化**（块按需生成）。
- **实时性**：**接近 O(1) 求值**（按块/区块求值并缓存已生成块）；但 Provider 允许声明「需要邻居数据」，所以严格说不是无状态。
- **地球式双峰高程**：**否**（引擎只提供机制，默认世界是普通地形）。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**无内置**（架构上可插入自定义 FacetProvider 实现）。
- **内海与孤岛**：无内置机制。
- **语言 / 依赖 / 许可证 / star**：Java（Gradle，模块化）/ **Apache License 2.0**（LICENSE 原文核实）/ star 未取到。
- **对本项目的可借鉴点**：
  1. **Facet 分层 + 依赖声明的软件架构**值得直接借鉴：塔洛斯经纬可以把「大陆掩码 / 海底深度 / 高度 / 温度 / 降水 / 生物群系」各写成一个**纯函数 facet**，用一张显式的依赖图组织；好处是每个 facet 都可以单独测试「分布是否双峰」「海岸线维数是否 1.35」。
  2. **「声明式邻域需求」机制**：把「需要邻域的少数量」局部化（例如只让热力侵蚀 facet 需求 ±1 块），其余 facet 保持纯 O(1)，是兼顾质量与性能的标准做法。
  3. **Java 生态 + Apache 2.0**：如果塔洛斯经纬需要直接抄代码，Terasology 是许可证最干净、语言最匹配的候选。
  4. **反面教训**：把地形拆成很多 Provider 会让性能变差（每个 facet 一次遍历）；塔洛斯经纬应保证**每个块只做一次全量求值**，facet 只是组织代码的方式，不要变成多次遍历。

## 08 Factorio（噪声表达式 + autoplace）

- **链接**：
  - Wiki 地图生成器：https://wiki.factorio.com/Map_generator
  - 可编程噪声说明（社区权威整理，TOGoS）：https://gist.github.com/TOGoS/97c0b905e1183e58ccf24fba6092bad6
  - 噪声表达式实验工具：https://togos.github.io/togos-example-noise-programs/
- **一句话原理**：地形的基底是 **Factorio basis noise**——一种连贯噪声；单次采样得到均匀的颠簸纹理，**把同一基函数在多个尺度上叠加就得到 multi-octave noise**（原文：layering of the basis noise at different scales to make multi-octave noise）；在此之上用 **autoplace 概率表达式**决定每种资源/地物放在哪，用频率/大小/丰富度滑杆暴露给玩家。
- **类别**：商业工厂建造游戏（C++）；**其噪声层是「可编程表达式」而非固定函数**，可读可改。
- **输出范围**：**无限**（2.0 的 Nauvis 及行星表面均无限；Map height on all planets is limited to 128 只限制竖直高度）。
- **实时性**：**O(1) 求值**——Factorio 的整个地形是 (x, y, seed) 的纯函数，不给全局地图；这是与塔洛斯经纬**约束完全一致**的商业级证据。
- **地球式双峰高程**：**否，但海平面可标定**（水覆盖度/尺度滑杆 + Terrain map type is set to island 预设；没有台地/深海两峰的显式构造）。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**无**。
- **内海与孤岛**：由「水覆盖度 + 尺度」两个滑杆间接控制；有 lakes 预设、cliff 连续性设置（Cliff continuity，越低越破碎；cliffs that tend to follow the coastline）。
- **语言 / 依赖 / 许可证 / star**：C++ + Lua（模组接口）/ 闭源商业软件 / star 不适用。
- **对本项目的可借鉴点**：
  1. **「地形 = (x, y, seed) 的纯函数」是商业上被验证可行的**：Factorio 用同一份确定性噪声同时服务多人同步、地图预览与超远距离探索，从不存全局地图。塔洛斯经纬的硬约束不是学术洁癖，而是被商业产品验证过的工程选择。
  2. **basis noise + 多尺度叠加的明确语义**：把「基函数」与「八度叠加」分离，使得**换基函数不影响结构**。塔洛斯经纬应把 Perlin/Simplex 封装成一个 basis(x,z)，大陆掩码、山脉、细节全部是它的不同频率叠加，便于单独调参。
  3. **autoplace 的「概率表达式」思想**：每个地物不是「在某个坐标生成」，而是「对该坐标求一个 0~1 的概率」，再与确定性随机数比较。这天然适合「山脉 / 岛弧 / 海沟」这类**稀疏特征**：P_trench(x,z) = clamp((boundaryDist < d) * voronoiActive)，无需任何数据结构。
  4. **cliff continuity 的教训**：破碎感来自「高频细节的连续性参数」；海岸线的分形维数可以用同样手法控制——**用一个连续度参数在高频与低频之间插值**，比调 octave 数更可控。
  5. **高度硬上限（128）**：给世界一个明确的高度范围可以让地形数据紧凑（byte/short），塔洛斯经纬若把高度量化到 8~16 位，能同时提高缓存友好度。

## 09 TerraFirmaCraft（气候驱动生物群系）

- **链接**：https://terrafirmacraft.github.io/Documentation/1.18.x/worldgen/dimension/
- **一句话原理**：不生成「生物群系」而是生成**气候场**：文档写明维度有 temperature_settings 与 rainfall_settings 两套**气候设置**（可用预设 tfc:default 或自定义），其 scale 参数定义为「**peaks 之间相距多远**」（原文：scale is an integer, which represents how far apart peaks are），另有 rock_layer_scale 控制岩层区域的距离；生物群系是「温度 × 降水 × 岩层」的查表结果。
- **类别**：Minecraft 大型模组（Java，Forge），**与塔洛斯经纬同一生态**。
- **输出范围**：**无限程序化**。
- **实时性**：**O(1)**（噪声采样 + 查表）。
- **地球式双峰高程**：**否**（TFC 不控制高程分布，它用的是 Vanilla 的 noise_settings）。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**无**（TFC 完全没有海洋深度分层）。
- **内海与孤岛**：不处理（沿用原版地形）。
- **语言 / 依赖 / 许可证 / star**：Java / Forge + NeoForge / 许可证未核实 / star 未取到。
- **对本项目的可借鉴点**：
  1. **「生物群系 = 气候场的查表结果」的解耦**：这是塔洛斯经纬**应该直接采用的架构**——不要生成「热带雨林」，生成「温度 27℃、降水 1800mm」，由查表决定群系。这样 Z 轴纬度可以直接进入温度公式，且永远不会出现「沙漠长在极地」的荒谬感。
  2. **scale = 「峰间距离」的语义**：TFC 把噪声频率直接暴露为**可理解的物理量**（相隔多远出现一个气候极值），这比暴露 frequency = 0.003 友好得多。塔洛斯经纬的参数应该用「大陆尺度（km）」「山脉间距（km）」表达。
  3. **独立 rock_layer_scale**：岩层区域与气候区域是**两套独立噪声**——因为地质与气候无关。塔洛斯经纬也应对「地质省（province）」与「气候带」使用不同种子/频率的噪声，避免地形与群系相关性过强。
  4. **1.7.10 版本提示**：现代 TFC 文档（1.18+）用的是数据包式配置；1.7.10 时代的 TFC 用 Java 常量 + 噪声场实现同类气候模型。若要移植，**数学（气候场）可以照搬，配置系统要重写成 1.7.10 的 WorldType + GenLayer 风格**。

## 11 Kerbal Space Program —— PQSMod_VertexPlanet（**双峰高程的现成实现**）

- **链接**：
  - 类参考（成员列表）：https://kspmoddinglibs.github.io/KSPDocsSite/class_p_q_s_mod___vertex_planet-members.html
  - Kopernicus 的 PQS Mods 文档：https://kopernicuswiki.github.io/PQSMods/PQSMods.html
- **一句话原理**：把行星表面当作**球面顶点网格**，每个顶点的高度由一组**大陆噪声 + 高度曲线 + 陆类选择**算出：类成员里可以明确看到 continental、continentalRuggedness、continentalSharpness、continentalSharpnessMap（大陆掩码与其锐度/锐度图）、GetVertexMinHeight() / GetVertexMaxHeight()（高度上下界）、OnVertexBuildHeight()（高度求值入口）、**SelectLandClassByHeight(double height)**（**按高度选择陆地类别**）与 buildHeightColors。
- **类别**：商业航天模拟游戏（C#，Unity）的**程序化行星模块**，且有完整的第三方文档（Kopernicus / KittopiaTech）。
- **输出范围**：**球面（有限但无缝）**。
- **实时性**：**O(1) 顶点函数**（每个顶点独立求值，随 LOD 分块构建）。**这是「按点求值 + 高度分层」的教科书实现**。
- **地球式双峰高程**：**是（结构上是）**——continental 噪声 + continentalSharpness 让高度分布呈现「大片低地/高地台面 + 陡峭过渡」，再由 SelectLandClassByHeight 把高度区间映射成不同的「陆地类别」（颜色/材质/地貌），这正是地球式「陆架—陆坡—台地」的实现范式，而且它**不需要全局信息**。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**有陆架/陆坡的机制（height → land class 映射 + sharpness 控制过渡带宽度）**；岛弧/海沟/洋中脊**无内置**（KSP 的行星不以地球板块为目标）。
- **内海与孤岛**：不处理（KSP 的星球可以到处是湖）。
- **语言 / 依赖 / 许可证 / star**：C#（游戏本体闭源；Kopernicus 等模组开源，许可证未核实）/ star 不适用。
- **对本项目的可借鉴点**（**本条是本调研中「双峰高程 + 陆架」最可直接抄的数学**）：
  1. **height → land class 的分段映射 = 大陆架/陆坡/深海平原的零成本实现**：定义几段高度区间与各自的「地貌类别」（深海平原 / 陆坡 / 陆架 / 海岸 / 平原 / 高原 / 山脉），class = SelectLandClassByHeight(h)。关键技巧是**在类别边界处用 sharpness 参数控制过渡带宽度**：shelfWidth 大则平缓陆架，小则陡峭陆坡。全部是纯函数比较，O(1)。
  2. **continentalSharpness + continentalSharpnessMap**：让「大陆边缘的陡峭程度」本身也是一张噪声图——这样同一颗星球上既有被动大陆边缘（宽陆架）又有活动边缘（窄陆架、紧邻深海）。塔洛斯经纬可以照抄：shelfWidth = lerp(minW, maxW, sharpnessNoise(x,z))。
  3. **GetVertexMinHeight()/MaxHeight() 显式维护高度上下界**：保证地形不会突破世界高度限制（对 Minecraft 1.7.10 的 256 高度上限尤其重要）。
  4. **「先算大陆掩码，再算高度曲线」的两段式**：h = curve(continental(x,z)) + ruggedness * detail(x,z)，与 PerfectMongoose 的「两张图混合」是同一思想，但**KSP 版本更适合实时**（无板块模拟、无距离场，纯噪声 + 曲线）。
  5. **把「锐度」也噪声化**是让海岸线分形维数 D 落在 1.2~1.4 的**直接手段**：锐度高则海岸线锯齿化（D 上升）；锐度低则海岸线平滑（D 下降）。这比调 octave 数更容易命中目标区间。

## 12 Azgaar Fantasy Map Generator

- **链接**：
  - 仓库：https://github.com/Azgaar/Fantasy-Map-Generator
  - 高度图生成器源码：https://github.com/Azgaar/Fantasy-Map-Generator/blob/master/src/generators/heightmap-generator.ts
  - 高度模板数据：https://github.com/Azgaar/Fantasy-Map-Generator/blob/master/public/config/heightmap-templates.js
  - 架构文档（第三方）：https://deepwiki.com/Azgaar/Fantasy-Map-Generator/2.2-heightmap-generation
- **一句话原理**：先在画布上生成 **Voronoi 图（网格单元）**，然后**按模板脚本**逐条执行「高度工具」：模板是一个多行字符串，每行是一个工具调用（Hill / Pit / Range / Trough / Strait / Mask / Invert / Add / Multiply / Smooth），每个工具在 Voronoi 图上落一个**斑块（blob）**并按 blobPower 做幂次衰减（源码：h = h ** this.blobPower * (Math.random() * 0.2 + 0.9)，blobPower 由单元数决定，缺省 0.98），最后平滑。也支持**导入真实地球高度图 PNG**（public/heightmaps/ 下有 world.png、eurasia.png 等）。
- **类别**：开源 Web 地图生成器（TypeScript + D3），有完整的可读源码与模板数据。
- **输出范围**：**有限画布**（点数/单元数可配），也可导入图片作为有限底图。
- **实时性**：**离线整图**（Voronoi 单元是全局结构，模板工具在整图上迭代）。
- **地球式双峰高程**：**弱**——模板 + blob 是「手工设计的形状」，分布由模板决定；Mask / Multiply 工具可以把中间高度整体压低，从而近似双峰，但不是数学保证。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**有 Trough（海沟/裂谷）与 Strait（海峡）工具**，是少数把「海沟」当作一等公民的生成器；**没有**岛弧/洋中脊（由模板里的 Hill/Range 近似）。
- **内海与孤岛**：**有专门的 Strait 与 Trough 工具来「切开」或「连接」水体**，并提供 Mask 工具强制边界为海；实际的内海数量靠模板设计 + 手动编辑保证，不是算法保证。
- **语言 / 依赖 / 许可证 / star**：TypeScript / D3、Web Worker / **MIT License**（LICENSE 原文核实）/ star 未取到。
- **对本项目的可借鉴点**：
  1. **blob 的幂次衰减**是「斑块式」地形最省事的方法：h += amplitude * max(0, 1 - (d/r)^2)^p。在无限世界里，可以用**Cellular/Worley 噪声的 F1 距离**当作 d，于是「落一个 blob」变成纯 O(1) 求值——**这是把 Azgaar 的模板系统搬进无限世界的关键改造**。
  2. **模板即数据（DSL）**：地形由「一串工具调用」描述，而不是硬编码。塔洛斯经纬应把「大陆掩码 / 山脉带 / 海沟」写成**可配置的工具序列**，每个工具在噪声域里对应一个数学算子（加 blob、乘掩码、幂重分布、平滑）。这样调参不需要重新编译，也便于做预设。
  3. **Mask（强制边界为海）与 Invert 工具**：对应塔洛斯经纬的极区/边界处理，可作为一个算子直接实现。
  4. **导入真实地球高度图**：虽然是有限底图、不能用于无限世界，但**可以用来做「分布标定」**——离线统计真实地球的测高直方图与海岸线维数，用来校准塔洛斯的曲线参数。这是把「离线」用在正确地方的方式。
  5. **Smooth 工具**：对噪声场做小核平滑是提升海岸线自然度最便宜的算子；在 O(1) 语境下用「降低最高八度的幅度」等效实现。

## 13 Amit Patel / Red Blob Games —— mapgen4 与 terrain-from-noise（**方法论标杆**）

- **链接**：
  - 教程：https://www.redblobgames.com/maps/terrain-from-noise/
  - 岛屿整形专文：https://www.redblobgames.com/maps/terrain-from-noise/islands.html
  - mapgen4 源码：https://github.com/redblobgames/mapgen4
  - mapgen4 场景集：https://www.redblobgames.com/x/2319-mapgen4-scenarios/
- **一句话原理**：把地形拆成三个可独立设计的纯函数：
  **① 噪声** noise(x,y)；
  **② 重分布（redistribution）** e' = pow(e, k)（原文：To make flat valleys, we can raise the elevation to a power）——把单峰分布整形成「大片低地 + 少量高地」；
  **③ 岛屿整形**：分解为**距离函数 d(x,y)** 与**重塑函数 r(e,d)** 两部分，d 推荐用 **Square Bump**（文中原话：Of the distance functions I looked at, I think Square Bump and Trig Product from KdotJPG are the best choices, and of those two, Square Bump is...），r 的设计目标是「地图边缘永远低（水）、地图中心永远高（陆）、其余混合」。
- **类别**：开源教学项目 + 可运行应用（TypeScript）；作者是 PCG 领域最权威的科普者之一。
- **输出范围**：**有限画布**（但其函数本身与范围无关）。
- **实时性**：**O(1)**——噪声、幂重分布、距离掩码全部是点函数，可直接用于无限世界。
- **地球式双峰高程**：**可构造**。pow(e, k) 是「单峰 → 偏双峰」的标准工具，配合海平面阈值即可得到「大片浅海/深海 + 大片低地台地」；文中也说明 pow() 只是其中一种重塑函数（There are many other functions you can try）。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**无**（岛屿整形只管陆地轮廓，不细分海底）。
- **内海与孤岛**：**重塑函数就是为此设计的**——文中明确列出「边缘永远水、中心永远陆」的设计目标，可以在数学上**保证**没有碎岛/内海（因为掩码单调）。
- **语言 / 依赖 / 许可证 / star**：TypeScript / 无重依赖 / **Apache License 2.0**（LICENSE 原文核实）/ star 未取到。
- **对本项目的可借鉴点**（**最推荐优先落地的一条**）：
  1. **pow(e, k) 是命中「双峰 + 陆地占比可标定」的最短路径**：取大陆掩码 m 属于 [0,1]，令 e = pow(m, k)；k 大于 1 会把分布推向 0（深海）与 1（台地）两端，中间态减少，海岸线附近碎岛减少。k 可以直接由「目标陆地占比 + 目标双峰锐度」离线解出。
  2. **「距离函数 × 重塑函数」的分解**直接对应塔洛斯的两个难点：距离函数用 **Z 轴周期性的纬度距离**（把 z 映射到圆上）而不是矩形边界距离，天然无缝；重塑函数用**单调**函数（如 smoothstep、1 - exp(-k e)）来**数学保证**「极区必为海/冰、中纬必为陆」，从而杜绝「贴着极点的畸形大陆」。
  3. **Square Bump 距离函数**：d = (1-nx²)(1-ny²) 形式，比欧氏距离更方，但等高线形状可控；在无限世界里可以用周期化版本（把 nx、ny 换成 cos(2πz/P) 等）得到「沿纬度带连续」的掩码。
  4. **不要用「距地图中心的径向渐变」**（这是最常见的岛屿掩码写法）：它在无限世界里没有定义。塔洛斯的「边界」只有南北两极，所以**掩码的边界项必须是纬度的函数**，而不是到某点的距离。
  5. **场景集（Scenarios）的思路**：作者把同一套 mapgen4 代码用不同参数跑出多种地貌，作为一种可复现的实验记录。塔洛斯经纬应该照做：**固定种子 + 参数矩阵，批量导出高度直方图与海岸线维数**做回归测试。

## 14 OpenTTD TGP（TerraGenesis Perlin）——**「无限延伸」的现成论证**

- **链接**：
  - 源码：https://github.com/OpenTTD/OpenTTD/blob/master/src/tgp.cpp
  - 文档页：https://docs.openttd.org/source/df/d80/tgp_8cpp
- **一句话原理**：源码头注释就是完整说明书：Perlin Noise is a series of octaves of random noise added together... I use 6 octaves, with the amplitude controlled by a power ratio, usually known as a persistence or p value... Each octave is however raised to the power of its position in the list。为了造山，它**用修改过的种子再加一张噪声图**（I add a second generated map (with a modified seed), onto the original. This generally raises the terrain），然后因为高度只有 0..15 档、山顶溢出成平台，就把 **大于 12 的高度按比例压回 15**。
- **类别**：开源交通模拟游戏（C++，GPL）；**其地形生成器直接来自 TerraGenesis（Andrew Park）**，是「无限可延伸高度场」的经典实现。
- **输出范围**：**无限**——源码原话：It is also infinitely expandable; a single random seed terrain continues in X and Y as far as you care to calculate.（**这就是塔洛斯经度方向需求的现成论证**）。
- **实时性**：**O(1)**（每次采样式地计算 noise(x, y) 的 6 个八度；文中还专门讨论了把 7 次噪声调用优化成更少调用的工程细节——The overall speedup should be 300% to 800%）。
- **地球式双峰高程**：**否**（它是「抬升 + 压缩」的启发式：mountainous wasn't mountainous enough ... Overall effect is a general uplift，没有任何测高曲线）。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**无**（但后来的提交加了「TGP 自己会造深水」，见 OpenTTD 提交 Add: TGP makes deep water on its own）。
- **内海与孤岛**：不处理（湖泊/海洋由地图生成参数控制）。
- **语言 / 依赖 / 许可证 / star**：C++ / SDL 等 / **GNU GPL v2**（源文件头：GNU General Public License as published by the Free Software Foundation; version 2）/ star 未取到。
- **对本项目的可借鉴点**：
  1. **「多个八度 + 每个八度取幂」的持久度控制**：amplitude_i = p^i（而不是常见写法），文中强调最后一项 0.35^6 约等于 0.0018，即**高八度几乎不贡献**。塔洛斯经纬如果发现「细节太吵导致海岸线维数偏高」，直接把最高八度的幅度按幂次压下去即可，不必减少八度数（减少八度会损失细节）。
  2. **「第二张图（换种子）叠加抬升」**：这是一个**极廉价的造山技巧**——同一基函数换 salt 再叠一次，只抬升不加细节，能在不增加高频噪声的前提下把山脉抬起来。可以做成 h += w * basis(x, z, seed XOR 0x9E37)。
  3. **「高度溢出后按比例压缩」**：Minecraft 1.7.10 世界高度上限 256，塔洛斯经纬必然会遇到「山脉顶到上限变平台」的问题。OpenTTD 的解法（对超过阈值的高度做线性压缩，而不是硬 clamp）值得照抄，能避免「玻璃一样平的山顶」。
  4. **性能工程**：文中提到为了性能把「4 次 noise 调用 + 3 次线性插值」的写法换成「更少计算、更多内存访问」的实现，换来 3~8 倍加速。塔洛斯经纬若要「接近纯噪声」的性能，**必须避免每个八度都做完整插值**，可以预先算好置换表并用位运算取梯度。
  5. **可无限延伸不等于可周期**：TGP 在 X、Y 都无限，但**没有周期**。塔洛斯经纬的 Z 轴要做成周期，必须在噪声采样层面解决（例如把 z 映射到圆环上采样 3D 噪声：n(x, R·cos(2πz/P), R·sin(2πz/P))），这条 OpenTTD 帮不上，需要额外设计。

## 15 World Machine

- **链接**：
  - 特性页：http://world-machine.com/features.php
  - 首页（口号 Simulate, Don't Sculpt）：http://world-machine.com/index.php
  - 宏库：https://world-machine.com/library/
- **一句话原理**：设备图（device graph）式地形工具，官方明确的立场是「**Real erosion, not a noise filter**」：跑真实的**流动侵蚀（Flow-based erosion，模拟水的动力学冲刷出沟谷）**与**热力侵蚀（Thermal erosion，把悬崖分解并把碎屑堆成坡积裙 talus）**，再叠加 controllable fractals 做分形基底。
- **类别**：商业地形生成/编辑工具（Windows），离线烘焙。
- **输出范围**：**有限**（高度图/网格）。
- **实时性**：**离线**（侵蚀是多次迭代的真实模拟）。
- **地球式双峰高程**：**可调**（用户可控制 fractal 与侵蚀强度；工具本身不强制双峰）。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**无内置地球构造**；但**热力侵蚀的坡积（talus）角**恰好是「大陆坡」形状的数学来源。
- **内海与孤岛**：无自动机制（靠设备图与侵蚀）。
- **语言 / 依赖 / 许可证 / star**：闭源商业软件（Windows）/ star 不适用。
- **对本项目的可借鉴点**：
  1. **热力侵蚀的公式可以搬**（这是唯一能在 O(1)/局部范围内做的侵蚀）：若 h(c) - h(n) 大于 talus，则移动量 = k * (h(c) - h(n) - talus) / 2；h(c) -= 移动量；h(n) += 移动量。对 8 邻域做固定次数迭代。因为只依赖邻域且迭代次数固定，**可以在块内做、跨块边界用确定性的邻居块求值**，不破坏 O(1) 语义（代价是每块要多次求值邻域）。
  2. **「用侵蚀代替高频噪声」的审美**：官方口号点破了关键——噪声给的「山」是分形的、均匀的；侵蚀给的「山」有**坡积、沟谷、水系**。塔洛斯经纬若只用 fBm，山脉会「处处一样」；加一次廉价的热力侵蚀就能出现「山坡 + 山脚堆积」的分层。
  3. **流动侵蚀不能直接搬**（需要全局流向/汇水区），但可以**用「局部流向近似」替代**：flow(x,z) 取 8 邻域最大落差方向，只做 1~2 步，得到局部沟谷感。
  4. **「宏（Macro）」的组织方式**：把「大陆 + 山脉 + 侵蚀 + 输出」封装成可复用宏，对应塔洛斯经纬的预设。

## 16 L3DT（Large 3D Terrain Generator）

- **链接**：
  - 水映射算法文档：http://www.bundysoft.com/docs/doku.php?id=l3dt:algorithms:wm
  - 项目主页/说明：http://www.bundysoft.com/docs/doku.php?id=l3dt:about
- **一句话原理**：把地形生成拆成多个可独立配置的**算法模块**；其官方 Water-mapping algorithms 文档明确分成两块——**Flooding sea and lakes（用泛洪把海与湖灌到同一水平面，并区分海/湖）**与 **Water table and salinity mapping（地下水位与盐度映射）**。
- **类别**：免费地形生成工具（Windows），偏工程向。
- **输出范围**：**有限**（高度图 + 贴图）。
- **实时性**：**离线**（泛洪是全局算法）。
- **地球式双峰高程**：**否**（分布由各模块参数决定）。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**无**（但它区分「海」与「湖」，即区分「连通大水体」与「内海」——**这正是塔洛斯经纬「内海 = 0」判定所需的语义**）。
- **内海与孤岛**：**有海/湖区分与盐度**，是本次调研里少数把「水体分类」做成算法的工具。
- **语言 / 依赖 / 许可证 / star**：闭源免费软件 / star 不适用。
- **对本项目的可借鉴点**：
  1. **「海 vs 湖」的判据**：L3DT 用泛洪（连通性 + 水位）区分。在无限世界里可以退而求其次：**用低频掩码的值区分**——掩码低于深海阈值判为海（连通性来自掩码的连续性），处于盆地内且被陆地包围的判为湖/内海，直接压到海平面以下消灭它。
  2. **「水位 + 盐度」双场**：盐度是「距海距离」的函数，同样可以用一个低频场近似，用来驱动生物群系。塔洛斯经纬若做生物群系，这是零成本的差异化维度。
  3. **算法模块可插拔**：L3DT 的架构说明「地形生成是一串可替换的算法」，与 Terasology 的 Facet 是同一思路——**塔洛斯经纬应把每个算子写成可组合的纯函数**。

  3. **笔刷的数学**（若要写开发期调试工具）：raise 笔刷就是「到笔刷中心距离的核函数叠加」，与 Azgaar 的 blob 是同一个数学对象。

## 20 TerraForged / ReTerraForged

- **链接**：
  - 原仓库：https://github.com/TerraForged/TerraForged

- **类别**：Minecraft 现代版本（1.12~1.20+）的**专业级地形模组**，与 RTG 同代但架构更新。
- **输出范围**：**无限程序化**（1.16+ 有大陆类型/地形类型预设，含「标准大陆」预设）。
- **实时性**：**O(1) 噪声 + 分块后处理**（侵蚀/河流在块范围内做，配合区域缓存；严格的无状态性未核实）。
- **地球式双峰高程**：**弱**（有大陆概念与海平面控制，但没有公开的地球测高曲线；大陆是低频噪声阈值的结果）。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**有岸/崖/坡度类过滤器（filters）与河流系统**（第三方解析提到河流密度参数，如「河流密度 0.3 / 0.15 / 0.45」的预设差异）；**岛弧/海沟/洋中脊未核实**。
- **内海与孤岛**：有大陆类型预设与海平面参数可调；无公开的连通性算法。
- **语言 / 依赖 / 许可证 / star**：Java（Fabric/Forge）/ **MIT License**（TerraForged 与 ReTerraForged 的 LICENSE 原文均核实为 MIT）/ star 未取到。
- **对本项目的可借鉴点**：
  1. **「基础层 / 细节层 / 修饰层」三层划分**是可以直接照抄的模块划分：塔洛斯经纬把「大陆与海底（低频）」放第一层，「山脉（高频）」放第二层，「热力侵蚀 / 河流 / 海岸整形」放第三层，**每层各有自己的种子与频率**。
  2. **MIT 许可证 + Java + Minecraft 生态**：这是本次调研中**法律与工程双重最友好**的可参考实现；ReTerraForged 的目录结构（world/worldgen/noise/module/、data/preset/settings/）本身就是一份「怎么把地形参数化」的范例（路径来自第三方解析，**未逐文件核实**）。

- **对本项目的可借鉴点**：
  1. **「LandSize / LandRarity / GenerationDepth」三层语义值得照抄**：不要暴露 frequency = 0.0007，而是暴露「**陆地大小**」「**陆地稀有度**」「**细节层级深度**」——塔洛斯经纬的参数命名应同样贴近地理直觉（见 TFC 条的 scale 例子）。
  2. **BiomeMode: FromImage**：把「生物群系布局」从「算法」中解耦出来，允许用一张图片驱动。对本项目的启示是**架构上把「群系布局」做成可替换策略**：默认无限噪声，开发期可用地球图片（离线）对拍。
  3. **兼容性策略**：OTG 通过「群系组（biome groups）+ 自定义群系注册」把新群系接进原版体系，是 1.7.10 生态里与 Biome Bundle 这类大型群系包共存的范例，塔洛斯经纬若要与 BOP 等其他群系模组共存，应参考它的「群系组 + 稀有度」而非硬编码群系 id。
  4. **反例**：OTG 的核心价值在「配置能力」而非「地质正确性」；它的地形**不是地球式的**，不能用来解决双峰/陆架问题。

## 22 WorldEngine（Python）

- **链接**：https://pypi.org/project/worldengine/
- **一句话原理**：World generator using simulation of plate tectonics and other natural processes——在网格上模拟**板块构造**（板块种子、生长、边界形变），再叠加**侵蚀**与**气候/降水**模拟，产出高度图与生物群系图。

- **实时性**：**需离线全局模拟**（板块与侵蚀都是迭代模拟）。
- **地球式双峰高程**：**是**（板块模拟天然产出「大陆台地 + 深海盆地」；这也是它被广泛用于教学的原因）。
- **大陆架 / 大陆坡 / 岛弧 / 海沟 / 洋中脊**：**有**（板块边界机制会产出俯冲带/洋中脊/岛弧的近似形态）。

- **语言 / 依赖 / 许可证 / star**：Python（numpy 等）/ 许可证未核实 / star 未取到。
- **对本项目的可借鉴点**：
  1. **搬不进来**：它是「先模拟整张图，再输出」，与「运行时 O(1)」直接冲突；而且板块模拟必须知道全局板块边界。

# 附录 B：可直接搬进「塔洛斯经纬」的配方草案

把上面 24 条里**能落地的部分**整理成一个可实现的方案（全部 O(1)，无全局状态）：

**第 1 层：大陆掩码（决定双峰与陆地占比）**
1. m = basis(x, z, seedA) 取低频（波长约 4000~8000 格，对应大陆尺度），叠加 2~3 个八度。
2. **域扭曲**（来自 PerfectMongoose 的 twisted Perlin）：x' = x + W*basis(x,z,seedW)；z' = z + W*basis(x,z,seedW+1)，W 约 500~1500 格，让海岸线自然蜿蜒。
3. **幂重分布**（来自 Unciv 的 powSigned / Red Blob 的 redistribution）：m' = pow(clamp01(m), k)，k 约 2~3，把分布推向两端，**得到双峰**。
4. **纬度整形**（来自 Red Blob 的 reshaping + KSP 的高度曲线）：m'' = m' * latitudeWindow(z)，其中 latitudeWindow 在极区单调降到 0、中纬为 1，且**以 20,000,000 为周期**（用 cos(2πz/P) 构造，天然周期无缝）。
5. **海平面阈值**：isLand = m'' > tSea，tSea 由离线标定（目标陆地占比 25%~35%）。

**第 2 层：海底分层（大陆架 / 大陆坡 / 深海盆地）**
6. **陆类映射**（来自 KSP SelectLandClassByHeight）：把 m'' 分段映射成「深海平原（−4 km）/ 陆坡 / 陆架（−0.2 km）/ 海岸 / 平原（+0.3 km）/ 高原 / 山脉」。
7. **陆架宽度可变**（来自 KSP 的 continentalSharpnessMap）：shelfWidth = mix(0.02, 0.12, sharpNoise(x,z))，让同一世界既有宽陆架被动边缘、也有窄陆架活动边缘。
8. **陆坡坡度**由分段函数的过渡段宽度控制，形状建议用 smoothstep 或 tanh（避免折线感）。

**第 3 层：山脉 / 岛弧 / 海沟（构造特征，全部用 Cellular 噪声近似，无需模拟）**
9. cell = worleyF1(x', z')（低频 Voronoi，单元约 2000~4000 格），得到「板块 id」。
10. b = F2 - F1（**边界距离场，O(1) 可求值**），越接近 0 越靠近板块边界。
11. **岛弧 / 洋中脊**：arc = A * exp(-b/λ) * (0.5 + 0.5*cos(2π*b/P + φ(cellId)))，叠加到第 1 层掩码上。
12. **海沟**：trench = -D * exp(-b/λt)，只在海洋侧生效（m'' < tSea 时），得到沿边界的深沟。
13. **山脉**：mtn = M * pow(clamp01(basis(x,z,seedM)), 3)，仅在大陆内部生效（乘 isLand 掩码）。

**第 4 层：局部整形（无全局依赖）**
14. **热力侵蚀**（来自 World Machine 的 talus 角公式）：对 8 邻域做 1~2 次固定迭代，talus 约 0.02（世界高度归一化后）。
15. **海岸线分形维数调节**：shorelineGain 参数在高频与低频之间插值（来自 Factorio 的 cliff continuity 思路），目标 D 约 1.2~1.4。
16. **内海消除**：若 isWater 且 m'' < tDeep 判为深海（保证是「大海」）；被陆地包围的小水域（m'' 略低于 tSea 且周围全为陆）则**直接压到 tSea 以下**（局部拒绝采样，来自 Dwarf Fortress「抽干小海洋」的思路）。
17. **孤岛消除**：对掩码做形态学开运算的解析近似（m'' > tSea 且 m'' > tSea2 才算陆，tSea2 > tSea），或要求陆地必须落在 m'' 的局部极大附近，大小不足的岛自动消失。
18. **Z 周期**：所有 z 相关量用 cos/sin(2πz/P) 参与；如果直接用 3D 噪声，可采样 basis(x, R·cos(2πz/P), R·sin(2πz/P))（R 取噪声域中一个合适的半径，使纬度带的特征尺度与 X 方向匹配），这样 **Z 方向天然无缝周期**。

**性能预算建议**：每块（16×16）的求值次数约为大陆掩码 3 次 + 域扭曲 2 次 + Worley 1 次 + 山脉 2 次 + 细节 2 次，合计约 **10 次噪声采样/像元**，与「纯噪声 + 少量曲线」同级；瓶颈会出现在 Worley（Cellular）而不是 Perlin，建议用「格点哈希 + 只查 3×3 邻格」的经典实现。
