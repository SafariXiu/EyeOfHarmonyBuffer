# 01 — 板块构造模拟类大陆生成算法调研

> 调研对象：用「板块边界 + 造山 + 俯冲 + 扩张」生成大陆 / 行星地形的算法、代码与论文。
> 目标项目：Minecraft 1.7.10 无限世界类地大陆生成器（X 无限非周期、Z 周期 20,000,000 表示纬度、零预计算优先、O(1) 块级求值、Java、性能接近纯噪声）。
> 数据抓取时间：2026-09（GitHub star / 许可证 / 最后提交均以该时点为准）。
> 链接原则：本文件中每一条链接都经过实际访问或出现在检索结果中；**无法验证的一律标注「未验证」并放在第 7 节，不编造**。

## 0. 判据速览（先看这段）

| 代码性质 | 能否直接搬进本项目 |
|---|---|
| 运行时逐步迭代的物理仿真（platec / tectonics.js / pyTectonics / tergen / DF / ASPECT / CitcomS / fastscape / badlands / Landlab / goSPL） | **不能直接搬**。它们是「有限地图 + N 轮全局时间步」，需要全局缓冲，违反 O(1) 与零预计算。只能借概念与参数。 |
| 程序化（procedural）而非仿真的板块方法（Cortial 2019、Frozen Fractal、Terramax、Experilous） | **可以搬**。核心是「最近板块 + 边界类型 + 剖面核函数」，天然 O(1)。 |
| 地质学公式（Parsons & Sclater 1977、Stein & Stein 1992） | **可以搬**。纯解析式，是产生「大陆架 / 大陆坡 / 深海盆地」分层的正确工具。 |
| 声明式几何（Geodynamic World Builder、GPlates 拓扑） | **结构可搬**（feature = 多边形 + 类型 + 速度），数据源不可搬（真实地球重建数据，非程序化）。 |

**全局结论**：本领域最有价值的三个「非仿真」来源是
**(a) Frozen Fractal 的六类边界效应表**（可直接改写成代码，见 2.2）、
**(b) Terramax 的「泊松盘板块中心 + Voronoi + 域扭曲」无限世界做法**（Java / Minecraft，Apache-2.0，见 1.9）、
**(c) Parsons–Sclater 年龄-深度公式**（把「距洋中脊距离」直接换算成深海盆地深度，见 5.1）。

## 1. 板块模拟引擎 / 可运行代码

### 1.1 PlaTec（Lauri Viitanen 的原版）
- **链接**：https://sourceforge.net/projects/platec/ ；论文 https://urn.fi/URN:NBN:fi:amk-201204023993 （Theseus 记录页 https://www.theseus.fi/handle/10024/40422 ）
- **一句话原理**：从一个平坦的分形高度图出发，随机切成若干板块并让它们平动；**陆-陆碰撞处褶皱成山带，洋壳碰撞处发生俯冲，产生海岸山脉或岛链**；配合侵蚀与重叠聚合参数迭代若干轮。
- **类别**：2D 离散板块运动仿真（高度图迭代）。这是本领域**所有现代实现的祖先**（plate-tectonics / pyplatec / worldengine / terrainbuilder 都是它的下游）。
- **输出范围**：有限地图（固定 width × height）。
- **实时性**：**需离线全局模拟**。API 形态就是 create(...) → while(is_finished()==0) step() → get_heightmap()；必须把整张图放内存里迭代。
- **双峰高程**：**是（结构性）**。模型显式区分大陆地壳与洋地壳，并有 sea_level 参数；俯冲/褶皱把两类地壳推向两个高度层。但公开文档没有直方图证据，属结构推断，**需自行跑一遍验证**。
- **是否处理地貌单元**：**大陆架/坡**：间接（有 sea_level 阈值，但无显式陆架剖面）。**岛弧**：有（源项目描述明确写 subduction ... resulting in coastal mountain ranges or island chains）。**海沟**：有俯冲语义，未确认是否有显式海沟凹陷。**洋中脊**：未见文档说明。**大陆坡**：未见。
- **内海与孤岛**：**不处理**。没有任何连通性后处理；小岛与内海会随机出现。
- **语言/依赖/许可证/star**：C++ / OpenGL 示例、CMake；原项目 **LGPL-2.0**（SourceForge 页面标注 GNU Library or Lesser General Public License version 2.0）；2015-08-03 最后更新；无 star 概念（SourceForge 1 条评价）。作者是 Metropolia 应用科学大学的 Lauri Viitanen，论文 *Physically Based Terrain Generation: Procedural Heightmap Generation Using Plate Tectonics*（2012）。
- **对本项目的可借鉴点**：
  1. **参数集就是最好的需求清单**：(seed, width, height, sea_level, erosion_period, folding_ratio, aggr_overlap_abs, aggr_overlap_rel, cycle_count, num_plates)。其中 sea_level 直接就是我们的「陆地占比标定旋钮」；folding_ratio（褶皱比）是「一次碰撞把多少重叠量转成高度」的系数 —— 我们的边界造山核函数应当保留一个等价的 foldK；aggr_overlap_abs/rel 是「两点被判定为同一板块/已聚合」的阈值 —— 我们可以把它改造成 O(1) 的「边界影响半径」。
  2. **「重叠 = 俯冲，间隙 = 裂谷」这一对判据**是整类算法的灵魂：任意两个相邻板块的相对位移投影到边界法线上，**正值（重叠）→ 挤压造山/俯冲，负值（间隙）→ 张裂/洋中脊**。这个判据本身与时间步无关，可以在 (x,z) 处**直接静态求值**，是本项目最该抄的一条。
  3. **不能搬的部分**：整图迭代、多轮 erosion_period、全局 get_heightmap()。
  4. 论文（URN:NBN:fi:amk-201204023993）里给出了模型的完整软件结构与「传统分形 vs 板块构造」的对比，是写设计文档时最好的引用源。（论文 PDF 正文我未能取到全文，仅取到摘要与元数据；引用前请自行下载核对。）

### 1.2 Mindwerks/plate-tectonics（platec 的活跃 C++ 分支）
- **链接**：https://github.com/Mindwerks/plate-tectonics
- **一句话原理**：与 1.1 同一模型，重构成干净的 C++ 库（libPlateTectonics.a），带 Python 绑定与 CMake/GoogleTest。
- **类别**：库化的板块运动仿真。
- **输出范围**：有限地图。
- **实时性**：需离线全局模拟（循环调用 platec.is_finished / platec.step）。
- **双峰高程**：同 1.1，结构性双峰，未验证直方图。
- **地貌单元**：同 1.1（岛弧有、海沟/洋中脊不明）。
- **内海与孤岛**：不处理。
- **语言/依赖/许可证/star**：C++17 + CMake + libpng（仅示例）；Python 绑定需 Python ≥ 3.9；**LGPL-3.0**（LICENSE 文件为 GNU LGPL v3，已实际读取）；**★95**；最后提交 2025-11-23。Haskell 绑定 hplatec：https://github.com/ftomassetti/hplatec
- **对本项目的可借鉴点**：
  1. **这是全领域唯一「代码质量够读、模型够正统」的实现**。建议把 platec 的核心结构（plate 对象、segment 边界段、movement/aggregation 三步）作为我们 Java 版的命名与模块划分参照。
  2. **LGPL-3.0 意味着「动态链接可以，静态抄源码进闭源模组不行」**。对 MC 1.7.10 闭源/半闭源模组，**只能读思路、不能复制代码**，这一点必须写进项目合规备注。
  3. cycle_count 参数说明作者发现「一次遍历不够，需要多轮」；我们的替代方案是用**多尺度核函数叠加**（同一板块边界在 2~3 个尺度上各算一次贡献）来等价替代多轮迭代 —— 这正好也是 O(1)。

### 1.4 Mindwerks/worldengine
- **链接**：https://github.com/Mindwerks/worldengine ；PyPI https://pypi.org/project/worldengine/ ；镜像分支 https://github.com/Charles-Zhang-Fork/worldengine
- **一句话原理**：基于 platec 的完整世界生成器 —— 板块模拟 → 侵蚀 → 雨影（rain shadow）→ 温度/降水 → 生物群系，再输出到 PNG/WorldPainter/Minecraft 地图格式。
- **类别**：端到端世界生成管线（板块在最上游）。
- **输出范围**：有限地图（可指定宽高，如 512×512 到 2048×2048）。
- **实时性**：需离线全局模拟 + 多遍后处理。
- **双峰高程**：继承 platec，结构性双峰；worldengine 的文档里有丰富的参数（plates、sea level、erosion）可用于标定。
- **地貌单元**：随 platec；额外提供**河流/侵蚀/雨影**（这对「海岸线分形维数」有直接影响 —— 侵蚀会把海岸线变得更碎，D 会上升）。
- **内海与孤岛**：**有内海/湖泊概念（watermap + 河流连通）**，但那是「水文」层面而非「构造」层面；不保证内海数量为 0。
- **语言/依赖/许可证/star**：Python（含 C 扩展依赖 platec/pyplatec）；**MIT**（GitHub API 识别）；**★1070**；最后提交 2026-08-27，**仍然活跃**。
- **对本项目的可借鉴点**：
  1. **它给出了「地块 → 生物群系」的完整中间量列表**，正好是我们 1.7.10 模组后面要接 Biome 的那一层：elevation → 温度（纬度 + 高度递减率）→ 降水（含雨影）→ 生物群系表。Z 轴周期 20e7 已知表示纬度，**温度可以直接是 Z 的解析函数**，雨影则可以用「沿主导风向的抬升积分」的近似核函数做 O(1) 版本。
  2. **它的 Minecraft 导出器说明「板块生成的高度图如何映射到 MC 高度」**，可作为我们 Y 轴缩放（大陆台地 +0.3 km / 深海盆地 −4 km 对应 MC 的哪一段）的参考。
  3. **MIT 许可证**：这是**本清单里少数可以真正抄代码进闭源模组的**（MIT 只要求保留版权声明）。Python→Java 需要移植，但它的算法步骤是伪代码级的，值得逐函数对照。
  4. 反面教材：worldengine 用「全局 watermap + 河流流向」来消除内海，这在我们的无限 X 轴上**做不到**；所以内海问题必须另找方案（见第 8 节的「构造式保证单连通」）。

### 1.5 seanth/PyTectonics（+ 原始 SourceForge pyTectonics）
- **链接**：https://github.com/seanth/PyTectonics ；原项目与文档 https://sourceforge.net/p/pytectonics/wiki/Home/ ；模型总览 https://sourceforge.net/p/pytectonics/wiki/Model%20Overview/
- **一句话原理**：把地壳表示成球面上**等距采样点**（Fibonacci 网格），点按最近中心分属各板块；每板块有**欧拉极 + 速度**；点随时间步移动 —— **重叠 = 俯冲（密度大者下沉），间隙 = 裂谷（生成新洋壳点）**；被俯冲的点继续迁移一段**固定距离**后才销毁，**这段距离直接决定山脉宽度**；高度主要来自**均衡补偿（isostasy）**：每点带厚度与密度，重叠时合并厚度/密度算出高程。
- **类别**：基于点的板块运动仿真（3D 球面，2D 类比可直接用）。
- **输出范围**：有限/球面（Fibonacci 网格点数固定）。
- **实时性**：需离线全局模拟（显式时间步 + 点在内存中移动）。
- **双峰高程**：**是，而且是本清单里唯一「机制上讲清楚」的双峰**。作者原话：*"Isostasy is perhaps the most important, since it's responsible for most mountains. Each point tracks thickness and density, and when points overlap their thicknesses/densities are considered together to determine elevation."* —— 陆壳厚而轻、洋壳薄而重 → 天然两个峰。**这正是我们实现双峰高程该抄的物理机制。**
- **地貌单元**：**岛弧**：有专门子模型（Island Arc Formation）：俯冲点被销毁时把一部分地壳加到与其重叠的点上。**海沟**：有（俯冲语义）。**洋中脊**：有（裂谷处生成新洋壳点）。**大陆架/坡**：未显式建模（但有 isostasy 分层，可自然产生被动大陆边缘）。
- **内海与孤岛**：**不处理**（模型是几何/物理的，没有拓扑连通性检查）。文档列出了 Rifting / Collision / Plate Motion / Grid Systems / Isostacy / Orogeny / Island Arc Formation 等子模型（子页面 URL 我未能验证，故不给链接）。
- **语言/依赖/许可证/star**：Python（原版 Python 2 时代，seanth 版为 Python 3 移植）；GitHub 版 **★4，许可证 NOASSERTION（需自行核对）**，最后提交 2018-08-29；SourceForge 原项目状态 Alpha，作者 Carl Davidson（davidson1）。
- **对本项目的可借鉴点**（本条的可借鉴度是全清单最高的之一）：
  1. **「俯冲板片存活距离 = 造山带宽度」这个映射必须抄。** 我们的 O(1) 版本：设 d = 到板块边界的距离、vRel = 相对速度在边界法线上的分量、L = 该边界的特征俯冲带宽度（可由 seed 哈希给出）。当 d < L 时按 w = 1 - d/L（或 tent 剖面）叠加地壳厚度。**L 就是控制山带宽度的旋钮**，改 L 就能改山带的「粗细」。
  2. **「厚度 + 密度 → 高度」的均衡公式要抄成闭式**。Airy 均衡：h = ((ρm - ρc)/ρm) × T_crust（T 为地壳厚度）。给定 ρc_陆 ≈ 2.7、ρc_洋 ≈ 2.9、ρm ≈ 3.3（g/cm³），它就自动给出：陆壳 T=35 km → 高约 +0.3~0.5 km；洋壳 T=7 km → 低约 −4 km。**双峰高程直接由这一个公式 + 两种地壳类型产生，不需要任何直方图塑形。**
  3. **「间隙 = 裂谷 → 生成新洋壳」→ 洋中脊。** 在 O(1) 版里：对离散边界，距离场用 1 - d/L_ridge 抬升洋底（洋中脊是洋盆里唯一的高地）。
  4. **用 Fibonacci/等距点 vs 用 Voronoi 的取舍**：作者用点阵是因为要在球面上等距；我们只需在 (x,z) 平面，**用抖动网格（jittered grid）+ 邻域 3×3 查最近中心即可 O(1)**，不需要 Fibonacci。但作者「点阵会随时间变乱，所以每个板块用自己的网格存点」的教训提醒我们：**板块中心必须由 seed 确定性生成，绝不能用「随时间演化的点集」**。
  5. SourceForge 页面上还有 Rifting / Collision / Isostacy / Orogeny / Island Arc Formation 等子页面（我未能逐个验证 URL，故不列链接），值得手动去 wiki 里翻一遍。

### 1.7 weigert/SimpleTectonics（Clustered Convection）
- **链接**：https://github.com/weigert/SimpleTectonics ；配套博客（作者 Nick McDonald）https://nickmcd.me/2020/12/03/clustered-convection-for-simulating-plate-tectonics/
- **一句话原理**：**「聚类对流」**——用泊松盘采样撒出「对流胞质心」，质心之间相互靠近 → 判定为俯冲并生成「热量」，热量经**扩散（diffusion）**与**沙堆级联（sand-pile cascading）**转成高度；整个模拟跑在 GPU 片段着色器上（Voronoi / subduction / diffusion / cascading 四个 shader）。
- **类别**：基于聚类的 GPU 板块仿真（不是经典板块刚体运动，而是「对流胞」隐喻）。
- **输出范围**：有限（一张纹理）。
- **实时性**：**运行时可在 GPU 上逐帧迭代**，但仍需要全局纹理缓冲（ping-pong FBO），属于「需要全局缓存」。
- **双峰高程**：**否（单峰为主）**。它是「热量扩散 + 级联」产生地形，没有两类地壳的均衡机制，出来的更像是「有山有谷的连续地形」，不天然具备大陆台地 / 深海盆地两个峰。
- **地貌单元**：**洋中脊/裂谷**：有（质心远离处）。**俯冲/海沟**：有（subduction shader 显式做「碰撞质心 → 热图」）。**岛弧**：未明确。**大陆架/坡**：无。
- **内海与孤岛**：不处理。
- **语言/依赖/许可证/star**：C++17 + OpenGL（依赖 TinyEngine 与 libnoise）；**README 声明 MIT，但仓库没有 LICENSE 文件，GitHub API 识别为 NONE —— 许可状态不一致，使用前必须向作者确认**；**★24**；最后提交 2022-07-24（停更）。
- **对本项目的可借鉴点**：
  1. **「俯冲 = 两个质心的碰撞 → 热量标量场」这个编码方式，恰好是 O(1) 友好的**：对任意点 p，只需找最近的两个质心 c1、c2，判断它们是否在互相靠近（相对速度与中心连线点积为负），是则把 heat = 1 - d/L 叠上去。**不需要任何全局迭代。**
  2. **「沙堆级联（cascading）」是替代全局侵蚀的廉价方案**：它是一个纯本地的「超过阈值就向邻居倾倒」的迭代，收敛快、可限定在局部窗口内跑几步 —— 这是我们**唯一有可能在块生成时本地跑几轮**的后处理（比如 16×16 块 + 1 圈 halo，跑 3~5 轮），用来软化极值、修掉单格尖峰。建议列入实验计划。
  3. **扩散（diffusion）同理**：局部热扩散可以 O(1) 地近似为「多尺度高斯核叠加」，不需要真的迭代。
  4. **它证明了「把板块类模型完全放在 GPU 纹理里」是可行的**；但对我们（MC 1.7.10，CPU 端 chunk generator）而言，GPU 路线不可用，只借数学。

### 1.8 Hafting/tergen（Freeciv 地形生成器）
- **链接**：https://github.com/Hafting/tergen
- **一句话原理**：给 Freeciv 用的**有限地图**生成器：撒若干板块中心并随机指定运动方向 → 每格归给最近中心（**凸多边形板块**）→ 多轮「分数板块移动」（每轮只有少数板块动）→ 板块分离处出现**裂谷**、碰撞处**累加高度形成山带**；每轮插入**天气模拟**（蒸发 → 按盛行风移动云 → 降雨 → 雨影）与**侵蚀**（河流下切、海岸侵蚀、沉积）。
- **类别**：端到端的有限地图世界生成（板块 + 气候 + 侵蚀）。
- **输出范围**：有限地图（支持方格/六角、iso/非 iso、no-wrap / wrap-x / wrap-xy）。
- **实时性**：**需离线全局模拟**（多轮板块移动 + 每轮天气 + 侵蚀）。
- **双峰高程**：**否**。README 只描述「山带、裂谷、浅海条带、岛屿」，没有两类地壳/均衡机制 —— 是「单峰 + 若干隆起」。
- **地貌单元**：**岛弧/岛链**：有，README 明确观察到 *"When a mountain range runs into the sea, it may continue as a land stripe, then a series of islands, and finally a long stripe of shallow water."* —— 这正是「大陆架 → 岛链 → 浅海」的理想序列。**洋中脊/裂谷**：有。**海沟**：未见。**大陆架/大陆坡**：有（a long stripe of shallow water）。
- **内海与孤岛**：**部分处理**。README 观察到「北岸被山带挡住时，会形成复杂的湖泊-河流系统，且每个湖都有河通向海」—— 它用**水文连通性**处理了内海，但代价是全局河流模拟。
- **语言/依赖/许可证/star**：C（输出 Freeciv scenario 存档）；**GPL-3.0**（GitHub API 识别）；**★3**；最后提交 2026-06-19（仍在动）。依赖 Freeciv 的存档格式，**不能作为库使用**。
- **对本项目的可借鉴点**：
  1. **README 里那张「地貌单元目录」是极好的验收清单**：山带跟随板块边缘（不限于网格方向）、山带入海 → 陆条 → 岛链 → 浅海条带、雨影、峡湾、河谷、湖泊-河流系统。**建议直接抄进我们的测试用例**：生成一张测试图，逐条肉眼验证。
  2. **「每轮只有少数板块移动」这个 trick 值得改造成静态版本**：等价于给每个板块一个「活跃度」权重（由 seed 哈希），活跃度高的板块边界造山强、活跃度低的边界造山弱 —— 这样大陆内部的边界不会到处冒山，更像地球（不是所有板块边界都在造山）。
  3. **海岸侵蚀 + 沉积是「海岸线分形维数 D」的天然调节器**：README 指出海岸也会被风浪侵蚀，会生成峡湾 → 提高 D。我们的目标 D≈1.2~1.4 偏低（地球约 1.2~1.25），**说明我们要的是「被侵蚀过但不碎」的海岸线**；tergen 的多轮侵蚀正好会过头，反向印证「少量、局部、O(1) 的噪声放大」比「多轮侵蚀」更合适。
  4. **GPL-3.0：只读文档，不能抄代码。**

### 1.9 verycareful/Terramax（Minecraft 模组的板块地形）★本清单对本项目最贴近的一个★

- **输出范围**：**无限**（Minecraft 世界，运行时按区块求值）。
- **实时性**：**运行时求值（chunk generator）**。README 明确警告 *"a chunk generator that has to be careful about what it evaluates"* —— 说明它就是 O(1) 路线。
- **双峰高程**：**是（设计目标）**。README 写「板块类型 + 高程」驱动，并有 continental proportions and real alpine relief。板块被分为陆/洋类型，对应不同的基准高度。
- **地貌单元**：**汇聚边界 → 山脉（alpine relief）**；**离散边界 → 裂谷（rifts）**；**转换边界 → 平坦剪切**；**大陆架/坡/海沟/洋中脊**：README 未逐条列出，只列了 convergent/divergent/transform 三类边界效应，**未提及海沟与岛弧的显式建模**。
- **内海与孤岛**：README 未提及任何连通性处理。**这是它相对我们需求的主要缺口。**
- **语言/依赖/许可证/star**：Java（JDK 25，Gradle，Mojang mappings —— 注意：**这是新版 MC，不是 1.7.10**）；**Apache-2.0**（README 明确 + LICENSE.txt）；**★1**（2026-09 时点，早期项目，README 自述 Status: early development… Nothing here is playable yet）；最后提交 2026-09-12。
- **对本项目的可借鉴点**（几乎每一条都能直接用）：
  1. **「泊松盘采样板块中心 + Voronoi 归属」是无限世界的正解**。我们没有全局内存，所以不能真的跑泊松盘采样 —— **替代方案：用「抖动网格（jittered grid）+ 邻域 3×3 搜索最近中心」**，等价于泊松盘且 O(1)。Terramax 的板块中心间距 **≈100,000 方块**是极有价值的尺度参考：我们的 Z 周期是 20,000,000，若按同样密度，**一圈纬度上大约 200 个板块带**；X 方向同理。这个数字直接决定我们的「板块中心网格单元大小」。
  2. **「domain warping 在每次板块查询前施加」是整份清单里最高性价比的一招**。原话：*"Domain warping is applied before every plate lookup so the result reads as coastline rather than as polygons."* 实现：p' = p + A × (noise1(p), noise2(p))，用 p' 去做 Voronoi 查询。**这是一个 O(1) 的坐标扰动，却能把「Voronoi 多边形」直接变成「自然海岸线」**，并且天然提高海岸线分形维数 —— 正是我们 D≈1.2~1.4 目标的核心旋钮。**强烈建议第一版就实现这个。**
  3. **「三模块切分 core / sim / mod」**（core 不依赖 Minecraft，可独立跑模拟器调参）。原话：*"core will hold the terrain mathematics with no Minecraft dependency, so a standalone simulator can render and tune it without launching the game. At 100,000-block plate spacing, in-game iteration is impractical: you would fly 50,000 blocks to reach a boundary."* —— **我们必须照做**：一个纯 Java（无 MC 依赖）的 tectonic-core 模块 + 一个用于出测试图的 main，否则每次调参都要开游戏跑 5 万格。
  4. **「生物群系不能控制自己的地形形状」这个观察**：*"a biome cannot control its own terrain shape in Minecraft: landforms like fjords, highlands and foothills are terrain features, not climate niches"* —— 对应到 1.7.10，**我们的地形必须由 chunk generator 直接产生，不能指望 BiomeDecorator 或生物群系高度变体去做峡湾/高地**。这对 1.7.10 的 biome 高度系统是个重要提醒。
  5. **Terramax 的 Y 轴尺度**：y = −256 到 1792，板块间距 100,000 方块。我们的 1.7.10 只有 y = 0~255，**必须做尺度映射**：把「真实地球的高程范围（−11 km 到 +8.8 km）」压缩到 MC 的可用高度带，并决定「海平面放在 y=63 还是更低」。这是我们必须自己决策、Terramax 不能直接给答案的地方。
  6. **注意：Terramax 是新版 MC，不是 1.7.10。** 它的 API 用法（world type、chunk generator）**完全不能参考**；能借鉴的只有数学与工程结构。

  2. **「板块整体平铺全图，用 offset 决定参与碰撞的部分」**是一个巧妙的 trick：把「有限尺寸的板块」变成「无限平铺场 + 平移」，这样**每个板块自身都是一张无限可求值的过程纹理**，碰撞只是两张无限纹理的相对平移。**这几乎就是我们要的答案** —— 把「板块」定义成一个 (x,z)→属性 的纯函数，板块运动就是给这个函数的坐标加一个偏移。
  3. **「相向运动 → 俯冲带 → 一串岛」是它默认就能出的效果**，说明**岛弧不需要专门的岛弧模块，只要在俯冲带上按「离边界的距离」做周期性调制即可**（岛屿 = 山带剖面上的周期性峰值）。这是一个很省事、很 O(1) 的岛弧做法：islandMask = smoothstep(...) × (0.5 + 0.5 × sin(2π × 沿边界距离 / λ))。

### 2.2 Frozen Fractal —「Around The World」系列（Thomas ten Cate）★★本清单最可直接落地的一份★★
- **链接**：Part 1 Continents https://frozenfractal.com/blog/2023/11/2/around-the-world-1-continents/ ；**Part 2 Plate tectonics** https://frozenfractal.com/blog/2023/11/13/around-the-world-2-plate-tectonics/ ；系列页 https://frozenfractal.com/blog/
- **一句话原理**：为航海探索游戏 *Around The World* 生成类地地图。**先**用 Voronoi 单元做成大陆形状并设定基础高度（曲线 + simplex 噪声）；**再**把「板块」叠上去：板块由大陆 Voronoi 区域**向外生长**得到（每个大陆有一个「偏好生长方向」，不是均匀外扩 —— 因为真实板块常常只有一侧是洋壳）；板块数多于大陆数，所以随机把板块一分为二；每板块有速度（由洋中脊推力 + 边界相互作用驱动）；然后**按「两侧地壳类型 × 汇聚/离散」查表施加地形效应**。
- **类别**：程序化板块地形（**不是仿真** —— 边界效应是「叠加一条带噪声的曲线」，而不是迭代物理）。
- **输出范围**：有限（游戏地图），但**方法本身是逐点距离函数，可无限化**。
- **实时性**：**接近 O(1)**。原文用的是「在边界处叠加一条加了噪声的曲线」；对任意点只需查最近边界 + 边界类型 + 距离即可。**这是全清单与我方约束最匹配的方案。**
- **双峰高程**：**是，而且是显式设计**。原文明确指出：*"There are two types of crust: continental and oceanic. Continental crust is thicker and lighter, causing it to float higher on the mantle and being pushed above water level; oceanic crust is thinner and denser, causing it to lie lower on the mantle and form the ocean floor."* 并批评了「把板块分成大陆板块与海洋板块」的常见错误做法（*"Most plates contain both continental and oceanic crust"*）。
- **地貌单元**：**六类边界效应全部列全了（这份表就是代码规格）**：

| 边界类型 | 效应（原文） |
|---|---|
| 陆-陆 汇聚 | 山脉（crumple up，喜马拉雅式山带）**+ 高原**（其中一块被另一块推上去形成 plateau） |
| 陆-陆 离散 | **裂谷**（rift valley），边界周围的地被降低 |
| 洋-洋 离散 | **洋中脊**（mid-oceanic ridge），熔岩从缝隙流出堆成火山脊 |
| 洋-洋 汇聚 | **岛弧**（island arc），一块俯冲到另一块之下，另一块被推高过海平面 |
| 陆-洋 汇聚 | **海沟（洋侧）+ 火山弧（陆侧）**：*"This causes a deep trench on the oceanic side, and an arc of volcanoes on the continental side."* |
| 陆-洋 离散 | 作者原话：「我也不知道，大概洋侧有条脊」 |
| 转换边界（走滑） | **刻意不做**，理由：*"pure sliding never happens: if you look closely enough, it's always sections of the boundary either converging or diverging"* |

  **另有关键实现细节**：山带「太光滑」的解法是 *"always: more simplex noise!"* —— **噪声同时作用于山带的宽度（distance/width）与高度**。

- **内海与孤岛**：**未讨论**（这是它的缺口，也是我们需要补的地方）。
- **语言/依赖/许可证/star**：JavaScript（游戏 *Around The World* 的实现，博客为该游戏开发日志）；**未开源、无许可证、无 star**（作者 Thomas ten Cate / Frozen Fractal）。
- **对本项目的可借鉴点**（**建议直接按这一节写第一版代码**）：
  1. **把上表原封不动抄成 6 个枚举 + 一个 switch**。这是整个调研中**唯一一份「现象 → 公式」都齐了、可以直接写出代码的边界效应表**。
  2. **「板块 = 从大陆 Voronoi 区域向外生长，且每个大陆有一个偏好生长方向」**：这条直接解决我们的「大陆架自然延伸、被动大陆边缘」问题。O(1) 实现：plateId(p) = argmin_i ( |p - c_i| / w_i(θ_i) )，其中 w_i 是由该板块的「偏好方向」给出的各向异性权重（一个椭圆距离即可）。
  3. **「板块数 > 大陆数，随机把板块一分为二」**：保证了大陆内部也有板块边界 → 才会出现「大陆内部的裂谷/山带」（东非大裂谷、乌拉尔山）。**这一条是让大陆看起来「有历史」而不是「一块均匀的饼」的关键**。O(1) 实现：板块 id 由网格哈希给出，再叠一层低频「子板块」噪声做二分裂。
  4. **「山带宽度与高度都加 simplex 噪声」** —— 原文特别强调这是让山带不假的关键。**我们的核函数应该是 A × noiseModulatedProfile(d / L(noise))，而不是固定的 tent 剖面。**
  5. **「不做转换边界」这个判断可以照抄**，能省掉一个分支（我们只需「汇聚 / 离散」两个方向 + 地壳类型组合 = 4~6 类）。
  6. **它的短板（内海/孤岛）正是我们的重点指标**，所以这一节能给我们 80% 的地形，但**内海数 = 0 这一条必须另外解决**（见第 8 节）。

### 2.3 kenny.wtf「World-Synth」
- **链接**：https://kenny.wtf/posts/world-synth-tectonic-plates/
- **一句话原理**：受 Experilous 启发的浏览器端「全建模地球尺度世界」项目。核心论点是**混合架构**：全局噪声快但**没有区域特征之间的关系**（做不出「两个点碰撞」这种离散事件），所以必须**离线生成一个「区域特征」数据集**（板块碰撞、大陆细节等），实时再把每个地形特征当成一个**距离函数（distance function）**查询；用空间哈希/空间网格只查询附近的特征。
- **类别**：混合架构（离线特征集 + 在线距离函数求值）。
- **输出范围**：全球（有限）。
- **实时性**：**需离线全局模拟生成特征集 + 运行时 O(1) 空间哈希查询**。原文明确：*"'Offline/Online' generation"*、*"we'll generate that all upfront, which will take some seconds, and then after in real-time, during terrain chunk generation we'll query our current position against that dataset"*。作者自评这是 naïve 做法。
- **双峰高程**：未讨论。
- **地貌单元**：未逐条讨论（目标是 plate collisions 驱动的大尺度特征）。
- **内海与孤岛**：未讨论。
- **语言/依赖/许可证/star**：TypeScript / WebGL（Astro 站点 + 自研 Hello Worlds 引擎）；**博客文章，无仓库许可证**；作者 Kenneth Pirman；文中给出性能目标：**生成大尺度模型数据 ~10 秒，之后每个地形 chunk 流式载入 < 100 ms**（当时实测 13 秒 / 120 ms）。
- **对本项目的可借鉴点**：
  1. **它精确地诊断了「为什么纯噪声不够」**（原文）：*"noise does not give us relationships between regional features. For example, we could know what's above water or under it, but we would not be able to create discrete formations where you would expect plates to collide or pull apart, because we need to qualify the relationship between two points. It would be difficult to generate rivers and mountain chains with this method."* —— **这句话是本项目立论的直接引用来源**：我们要的就是「两点之间的关系」，而板块模型正是用「相对速度投影到边界法线」来表达这种关系。
  2. **「每个地形特征 = 一个距离函数」这个抽象必须抄**：我们的每个板块边界就是一个距离函数 f_i(p) = profile(distance(p, boundary_i), type_i)，总高程是它们的叠加。**距离函数天然可并行、可增删、可 O(1) 局部求值。**
  3. **「只查询附近的特征（空间哈希）」**：我们的版本更简单 —— 因为板块中心是程序化生成的，**用抖动网格直接定位 3×3 邻域即可，不需要真的建哈希表**（这比 kenny 的方案更省内存）。
  4. **它承认「离线生成几秒 + 在线查询」在浏览器可行**，但对我们来说，**「离线几秒」可以接受（用户已放宽），然而「离线几百 MB 特征集」不能接受**。所以我们的折中是：**离线只产出「常数」，在线仍用解析函数**。

### 3.1 Procedural Tectonic Planets（Cortial, Peytavie, Galin, Guérin, CGF 2019）
- **链接**：DOI https://doi.org/10.1111/cgf.13614 ；Eurographics 数字图书馆记录页 https://diglib.eg.org/items/d7b74043-dcb2-4b18-b128-5ec43b73548d （摘要页已实际读取，DOI 已经 Crossref 核对）
- **一句话原理**（摘要原文要点）：*"Instead of relying on computationally demanding physically-based simulations, we capture the fundamental phenomena into a **procedural method** that faithfully reproduces large-scale planetary features generated by the movement and collision of the tectonic plates. We approximate complex phenomena such as **plate subduction or collisions to deform the lithosphere, including the continental and oceanic crusts**. The user can control the movement of the plates, which dynamically evolve and generate a variety of landforms such as **continents, oceanic ridges, large scale mountain ranges or island arcs**. Finally, we amplify the large-scale planet model with either procedurally-defined or real-world elevation data to synthesize coherent detailed reliefs."*
- **类别**：学术程序化（非仿真）行星构造建模。
- **输出范围**：整颗行星（但因为是 procedural，**理论上可无限化**）。
- **实时性**：**交互式（运行时求值）**。摘要明确 *"allows the user to control the evolution of an entire planet interactively, and to trigger specific events such as catastrophic plate rifting"* —— **不是离线仿真，是程序化参数化模型。这是本清单里与「零预计算」最契合的学术工作。**
- **双峰高程**：**是（结构性）**。摘要明确提到同时变形 continental and oceanic crusts —— 两类地壳 → 双峰。
- **地貌单元**：**洋中脊**：有（oceanic ridges）。**大尺度山带**：有。**岛弧**：有（island arcs）。**大陆架/坡**：间接（continental vs oceanic crust 的过渡）。**海沟**：有（plate subduction）。
- **内海与孤岛**：摘要未提及。
- **语言/依赖/许可证/star**：论文（CGF 38(2), 2019, Eurographics）；**无公开代码**；作者单位含里昂大学 / 斯特拉斯堡（hdworlds 组，https://hdworlds.unistra.fr/ ）。
- **对本项目的可借鉴点**：
  1. **这是「官方认证」的「不用仿真也能做出板块地形」的学术结论** —— 摘要第一句就是 *"Instead of relying on computationally demanding physically-based simulations"*。**如果我们被质疑「不做仿真怎么可能有板块地形」，这篇文章就是标准引用。**
  2. **它列出了必须复现的 5 个现象：continents / oceanic ridges / large scale mountain ranges / island arcs / subduction** —— **建议直接作为我们的功能需求清单**（与我们的目标「大陆架、大陆坡、深海盆地、山脉、岛弧」高度重合，只差「大陆坡」与「深海盆地」，而这两个正好是第 5 节的年龄-深度公式负责）。
  3. **「先程序化大尺度行星，再用数据放大细节」这个两阶段架构要抄**：第一阶段 = 板块模型给出低频高程（正是我们的 O(1) 板块函数）；第二阶段 = 用 FBM / 侵蚀噪声放大（我们的细节层）。**注意第二阶段必须也是 O(1) 的**，所以「真实高程数据」那一半不可用，只能用 procedural 那一半。
  4. **「用户可以触发 catastrophic plate rifting 这类事件」是很好的产品灵感**：在无限世界里，这类事件可以做成低频的「构造事件场」（比如每 500,000 格出现一次超级裂谷），是一个便宜的地标机制。

### 3.2 Large Scale Terrain Generation from Tectonic Uplift and Fluvial Erosion（Cordonnier, Braun, Cani, Beneš, Galin, Guérin, Peytavie, CGF 2016）
- **链接**：DOI https://doi.org/10.1111/cgf.12820 （已 Crossref 核对） ；HAL 记录 https://hal.sorbonne-universite.fr/LJK_GI/hal-01262376v1
- **一句话原理**：把**构造抬升**与**河流侵蚀（stream power law）**耦合起来生成大尺度地形；抬升项是可控的参数化场，侵蚀项用 stream power 方程求解，从而得到「有流域结构、有分水岭」的山脉。
- **类别**：学术地形生成（抬升 + 侵蚀耦合）。
- **输出范围**：大尺度区域（有限）。
- **实时性**：**需离线全局模拟**（河流流向与汇水面积 A 是全局量）。
- **双峰高程**：**否**。它生成的是「有流域的山地」，不涉及两类地壳，因此是单峰的侵蚀地貌。
- **地貌单元**：**山脉**：有（主打）。**大陆架/坡/岛弧/海沟/洋中脊**：无。
- **内海与孤岛**：**部分**（河流系统会自然产生湖泊/内流盆地，但这是侵蚀的副产物，不受控）。
- **语言/依赖/许可证/star**：论文 + 作者后续开源实现（见 4.5 fastscape，同一学术脉络：Braun & Willett 的 stream power 求解器）。
- **对本项目的可借鉴点**：
  1. **stream power 公式本身值得记住**：dh/dt = U − K × A^m × S^n（U 抬升、A 汇水面积、S 坡度、m/n 经验指数）。**对我们是「不能算，但必须理解」**：正因为 A 是全局量，我们才不能做真正的河流侵蚀 —— **这解释了为什么我们的地形里不应该有「真正的流域结构」，而应该用「与抬升场相关的伪河道噪声」来假装**。
  2. **「抬升场」这个概念可以搬**：把板块边界造山写成 U(x,z) 一个解析场，形式上与本文一致，只是我们不解侵蚀方程。
  3. **它给出了「构造」与「侵蚀」的正确分工**：构造负责**大尺度、有方向性、沿边界成带**的特征；侵蚀负责**小尺度、各向同性、分形**的特征。**我们的层叠顺序应该照此**：低频板块（构造）→ 中频 FBM（侵蚀伪影）→ 高频细节。

### 3.3 Terrain Amplification with Implicit 3D Features（Paris, Galin, Peytavie, Guérin, ACM TOG 2019）
- **链接**：DOI https://doi.org/10.1145/3342765 （已 Crossref 核对） ；全文 https://dl.acm.org/doi/fullHtml/10.1145/3342765
- **一句话原理**：把粗糙的低分辨率地形**放大（amplify）**到高分辨率细节，方法是提取地形的**隐式 3D 特征**（例如「这是山脊」「这是沟谷」），再据此合成细节，使得细节与宏观地貌一致。
- **类别**：地形细节放大（后处理）。
- **输出范围**：任意（对已有高度场做放大）。
- **实时性**：**运行时 O(1) 可求值**（放大是逐点的局部算子）。
- **双峰高程**：不适用（不改变宏观分布）。
- **地貌单元**：不适用（只加细节）。
- **内海与孤岛**：不适用（但它的「山脊/沟谷」特征提取对**海岸线的分形细化**有直接价值）。
- **语言/依赖/许可证/star**：论文（TOG 38(6)）；同一组（hdworlds）有大量相关工作。
- **对本项目的可借鉴点**：
  1. **这是我们「板块低频场 → 16×16 块级细节」的正确工具**。它的核心思想（**先判断局部是脊还是谷，再沿该方向叠加噪声**）可以简化成：h = H_plate(x,z) + amp(H_plate) × fbm(x,z，频段随 H 变化) —— **细节幅度是宏观高度的函数**（山上细节大、海底细节小），这一条能显著提升观感且零额外成本。
  2. **「沿脊线方向的各向异性噪声」比各向同性 FBM 更像山**：可以用 H 的梯度方向来做各向异性拉伸（例如把噪声坐标沿等高线方向压缩 4 倍）。**这是一个 10 行代码的改动，观感提升很大。**
  3. 综述性质的配套阅读：**A Review of Digital Terrain Modeling**（Galin 等, CGF 2019, DOI https://doi.org/10.1111/cgf.13657 ，已 Crossref 核对）—— **写相关工作时引用这一篇即可覆盖整个领域**。

### 3.4 博士论文：Layered Models for Large Scale Time-Evolving Landscapes（Cordonnier）
- **链接**：HAL https://hal.univ-grenoble-alpes.fr/tel-01971947v2 （记录页已实际访问）
- **一句话原理**：把大尺度、随时间演化的地形组织成**分层模型**（构造层 / 侵蚀层 / 细节层），每层有不同的时间尺度与空间尺度。
- **类别**：博士论文（综述 + 方法）。
- **输出范围**：大尺度区域。
- **实时性**：混合（论文中不同章节方法不同）。
- **双峰高程 / 地貌单元 / 内海与孤岛**：需读全文确认（**我未取到全文，仅验证了 HAL 记录存在**）。
- **语言/依赖/许可证/star**：学位论文，HAL 开放获取。
- **对本项目的可借鉴点**：
  1. **「分层」是本项目架构的核心隐喻**：我们已经有天然的分层（板块层 → 均衡/深度层 → FBM 细节层 → 生物群系层），**论文的分层框架可以拿来当设计文档的骨架**。
  2. **它系统整理了 Cordonnier 组 2016–2019 的全部工作**（3.2、3.3 都在其中），是**一次读完全部相关方法的最高效路径**。

## 4. 地球物理 / 地质建模代码（真实科学代码，用于借公式与数据结构）

### 4.1 GPlates / pyGPlates / GPlately
- **链接**：https://github.com/GPlates/GPlates ；官网 https://www.gplates.org/ ；GPlately 文档 https://gplates.github.io/gplately/latest/ ；GPlately https://github.com/GPlates/gplately
- **一句话原理**：真实的**板块重建（plate reconstruction）**软件：把地球的板块边界几何 + 旋转极（Euler pole）+ 旋转序列组织成「拓扑」，可在任意地质时间重建板块位置；pyGPlates 是它的 Python 绑定。
- **类别**：地质数据/重建工具（**用真实数据，不是程序化生成**）。
- **输出范围**：真实地球（有限，且有真实数据依赖）。
- **实时性**：**需全局预计算缓存 + 真实数据文件**（.rot / .gpml 等）。**对本项目完全不可用**。
- **双峰高程**：是（真实地球本来双峰）。
- **地貌单元**：真实地球的**全部**（海沟、岛弧、洋中脊、大陆架…），因为它就是地球。
- **内海与孤岛**：真实地球有（地中海、黑海、日本…）。
- **语言/依赖/许可证/star**：C++ / Python / Qt；**许可证 GitHub API 识别为 NOASSERTION（LICENSE 文件不在常规路径，我未能验证）—— 使用前必须自己核对**；**★152**；最后提交 2026-09-17（活跃）。论文：*Next-generation plate-tectonic reconstructions using GPlates*（Boyden, Müller, Gurnis, 2011, DOI https://doi.org/10.1017/CBO9780511976308.008 ）；*Plate tectonic raster reconstruction in GPlates*（Cannon, Lau, Müller, 2014, DOI https://doi.org/10.5194/sed-6-793-2014 ）。
- **对本项目的可借鉴点**：
  1. **「板块拓扑」的数据结构值得抄**：一个板块边界由**几何（折线）+ 边界类型（汇聚/离散/转换）+ 有效时间区间 + 两侧板块 id** 构成。我们的版本把「时间」换成「X 轴位置」或「板块索引」，就得到一个纯数据的边界表。**注意：我们的边界必须由程序化生成，而不是加载 .gpml 文件**（否则就不能无限 X 了）。
  2. **「旋转极（Euler pole）+ 角速度」是表达板块运动的正确参数化**：在球面上它给出刚体运动；在平面上退化为「平移 + 旋转」。**如果我们要让板块运动随纬度变化（这在球面上是必然的），欧拉极就是最省的参数化**（3 个数：极点经纬度 + 角速度）。**建议采用：每板块 (eulerPoleLat, eulerPoleLon, omega)，用哈希从板块 id 生成。**
  3. **pyGPlates 的价值在于「验证」**：可以拿真实地球的板块边界去对照我们生成的地形，**定量比较「我们造出的山带是否落在合理的位置模式上」**（作为离线质检，不进模组）。
  4. **许可证不明 + GPL 系**：只借概念。

### 4.2 ASPECT（Advanced Solver for Planetary Evolution, Convection, and Tectonics）
- **链接**：https://github.com/geodynamics/aspect ；文档 https://aspect.geodynamics.org/
- **一句话原理**：大规模并行有限元**地幔对流**求解器，用 Stokes 方程描述地幔流动，并把板块运动作为**速度边界条件**施加，从而研究板块构造的驱动力。
- **类别**：地球动力学数值求解器（PDE）。
- **输出范围**：有限（球壳 / 2D 剖面），需网格与时间步。
- **实时性**：**需离线全局模拟**（HPC 级）。**对本项目完全不可用。**
- **双峰高程**：否 —— 它解的是地幔对流（速度场、温度场），**不输出地表高程**。
- **地貌单元**：无（不生成地形）。
- **内海与孤岛**：无。
- **语言/依赖/许可证/star**：C++（依赖 deal.II、p4est、Trilinos 等一大票 HPC 库）；**GPL-2.0-or-later**（LICENSE 文件已实际读取）；**★308**；最后提交 2026-09-16（活跃）。论文：*High accuracy mantle convection simulation through modern numerical methods – II: realistic models and problems*（Heister, Dannberg, Gassmöller, Bangerth, GJI 2017, DOI https://doi.org/10.1093/gji/ggx195 ，已 Crossref 核对）。
- **对本项目的可借鉴点**：
  1. **它回答的是「为什么板块会动」而不是「地形长什么样」** —— 对本项目**只有间接价值**：它提示**板块运动的驱动力是「洋中脊推力 + 俯冲板片拉力」**。这可以指导我们的**速度场生成**：不要给板块纯随机速度，而应该让速度**大致沿着「远离洋中脊、朝向俯冲带」的方向**，这样看起来才合理。Frozen Fractal 正是这么做的。
  2. **它的「速度边界条件」概念**：把板块当成给定速度的刚性盖层，地幔在其下流动。我们的类比：**给定速度的板块盖层 + 无地幔 = 我们的模型**。**所以我们可以正当地说「本项目是 ASPECT 的零阶近似」。**
  3. **GPL-2.0-or-later + HPC 依赖**：绝对不能碰代码。

### 4.3 CitcomS
- **链接**：https://github.com/geodynamics/citcoms
- **一句话原理**：球壳有限元**可压缩热化学对流**求解器，用于地幔对流；与 ASPECT 同类，是更老的一代 HPC 代码。
- **类别**：地球动力学数值求解器。
- **输出范围**：有限（球壳网格）。
- **实时性**：需离线全局模拟。**不可用。**
- **双峰高程**：否（输出温度/速度场）。
- **地貌单元 / 内海与孤岛**：无。
- **语言/依赖/许可证/star**：C / MPI（依赖 PETSc 等）；**GPL-2.0**（GitHub API 识别；LICENSE 文件不在常规路径，**未逐字验证**）；**★52**；最后提交 2025-09-12。论文：*GeoFramework: Coupling multiple models of mantle convection within a computational framework*（Tan, Choi, Thoutireddy, Gurnis, Aivazis, G3 2006, DOI https://doi.org/10.1029/2005GC001155 ，已 Crossref 核对）；基准论文 *A benchmark study on mantle convection in a 3-D spherical shell using CitcomS*（Zhong, McNamara, Tan 等, G3 2008, DOI https://doi.org/10.1029/2008GC002048 ）。
- **对本项目的可借鉴点**：
  1. **与 ASPECT 相同的定位**：属于「板块运动的上游物理」。**对本项目的唯一价值是提供引用与术语**（例如在文档里说明我们省略了地幔对流这一层）。
  2. **它的基准论文（benchmark）提醒我们**：地幔对流社区花了十几年做**标准算例**。**我们也应该为自己的板块生成器建一套「标准算例」**：固定的 seed、固定的参数、固定的检查项（内海数、连通大陆数、D 值、陆地占比、双峰性），每次改代码都跑一遍。**这是本清单之外、但由这些项目间接教给我们的工程实践。**

### 4.4 Geodynamic World Builder（GWB）
- **链接**：https://github.com/GeodynamicWorldBuilder/WorldBuilder ；论文 DOI https://doi.org/10.5194/se-10-1785-2019 （已 Crossref 核对）
- **一句话原理**：为地球动力学数值模型生成**初始条件**的声明式库：用户写一份配置文件，里面是一系列 **feature**（多边形 / 折线 / 距离场），每个 feature 携带随深度变化的温度、密度、粘度等属性；GWB 在任意查询点求值，返回该点的属性。
- **类别**：声明式几何特征库（**初始条件生成器，不是仿真器**）。
- **输出范围**：全球（可无限求值）。
- **实时性**：**运行时 O(1) 求值**（对任意 (x,y,z) 查询，遍历 feature 列表并做「点在多边形内」判定 + 距离衰减）。**这是本清单里架构与我们最接近的科学代码。**
- **双峰高程**：不适用（它给的是密度/温度/粘度，不是高程）。但它**显式区分大陆地壳与海洋地壳**（通过不同的 feature 与属性），**这正是双峰高程的输入**。
- **地貌单元**：不生成地形，但它能表达**俯冲板片、洋中脊、大陆岩石圈、地幔柱**等构造单元。
- **内海与孤岛**：不适用。
- **语言/依赖/许可证/star**：C++（CMake，有 Python 绑定）；**LGPL-2.1**（GitHub API 识别）；**★41**；最后提交 2026-09-16（活跃）。论文：*The Geodynamic World Builder: a solution for complex initial conditions in numerical modeling*（Fraters, Thieulot, van den Berg, Solid Earth 10, 1785–1807, 2019）。
- **对本项目的可借鉴点**：
  1. **「feature 列表 + 逐点求值」就是我们要的架构**：把一个板块写成 Feature{polygon, type, velocity, crustThickness, crustDensity}，把一条板块边界写成 Feature{polyline, boundaryType, width, upliftAmplitude}；对任意 (x,z) 顺序求值并累加。**GWB 用同样的方式组织地球，我们用它组织一个虚构星球。**
  2. **「距离场（distance field）」是它的核心原语**：feature 的影响按「离几何的距离」衰减。**我们的造山核函数本质就是「到边界折线的距离场」，可以直接采用「距离 → 影响」这一层抽象。**
  3. **LGPL-2.1：可以动态链接、不能静态抄**（与 platec 同）。而且它是 C++，对我们意义主要在**架构借鉴**。
  4. **它把「随深度变化」作为一个显式维度**：对我们（MC 只有 y=0~255）来说，这个维度可以简化掉 —— **但「地壳厚度」这个量必须保留**，因为它是双峰高程的物理来源。

### 4.5 Fastscape / FastScapelib
- **链接**：https://github.com/fastscape-lem/fastscape ；官网 https://fastscape.org/
- **一句话原理**：快速、易用的**景观演化模型（LEM）**：以 stream power 方程为核心，把构造抬升当作输入，求解河流侵蚀与坡面扩散，得到随时间演化的地形。
- **类别**：景观演化数值模型（Python 生态）。
- **输出范围**：有限网格。
- **实时性**：需离线全局模拟（时间步迭代，且流向/汇水面积是全局量）。
- **双峰高程**：否（单峰侵蚀地貌 + 给定抬升）。
- **地貌单元**：山脉、河流、分水岭；**无**陆架/坡/岛弧/海沟/洋中脊。
- **内海与孤岛**：河流系统会产生湖泊，但不受控。
- **语言/依赖/许可证/star**：Python（含 Cython/C++ 内核，依赖 xarray/dask 等）；**BSD-3-Clause**；**★76**；最后提交 2026-09-07。理论基础：*A very efficient O(n), implicit and parallel method to solve the stream power equation governing fluvial incision and landscape evolution*（Braun & Willett, Geomorphology 2013, DOI https://doi.org/10.1016/j.geomorph.2012.10.008 ，已 Crossref 核对）。
- **对本项目的可借鉴点**：
  1. **BSD-3-Clause = 可以自由使用**，如果我们想要一个「离线参考地形」来标定细节噪声的统计特性，fastscape 是合适工具。
  2. **它的「抬升场 U(x,t)」接口正是我们板块模型的输出**：我们可以**离线**用 fastscape 跑几个「给定抬升场 → 侵蚀后地形」的算例，**统计侵蚀后地形的功率谱（power spectrum）**，再把这个谱拟合进我们的 FBM 层。**这样我们的噪声就不是拍脑袋的，而是从真实景观演化模型反推出来的。**（属于用户放宽允许的离线标定，产物是几个谱系数，不是地图。）
  3. **不要试图在线跑它**：O(n) 的隐式求解需要全图排序（按高程），与 O(1) 求值根本冲突。

### 4.6 Landlab
- **链接**：https://github.com/landlab/landlab ；文档 https://landlab.csdms.io/ ；构造活动组件示例 https://landlab.csdms.io/tutorials/normal_fault/normal_fault_component_tutorial.html
- **一句话原理**：一个**组件化**的地表过程建模工具箱（网格 + 可插拔组件：断层、抬升、侵蚀、水文、风成…），其中 NormalFault 等组件专门负责**构造活动**（把断层位移加到高程上）。
- **类别**：组件化地表过程模型库。
- **输出范围**：有限网格。
- **实时性**：需离线全局模拟（时间步）。
- **双峰高程**：否。
- **地貌单元**：**断层崖、抬升**（构造侧）；**无**陆架/坡/岛弧/海沟/洋中脊。
- **内海与孤岛**：由水文组件部分处理。
- **语言/依赖/许可证/star**：Python；**MIT**；**★441**；最后提交 2026-09-17（非常活跃）。
- **对本项目的可借鉴点**：
  1. **MIT + ★441 + 组件化 = 最好的「构造活动如何加到高程上」的代码参考**。具体看 NormalFault 组件：它把「断层线 + 位移量 + 上盘/下盘」变成一个**逐点的高程增量**。**我们的板块边界造山核函数就是一个更一般的 Fault/Uplift 组件**，可以直接照着它的接口设计。
  2. **它的「网格（grid）+ 组件（component）+ 场（field）」抽象很适合描述我们的分层**：每个地形层是一个 component，输入是 (x,z) 网格上的场，输出是场的增量。**建议我们内部也按这个模式组织：ElevationField += TectonicComponent(x,z)。**

### 4.7 Badlands（Basin and Landscape Dynamics）
- **链接**：https://github.com/badlands-model/badlands ；组织页 https://github.com/orgs/badlands-model/repositories
- **一句话原理**：盆地与景观动力学模型：耦合**构造沉降/抬升、地表侵蚀搬运、沉积**，模拟从源到汇（source-to-sink）的完整过程，输出地层与地貌。
- **类别**：源-汇耦合地球动力学模型（Python）。
- **输出范围**：有限区域。
- **实时性**：需离线全局模拟（HPC 可选）。
- **双峰高程**：否。
- **地貌单元**：山地带、冲积扇、三角洲、盆地充填；**无**洋中脊/海沟/岛弧的显式模型（但它有海平面与被动边缘概念）。
- **内海与孤岛**：部分（沉积盆地会形成湖/内海）。
- **语言/依赖/许可证/star**：Python（依赖 numpy/scipy、可选 MPI）；**LGPL-3.0**；**★192**；最后提交 2026-05-01。
- **对本项目的可借鉴点**：
  1. **它是「海平面 + 沉积」这一对的参考**：**大陆架/大陆坡的形成本质就是沉积物堆积**（被动大陆边缘的楔形体）。**如果我们要让大陆架看起来真实（宽、平、缓慢下降），最省的模型就是「从海岸线向外的一个指数/多项式下降剖面」，而不是按构造边界算。**
  2. **「沉积楔形体」的解析近似**：depth(d) = shelfDepth × (1 − exp(−d/W)) 从海岸向外，W 是陆架宽度（可由低频噪声调制）。**这是一个纯 O(1) 的公式，是本项目做大陆架最实用的一条。**
  3. LGPL-3.0：只借概念。

### 4.8 goSPL（Global Scalable Paleo Landscape Evolution Model）
- **链接**：示例集 https://github.com/Geodels/goSPL-examples ；组织 https://github.com/Geodels
- **一句话原理**：全球尺度的古景观演化模型，把**全球**的构造（板块运动、动态地形）与地表过程（侵蚀、沉积、河流）耦合，模拟地质时间尺度上的全球地形演化。
- **类别**：全球景观演化模型。
- **输出范围**：全球（有限网格）。
- **实时性**：需离线全局模拟。
- **双峰高程**：**是（输入侧）** —— 它用真实的**动态地形（dynamic topography）**与**板块模型**驱动，输出天然是双峰的；但双峰来自输入数据，不是模型产生的。
- **地貌单元**：全球尺度的大陆、被动边缘、山脉、洋盆；**这是本清单里唯一在「全球 + 构造 + 地表过程」三方面都覆盖的模型**。
- **内海与孤岛**：真实地球有，模型会继承。
- **语言/依赖/许可证/star**：C++ 核心 + Python 绑定（示例集仓库）；核心 goSPL 的 star 与许可证**未逐一验证**。
- **对本项目的可借鉴点**：
  1. **「动态地形（dynamic topography）」这个概念值得引入**：即使板块边界不动，地幔流动也会让地表缓慢起伏。**在 O(1) 层面的廉价等价物是：再叠一层极低频（波长 ~50,000 格）的噪声，幅度 ±500 m**，用来打破「大陆内部太平」的问题。**这是一条很便宜、效果很好的建议。**
  2. **「全球尺度 + 纬度」的耦合**：goSPL 处理的是球面，而我们的 Z 轴周期 2e7 **正好可以当作纬度**。**sediment flux / 气候带 / 温度随纬度变化** —— 这些是 goSPL 的输入，也是我们可以在 Z 方向上解析地做出来的（例如：赤道附近侵蚀更强 → 细节噪声幅度随 sin(纬度) 变化）。
  3. **注意**：核心仓库与许可证我未逐一验证，**引用前请自行核对**。

## 5. 关键公式（不是算法库，但却是「双峰高程 + 陆架/坡/深海盆地」的核心）

### 5.1 Parsons & Sclater 1977 —— 海底深度随年龄
- **链接**：DOI https://doi.org/10.1029/JB082i005p00803 （*An analysis of the variation of ocean floor bathymetry and heat flow with age*, Parsons & Sclater, JGR 82(5), 1977；已 Crossref 核对）
- **一句话原理**：洋壳是**热的、浮的**，随年龄冷却收缩下沉。**半空间冷却模型**给出 d(t) = d0 + c × √t（t 为年龄，单位 Ma；经典拟合 d ≈ 2500 + 350 × √t 米），约 70 Ma 之后偏离，改用**板块模型**（趋于约 6400 m 的渐近深度）。
- **类别**：地质学解析公式（**不是软件**）。
- **输出范围**：全球适用（解析式，任意点可求值）。
- **实时性**：**O(1) 解析求值**。★完美契合本项目★
- **双峰高程**：**是，而且是双峰里「低峰」的成因**。它给出了**深海盆地（−4 km 级）**与**洋中脊（−2.5 km 级）**之间的关系 —— **洋中脊高、老洋盆低，两者之间是连续下降的**，这正好解释了「洋底不是平的，而是一个随年龄下降的坡面」。
- **地貌单元**：**洋中脊**：直接（t→0 处深度最小）。**深海盆地**：直接（t 大处深度趋于渐近值）。**大陆架/大陆坡**：**间接但关键** —— 陆架/坡是**陆壳向洋壳的过渡**，不是同一个公式；但「洋侧深度随离脊距离增加」这一半是它的功劳。
- **内海与孤岛**：不适用。
- **语言/依赖/许可证/star**：论文（JGR）；公式本身无版权限制。
- **对本项目的可借鉴点**（**这是本清单里最实用的一条，建议立刻落地**）：
  1. **构造一个「洋壳年龄」场**。既然板块是程序化的，我们可以让「离散边界（洋中脊）」生成洋壳，并令 **age(p) 正比于 到最近洋中脊的距离 / 该处的扩张速率**。扩张速率由边界两侧板块的相对速度在法线上的分量给出（半扩张速率）。
  2. **深度 = 2500 + 350 × √age（米），age 以 Ma 计，封顶在 ~70 Ma 后改用渐近值 ~6400 m**。用这条公式取代「洋底就是一个常数 −4000 m」的粗暴做法，**深海盆地会自然呈现「靠近洋中脊较浅、远离较深」的斜坡**，观感提升巨大，且完全 O(1)。
  3. **它给出大陆架的正确宽度尺度**：大陆架（shelf，~0~200 m 深，宽度 10~100 km）→ 大陆坡（slope，200~2000 m，坡度 3~6°）→ 陆隆/深海平原。**在 Z 周期 20,000,000 的世界里，如果 1 格 ≈ 1 km 量级，那么大陆架宽度只有几十格 —— 这意味着在 MC 的 16×16 块精度下，大陆架是「一个块级别」的特征，必须显式放大或按比例夸张，否则玩家根本看不到。** 这是一个必须在设计早期做出的尺度决策。
  4. **配合 Stein & Stein 1992 的板块模型**（DOI https://doi.org/10.1038/359123a0 ，*A model for the global variation in oceanic depth and heat flow with lithospheric age*, Nature 359, 1992；已 Crossref 核对）作为「70 Ma 之后的渐近行为」的更精确版本。**两条公式合起来 = 一个完整的、O(1) 的洋底深度函数。**

### 5.2 Airy 均衡（等压补偿）—— 双峰高程的物理根源
- **链接**：无单一「官方」链接；公式出现在 1.5 的 pyTectonics 模型文档（https://sourceforge.net/p/pytectonics/wiki/Model%20Overview/ ）与任何地球物理教科书。**我未找到一篇可单独引用的开放获取原文，故不编造 DOI。**
- **一句话原理**：地壳漂浮在密度更大的地幔上，**厚而轻的陆壳浮得高，薄而重的洋壳沉得低**：h = ((ρm − ρc)/ρm) × T（T 为地壳厚度）。
- **类别**：物理公式。
- **输出范围**：任意点。
- **实时性**：**O(1)**。
- **双峰高程**：**是，这是双峰的成因本身**。取 ρm ≈ 3.3、ρc_陆 ≈ 2.7 → 系数 ≈ 0.18；T_陆 = 35 km → 相对高度大；T_洋 = 7 km、ρc_洋 ≈ 2.9 → 系数 ≈ 0.12 → 相对低约 4~5 km。**关键是：只要模型里有「两种厚度 + 两种密度」，高程分布就自动双峰。**
- **地貌单元**：**大陆架/坡**：均衡给出「陆壳到洋壳的厚度过渡带」，这**就是**大陆坡的位置。**海沟**：俯冲带的地壳被拉薄 + 板片下拉 → 负异常。其余不适用。
- **内海与孤岛**：不适用。
- **对本项目的可借鉴点**：
  1. **这是「不写一个真实板块引擎，也能做出双峰」的最短路径**：给每个点两个标量 —— crustType（陆/洋）和 thickness，然后套公式。crustType 可以由低频噪声（大陆度场）阈值化得到，thickness 可以由「大陆度」连续映射 + 山带叠加得到。
  2. **它自动解决「为什么大陆是一块平的台地」**：陆壳厚度在克拉通内部近似常数 → 高程近似常数 → **平坦的大陆台地（+0.3 km 峰）**。这正是我们要的第一个峰。
  3. **它也自动解决「为什么深海盆地是平的」**：老洋壳厚度/密度稳定 → 深度趋于常数（−4 km 峰）。配合 5.1 的年龄项，就得到「有坡度的洋盆」。
  4. **实际落地建议**：不要真的去解均衡方程（那需要全局的厚度场），而是**把均衡的结果直接写成解析式**：h = base(crustType) + k_thick × thicknessAnomaly(p)，其中 thicknessAnomaly 由「大陆度噪声 + 山带叠加」给出。**形式上是均衡，实现上是 O(1) 映射。**

### 6.1 Dwarf Fortress 的世界生成 —— **明确结论：它不做板块构造**
- **链接**：官方 wiki 世界生成页 http://dwarffortresswiki.org/index.php/World_generation ；进阶参数 http://dwarffortresswiki.org/index.php/Advanced_world_generation

- **类别**：全局世界模拟（地形 + 历史）。
- **输出范围**：有限（Pocket 17×17 / Large 257×257 region tiles，每个 region tile = 16×16 local blocks）。
- **实时性**：**需离线全局模拟**。wiki 明确：*"World generation can take a long time"*，且 *"Setting this to a larger value will cause world generation to take longer"*。
- **双峰高程**：未在 wiki 中说明。
- **地貌单元**：**大陆架/坡/岛弧/海沟/洋中脊：wiki 均未提及**。
- **内海与孤岛**：DF 的世界**充满内海与岛屿**，且它是**刻意如此**（REGION_COUNTS:OCEAN 等参数控制海洋区域数量，玩家可调）。**与我们的指标（内海 = 0）完全相反。**
- **语言/依赖/许可证/star**：闭源商业游戏（C++，Tarn Adams / Bay 12 Games）。
- **对本项目的可借鉴点**（**重要的「反面 + 侧面」参考**）：
  1. **核实结果：DF 世界生成不使用板块构造。** 我实际抓取并统计了官方 wiki 的 World generation 页面全文：**"tectonic" 出现 0 次**，"erosion" 1 次，"rainfall" 4 次。**任务描述中「它真的做板块+侵蚀+降雨」这个假设，就「板块」这一项而言不成立 —— 请勿在文档中引用为板块构造案例。** 它做的是**侵蚀 + 降雨（含雨影）+ 温度**。
  2. **但它的「后处理链」顺序值得抄**：高程 → 降雨 → 温度 → 河流 → 侵蚀 → 生物群系。**我们的顺序应当一致**，且要在每一步都保持 O(1)。
  3. **它反证了「无限世界 + 全局模拟」不可兼得**：DF 的世界是**有限**的，正因为如此它才能跑上百年的历史模拟。**这从侧面支持了我们的硬约束：如果坚持 X 无限，就必须放弃任何需要全局状态的东西（包括真正的河流侵蚀、真正的连通性分析）。**
  4. **它的「rejection（拒绝重采样）」机制**：世界生成会**反复重掷直到满足统计条件**（例如大陆数量、海洋比例）。**这是一个可以直接搬的离线技巧**：我们在离线标定阶段也可以用「重掷 seed 直到统计量达标」，然后把「哪些 seed 合格」编译成一个小判据；**在线阶段则用一个显式的确定性函数直接构造出合格的世界，而不是碰运气。**

- **语言/依赖/许可证/star**：本体闭源（itch.io 开发日志）；**SongsOfFOSS 为开源分支**（GitHub；star 数未验证）；climatenet 是配套的气候神经网络训练仓库。**三个链接都经检索确认存在，但我只读了描述，未读源码。**
- **对本项目的可借鉴点**：
  1. **它证明「板块 + 气候」的组合在独立游戏里被认真做过**，且社区接受了这种世界生成方式。
  2. **climatenet（用神经网络做气候）提示了一条我们可能用得上的路**：**如果我们只需要「降水/温度」两个标量场，用一个预先训练好的小网络（或者干脆查表）比跑物理气候模型便宜得多**。对 Z 轴 = 纬度 的我们来说，气候几乎可以是 **Z 的解析函数 + 高程修正 + 一个雨影核函数**，甚至不需要网络。

### 6.4 Fracplanet（Tim Day）
- **链接**：https://www.timday.com/share/fracplanet/index.html ；Debian 包 https://packages.debian.org/trixie/amd64/fracplanet
- **一句话原理**：**分形行星生成器**：从二十面体出发做**递归细分（recursive subdivision）**，在细分过程中施加**扰动（perturbation）**得到地形；支持云层、导出 POV-Ray / Blender。关键词（作者站点 meta）：fractal、subdivide、recursive subdivision、perturbation、Perlin noise。
- **类别**：分形地形生成（**无板块构造**）。
- **输出范围**：有限/球面。
- **实时性**：**运行时 O(1) 可求值**（递归细分 + 噪声，是纯几何函数）。
- **双峰高程**：**否**。分形地形是单峰的（高度服从近似高斯/稳定分布），**这正是「纯噪声做不出双峰」的标准反例**。
- **地貌单元**：**无**任何板块单元（无陆架/坡/岛弧/海沟/洋中脊）。
- **内海与孤岛**：不处理（分形地形天然会产生大量岛屿与内海）。
- **语言/依赖/许可证/star**：C++ / Qt / OpenGL；**GPL**（Debian 包与 FreeBSD port 均标注 GPL；作者站点 meta 关键词也含 GPL）；Debian 版本 0.5.1-6。
- **对本项目的可借鉴点**（**重要的基线对照**）：
  1. **它是「对照组」**：把 fracplanet 的输出与板块模型输出并排看，可以直观看出**纯分形地形为什么达不到我们的指标**（单峰、碎岛多、内海多、没有方向性的山带）。**建议在测试用例里保留一个「纯 FBM 基线」用于对比。**
  2. **它的「递归细分 + 扰动」在无限平面上有等价物**：就是**多倍频 FBM**。**我们可以把它当作细节层（最高频那一层），但绝不能当作大陆形状的来源。**
  3. **GPL**：不抄代码，只做对照实验。

### 6.5 Minecraft「Tectonic」（数据包 / 模组）

- **一句话原理**：Minecraft 的地形重塑数据包/模组，用原版的**密度函数（density function）+ 样条 + 噪声**做大规模地形塑形（更真实的山脉、河谷），**名字叫 Tectonic 但并非板块构造模拟**。

- **实时性**：运行时 O(1)（密度函数）。
- **双峰高程**：否（它是原版世界的重塑，继承了原版的高度分布）。

## 8. 综合：把上面所有东西拼成一个可落地的方案（本项目的技术建议）

> 这一节是调研的**产出**，不是引用。目标是「在 X 无限、Z 周期 2e7、O(1)、零全局内存」的约束下，做出 1~2 块连通大陆、双峰高程、内海≈0、D≈1.2~1.4 的世界。

### 8.1 分层架构（借 3.4 的「分层」与 4.4 GWB 的「feature + 逐点求值」）

    h(x,z) = BASE(crustType)                 // 两类地壳的基准面
           + ISOSTASY(thicknessAnomaly)      // 5.2  双峰的两个峰
           + Σ_b BOUNDARY_b(x,z)             // 2.2  六类边界效应
           + SEAFLOOR_AGE(x,z)               // 5.1  洋盆的坡度
           + DETAIL(x,z)                     // 3.3  与宏观高度相关的分形细节

每一层都是**纯函数**，没有状态。

### 8.2 九条具体建议（按实现顺序）

1. **板块中心：抖动网格，不是泊松盘。** 在 (x,z) 上定义单元边长 S（Terramax 用 ≈100,000 方块；我们的 Z 周期是 20,000,000，取 S ≈ 100,000 得到约 200 个板块带）。每个单元 (i,j) 由 hash(i, j, seed) 生成一个抖动点 c_ij 及其属性 (crustBias, thickness, density, eulerPole, omega, activity)。查询时只看 3×3 邻域 → **O(9)**，可以进一步用「距离下界剪枝」压到平均 O(1~2)。**这是整份清单最重要的工程决策**（来源：Terramax 1.9 + pyTectonics 1.5 的教训）。

2. **域扭曲（domain warping）必须第一版就上。** p' = p + A × (noise1(p), noise2(p))，用 p' 做 Voronoi。**它把多边形变成海岸线，并且是控制海岸线分形维数 D 的主要旋钮**（来源：Terramax 原文 so the result reads as coastline rather than as polygons）。调 A 与噪声频率即可把 D 调到 1.2~1.4。

3. **每个点算两个标量：crustType 与 thickness。**
   - crustType 来自一个**极低频的大陆度场**（波长约几百万格，必须保证在 Z 上周期为 2e7，用「Z 方向可周期化的噪声」如 sin/cos 组合或周期化的 value noise）。
   - thickness = base(crustType) + 山带叠加。
   - 用 Airy 均衡的**闭式**（5.2）得到高程 —— **双峰自动出现，不需要任何直方图塑形**。

4. **边界效应查表：直接抄 Frozen Fractal 的六类表**（2.2）。相对速度 v_rel = v_a - v_b，边界法线 n（由两个板块中心的连线给出，Voronoi 边界的法线就是中心连线方向）。
   - 相对速度与法线点积 > 0 → 汇聚；< 0 → 离散。
   - 再结合两侧 crustType → 6 类。
   - 每类给一个**带噪声调制的剖面核**：contribution = amp(type) × profile(d / (L(type) × (1 + 0.4 × noise))) × (1 + 0.6 × noise2)。**剖面可以是 tent（山带），也可以是 plateau（高原）/ trench（窄而深的负向尖峰）/ ridge（宽而缓的正向）。** 噪声同时作用于宽度与幅度（Frozen Fractal 强调这一点）。

5. **岛弧不需要单独的模块。** 在洋-洋 / 陆-洋汇聚边界上，把剖面改成**周期性峰值**：profile(d) × (0.5 + 0.5 × sin(2π × s / λ + φ_noise))，其中 s 是沿边界走向的距离。λ 取几万格。（来源：FioDev 1.13 的「俯冲带生成一串岛屿」+ 4x_planet_generator 1.11 的夏威夷链。）

6. **大陆架 / 大陆坡用「沉积楔形」解析式，不要用构造公式。** 4.7 badlands 的启示：被动大陆边缘的陆架是沉积物堆积。用 depth(d) = shelfDepth × (1 − exp(−d/W))，d = 到海岸线的距离，W = 陆架宽度（由低频噪声调制）。**注意尺度问题**：如果世界尺度是 1 格 ≈ 1 km，真实陆架只有几十格宽，在 MC 里几乎看不见 —— **建议对陆架/坡做 3~10 倍夸张，并在配置里暴露这个倍数。**

7. **洋底年龄 → 深度：用 Parsons & Sclater（5.1）。** age = distToRidge / halfSpreadingRate，depth = min(2500 + 350 × √age, 6400)（米，age 以 Ma 计）。**这一步让深海盆地不再是一块平板**，而是从洋中脊向两侧缓降 —— 观感提升最大、成本最低的一条。

8. **细节层与宏观高度耦合**（3.3）：DETAIL = fbm(x, z, octaves) × amp(h_macro)，并且让噪声**各向异性**（沿等高线方向压缩）以呈现「沿走向的山脊」。同时叠加一层**极低频动态地形**（4.8 的建议：波长 ~50,000 格，幅度 ±500 m）来打破大陆内部的平淡。

9. **内海与孤岛的解法 —— 必须在 O(1) 之外想清楚。**
   - 「内海 = 0」等价于「陆地部分是单连通的」，这是**全局拓扑性质，O(1) 不可能判定**。清单里所有项目（除 Azgaar 与 tergen 用全局水文算法外）都不处理它。
   - **可行方案（按推荐度排序）**：
     - **(A) 构造式保证（推荐）**：把大陆度场设计成**只有一个超阈值连通分量**。例如：continentality(p) = G(p) − penalty(p)，其中 G 是一个**单峰**的、覆盖整个世界（Z 周期内）的连续场，penalty 是远离该单峰的单调上升项。由于 G 的阈值上集是凸的（或单连通的），陆地必然只有一块。**这是唯一真正 O(1) 的内海 = 0 方案。**
     - **(B) 半离线修正（可用，需标注）**：离线在一个粗分辨率（如 2048×2048，覆盖整个 Z 周期）上跑一次连通分量分析，把「需要填平的内海」编码成一个**极小的修正层**（例如把它拟合成几十个椭圆洼地的填充参数，或直接存一个 2048×2048 的 1-bit 掩码 = 512 KB，可接受）。用户已放宽「有限范围离线方案」，**这条属于「离线产物小、可以搬进模组」，但仍然违反严格的零预计算，应在文档中明确标注为可选模块。**
     - **(C) 后处理修复（不推荐）**：在区块加载时做局部洪水填充。**在无限 X 上不可行**（无法确定一个水体是否连通到远方的海）。
   - **孤岛同理**：散落小岛来自「大陆度场的噪声毛刺」。**方案：对大陆度场做一次 smoothstep 硬化（而不是硬阈值）**，让接近阈值的区域被强烈推向两侧，消除「刚好在海平面附近抖动」产生的碎岛。这是 O(1) 的，且效果显著。

### 8.3 建议的验收指标（自动化测试，借 4.3 CitcomS 的 benchmark 文化）

在离线测试工具里，对每个 seed 生成一张 4096×4096（覆盖 Z 周期的一个代表性子带）的低分辨率图，自动计算：
- **内海数量**（洪水填充，统计「不与边界海洋连通的陆地围合水域」）→ 目标 0；
- **连通大陆数**（陆地连通分量，忽略面积过小的）→ 目标 1~3；
- **陆地占比** → 可标定，默认 ≈ 0.29（地球值）；
- **海岸线分形维数 D**（盒计数法）→ 目标 1.2~1.4；
- **高程直方图的双峰性**（高斯混合拟合的 BIC 差值 / 双峰系数）→ 目标两个峰分别落在 ≈ +0.3 km 与 ≈ −4 km（5.2 的均衡公式应当自动满足）；
- **山带的方向性**（梯度方向直方图的各向异性）→ 应当明显偏离各向同性（这是与纯 FBM 基线的关键区别）。

### 8.4 一句话总结

**这个领域里 95% 的代码（platec、worldengine、tectonics.js、pyTectonics、tergen、ASPECT、CitcomS、fastscape、badlands…）都是「有限地图 + 全局时间步」，对本项目的硬约束不可搬；真正能搬的是四样东西：(1) Frozen Fractal 的六类板块边界效应表，(2) Terramax 的「抖动网格板块 + Voronoi + 域扭曲」无限世界骨架（Java/Apache-2.0），(3) Airy 均衡 + Parsons–Sclater 年龄-深度两个公式（它们直接产生双峰高程与陆架/坡/深海盆地分层），(4) 「距离函数 + 逐点求值」的架构（Geodynamic World Builder / kenny.wtf）。内海 = 0 与孤岛问题，全清单无人用 O(1) 解决过，必须靠「构造式保证单连通」自己解决。**
