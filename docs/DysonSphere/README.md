# 塔罗斯戴森球：模块化巨构机器系统

> 本文件是戴森球**机器系统**的唯一规格记录，随开发实时更新。
> 天空盒渲染、全局赛跑语义与三计数器见同目录 [design.md](./design.md)。

## 一、定位

戴森球是游戏旅程最后的唯一超级巨构：**每位玩家一台戴森核心**，同队玩家共享队伍三计数器（组队并行推进）；
核心通过 32 个**模块槽**挂载可插拔模块。
三计数器（云/框架/贴片）、每日结算、完工规则全部沿用 `design.md` 的定稿语义，本文件只负责机器侧。

## 二、全局约定

- **队伍语义**：`OrundumEnergyService.getTeamIdForUser(playerUUID)`（空间工程队长），不使用 `/ocgroup`。
- **能量交互**：核心与所有模块**不设能量仓、不接能量 hatch**。一切耗电/发电只走两套无线账本：
  - 无线 EU：`addEUToGlobalEnergyMap(userUUID, BigInteger)`
  - Orundum：`OrundumEnergyService.changeOrundumForTeam(teamId, BigInteger)`
- **能量结算**：制造/发射等模块的消耗**全部走 Orundum 账本**（1 EU 成本基准 ≡ 1 Orundum），不使用无线 EU。
  接收模块产出按 GUI 配置的 **Orundum 占比**拆无线 EU 与 Orundum 两本账。全部使用 BigInteger。
- **单位约定**：所有功率以 **EU/t** 为成本基准，Orundum 按 **1 EU ≡ 1 Orundum** 换算。
  接收模块每 1 秒（20 tick）结算一次（当前占位为全额入 Orundum）；制造/发射模块按各自无线周期结算。
- **维度强约束**：戴森核心与所有模块**只能在塔罗斯 2（ID 14001）维度运行**；其他维度下核心停机并断开全部模块，
  模块自身也拒绝工作（不结算、不耗算力）。
- **供电场约束**：核心与所有模块必须在 **Orundum 供电场**（ProtocolCore 电场覆盖区）内才能工作，场外自动停机。
- **进度读写**：机器只调用 `DysonSphereSystem.addModules(...)`、`settleDaily(...)`，读取 `DysonSphereWorldData.getTeam(teamId)`；
  天空盒照旧渲染领先者，机器层不感知渲染。
- **虚拟组件库存**：制造模块产出、发射模块消耗的组件**只记队伍账本**（`DysonTeamProgress.cloudComponents / frameComponents`），
  不流转实体物品；组件物品保留为展示/纪念品。

## 三、戴森核心

- 每位玩家**限 1 台**（已代码强制）：同一玩家第二台核心会被停机并断开全部模块；拆除/毁坏后释放槽位。
  同队成员可各自建核心，共同推进共享的队伍计数器。
- **无燃料、无电池、自身不耗电**；核心是纯枢纽：识别模块、按贴片进度激活模块槽、把队伍三计数器推给系统。
- **算力需求**：核心固定消耗 1,000,000 算力（见第七节）。
- **维度强约束**：只能在塔罗斯 2（ID 14001）运行，离开该维度核心停机并断开全部模块。
- **核心在线约束**：核心停机（软锤关闭/算力不足/未成型）或区块卸载时，全部模块在 2 秒心跳窗口内自动断开、
  停止一切结算（接收模块同样受此约束）。
- 结构：当前为**临时占位结构**（手写 shape，随时会变），后续接入搭建好的最终多方块；模块位暂未铺满 32 个，以最终结构为准。
- 32 个模块位**自始就物理存在**，但按本队贴片数逐步激活：

| 本队贴片数 | 激活槽位 |
| --- | --- |
| 0 | 8 |
| 500,000 | 12 |
| 1,000,000 | 16 |
| 1,500,000 | 20 |
| 完工（2,000,000） | 32 |

- 激活规则：控制器定期重算，超出激活数的模块被 `disconnect()`；后 12 槽**只在完工后启用**。

## 四、模块体系

所有模块继承 `DysonModuleBase`（基于 `OrundumWirelessMultiMachineBase`），模块位用自定义结构元素收集（参考 God Forge 的 `addModuleToMachineList` 模式）。

`DysonModuleBase` 契约：

- `getModuleType()`：`MANUFACTURING / LAUNCH / RECEIVER / FUNCTIONAL`；
- `getRequiredPaste()`：启用所需的贴片数，默认 `0`（保留给未来“功能性模块”设门槛）；
- `getRequiredCompute()`：本模块固定算力需求（制造 10,000、发射 100,000、接收 0）；
- `connect() / disconnect() / isConnected()`：由核心控制，断开时不 tick、不结算；
- 自身业务走 `doWirelessBusinessOnce()` 等无线基类钩子，能量只走第二节的两本账。

当前三种模块门槛均为 **0 贴片**。

## 五、三种模块

### 1. 制造模块

- 结构：模块位外扩一层，含**输入总线 + 输入仓**（物品与流体原料入口）。
- 配方：原料 → **戴森云组件** / **框架组件**（配方材料先用占位，数值待定）；配方结算后组件**计入队伍虚拟库存**，不产出实体。
- 成本：按配方 `EUt × 时长 × 并行` 结算，**全额计入 Orundum 账本**（1 EU ≡ 1 Orundum）。
- 0 贴片门槛；完工后仍可工作（组件可作他用）。

### 2. 发射模块

- 输入：从**队伍虚拟组件库存**扣云/框架组件（先云后框架，每周期至多 `launchBatch` 个）。
- 效果：`DysonSphereSystem.consumeComponents(...)` + `addModules(teamId, cloudDelta=+1 或 frameDelta=+1)`，1 组件 = 1 计数。
- 成本：每次发射 `C_launch = 10,000`（EU 等价，可配置），**全额计入 Orundum 账本**。
- 0 贴片门槛；**完工后永久失效**（`addModules` 返回 false）。
- 无需物品/流体舱室；多台发射模块可并行，共同推进本队计数器。

### 3. 接收模块

- **每核心至多 1 台**：核心连接阶段只允许 1 个接收模块，多余的保持断开（防止叠接收机刷功率）。
- 输出：本队当前功率池全额，单位 **EU/t**，每 1 秒（20 tick）结算一次，单次入账 = `P × 20`：
  - 完工前：`P = cloudCount × 2^41 + pasteCount × 2^79`；
  - 完工后（仅占领者）：`P = 10^200` 固定。
- 结算：机器 GUI 里打开拆分窗口，输入 **Orundum 占比（0~100）**——如输入 40，则 40% 入 Orundum、60% 入无线 EU；
  默认 100（全 Orundum）。完工满功率同样按此拆分。
- 0 贴片门槛；戴森云无需框架即可发电，纯云路线可用。

## 六、完工后

- 发射模块与一切发射行为永久锁死（含占领者）。
- 后 12 槽解锁，供**接收模块与未来功能性模块**使用。
- 占领者剩余轨道云按每日掉落递减至 0；球壳以 10^200/tick 供能。

## 七、算力需求

戴森核心与模块是我们自有无线算力系统的消费者，需求按台结算（BigInteger）：

| 对象 | 算力需求 |
| --- | --- |
| 戴森核心 | 1,000,000 |
| 制造模块（每台） | 10,000 |
| 发射模块（每台） | 100,000 |
| 接收模块 | 0 |

- 需求从机器 owner 的个人算力网络结算（可经 `/ocgroup` 组内共享，沿用现有 `WirelessComputeHelper` 语义）。
- 核心算力不足 → 核心停机、全部模块断开；单台模块算力不足 → 该模块断开。
- 后续新增的功能性模块自行声明需求。

- **货币占位**：当前用原版圆石；后续替换为专属物品。
- 首批节点（效果数值均为占位，待定）：

## 九、接口清单

| 机器侧调用 | 作用 |
| --- | --- |
| `DysonSphereSystem.addModules(world, teamId, teamName, cloudDelta, frameDelta)` | 发射模块推进本队云/框架 |
| `DysonSphereSystem.addComponents(...)` / `consumeComponents(...)` | 制造入账 / 发射出账队伍虚拟组件库存 |
| `DysonSphereWorldData.getTeam(teamId)` | 读本队 cloud/frame/paste |
| `DysonSphereSystem.settleDaily(world)` | 每日结算（由每日处理器触发） |
| `OrundumEnergyService` / `addEUToGlobalEnergyMap` | 能量出入两本账 |
| `WirelessComputeHelper.updateConsumer(...)` | 声明核心/模块算力需求 |
