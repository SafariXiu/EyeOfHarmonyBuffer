# 塔罗斯戴森球：模块化巨构机器系统

> 本文件是戴森球**机器系统**的唯一规格记录，随开发实时更新。
> 天空盒渲染、全局赛跑语义与三计数器见同目录 [design.md](./design.md)。

## 一、定位

戴森球是游戏旅程最后的唯一超级巨构：**每位玩家一台戴森核心**，同队玩家共享队伍三计数器（组队并行推进）；
核心通过 **GT 数据棒链接**最多挂载 32 台模块（见第四节），模块可放置在任意位置。
三计数器（云/框架/贴片）、每日结算、完工规则全部沿用 `design.md` 的定稿语义，本文件只负责机器侧。

## 二、全局约定

- **队伍语义**：`OrundumEnergyService.getTeamIdForUser(playerUUID)`（空间工程队长），不使用 `/ocgroup`。
- **能量交互**：核心与所有模块**不设能量仓、不接能量 hatch**。一切耗电/发电只走两套无线账本：
  - 无线 EU：`addEUToGlobalEnergyMap(userUUID, BigInteger)`
  - Orundum：`OrundumEnergyService.changeOrundumForTeam(teamId, BigInteger)`
- **能量结算**：制造/发射等模块的消耗**全部走 Orundum 账本**（1 EU 成本基准 ≡ 1 Orundum），不使用无线 EU。
  接收模块产出按 GUI 配置的 **Orundum 占比**拆无线 EU 与 Orundum 两本账。全部使用 BigInteger。
- **单位约定**：所有功率以 **EU/t** 为成本基准，Orundum 按 **1 EU ≡ 1 Orundum** 换算。
  接收模块每 1 秒（20 tick）结算一次，按 GUI 配置的 Orundum 占比拆分入账；制造/发射模块按各自无线周期结算。
- **维度强约束**：戴森核心与所有模块**只能在塔罗斯 2（ID 14001）维度运行**；其他维度下核心停机并断开全部模块，
  模块自身也拒绝工作（不结算、不耗算力）。
- **供电场约束**：核心与所有模块必须在 **Orundum 供电场**（ProtocolCore 电场覆盖区）内才能工作，场外自动停机。
- **队伍变更语义**：玩家离队/被踢后，其核心与模块仍归本人所有并继续运行，但改读写**玩家个人进度**；
  未发射的云/框架组件是**个人资产**，随玩家带走；已发射上天的云/框架是**队伍公共资产**，离队后留在队伍拿不回来；
  升级树在离队/被踢时整体继承一份到个人（与个人已有进度取并集）。加入新队伍时使用新队伍的树，个人树不会反向注入队伍。
- **进度读写**：机器只调用 `DysonSphereSystem.addModules(...)`、`settleDaily(...)`，读取 `DysonSphereWorldData.getTeam(teamId)`；
  天空盒照旧渲染领先者，机器层不感知渲染。
- **虚拟组件库存**：组件是**个人资产**，记在机主自己名下（`DysonTeamProgress.cloudComponents / frameComponents`，
  以玩家 UUID 为键）；制造入个人账、发射扣个人账，打上轨道后转为队伍云/框架计数。不流转实体物品，组件物品保留为展示/纪念品。
- **数值定稿**：贴片容量、掉落范围、功率常数等全部为 `DysonMachineConfig` 内硬编码的 final 常量，
  刻意不开放配置文件，防止玩家修改破坏平衡。

## 三、戴森核心

- 每位玩家**限 1 台**（已代码强制）：同一玩家第二台核心会被停机并断开全部模块；拆除/毁坏后释放槽位。
  同队成员可各自建核心，共同推进共享的队伍计数器。
- **无燃料、无电池、自身不耗电**；核心是纯枢纽：识别已链接模块、按贴片进度激活模块链接槽、把队伍三计数器推给系统。
- **奇异物质**：核心按本队云/贴片数量自动产出**奇异物质**并储存在本机（个人资产，跟组件一样随玩家走）；
  主 GUI 提供“喷射奇异物质”按钮，把储存量喷出到**核心的输出总线**（原版神锻引力子语义：能塞多少塞多少，
  塞不下的留在核心储存）。输出总线为**可选舱室**（0+，结构 D 位，紧邻控制器柱），未接输出总线时按钮会提示。
- **算力需求**：核心固定消耗 1,000,000 算力（见第七节）。
- **维度强约束**：只能在塔罗斯 2（ID 14001）运行，离开该维度核心停机并断开全部模块。
- **核心在线约束**：核心停机（软锤关闭/算力不足/未成型）或区块卸载时，全部模块在 2 秒心跳窗口内自动断开、
  停止一切结算（接收模块同样受此约束）。
- 结构：当前为**临时占位结构**（手写 shape，随时会变），后续接入搭建好的最终多方块；结构内**不再包含模块位**，模块通过数据棒链接（见第四节）；
  结构含 5 个**可选输出总线位**（D，0+），用于取出奇异物质。
- 核心最多可链接 **32 台模块**（`MAX_LINKED_MODULES` 硬上限），链接后按本队贴片数逐步激活（链接但未激活的模块不工作）：

| 本队贴片数 | 激活槽位 |
| --- | --- |
| 0 | 8 |
| 500,000 | 12 |
| 1,000,000 | 16 |
| 1,500,000 | 20 |
| 完工（2,000,000） | 32 |

- 激活规则：控制器定期重算，超出激活数的模块被 `disconnect()`；后 12 槽**只在完工后启用**。
- **主方块 GUI**：终端区域实时显示本队云 / 框架 / 贴片与机主个人组件库存，便于监控。

## 四、模块体系

所有模块继承 `DysonModuleBase`（基于 `OrundumWirelessMultiMachineBase`）。**链接方式：GT 数据棒左键核心保存坐标 → 右键模块完成绑定**（GT5U 净化水厂同款交互）：

- 无距离限制；但核心与模块必须在同一维度，且双方区块同时加载才能工作（40 tick 心跳窗口不变）。
- 链接权限：机主本人或同队成员；无显式解绑操作（拆方块自动解绑，重新绑定自动替换）。
- 链接关系持久化在**模块侧 NBT**（控制器坐标），核心侧链接列表仅运行时缓存；服务器重启后模块每 100 tick 自动重连。
- 模块自身仍是独立成型的小多方块（制造 5×3×3 带输入总线/仓，发射/全量/接收 3×3×3），不依赖核心结构。

`DysonModuleBase` 契约：

- `getModuleType()`：`MANUFACTURING / LAUNCH / RECEIVER / FUNCTIONAL`；
- `getRequiredPaste()`：启用所需的贴片数，默认 `0`（保留给未来“功能性模块”设门槛）；
- `getRequiredCompute()`：本模块固定算力需求（制造 10,000、发射 100,000、接收 0）；
- `connect() / disconnect() / isConnected()`：由核心控制，断开时不 tick、不结算；
- 自身业务走 `doWirelessBusinessOnce()` 等无线基类钩子，能量只走第二节的两本账。

当前三种模块门槛均为 **0 贴片**。

## 五、三种模块

### 1. 制造模块

- 结构：独立成型的小多方块（5×3×3），含**输入总线 + 输入仓**（物品与流体原料入口）。
- 配方：64 源石 → **64 戴森云组件**；64 息壤 → **512 框架组件**。结算后组件**计入机主个人库存**，不产出实体。
- 基准节奏：**基础一轮 30 秒，基础并行 64**（升级树可缩短一轮时间、提升并行）。
- 成本：每 tick 基准（云 10 亿 Orundum/t、框架 50 亿 Orundum/t）× 实际时长 × 并行，**全额计入队伍 Orundum 账本**。
- 0 贴片门槛；完工后仍可工作（组件可作他用）。

### 2. 发射模块

- 输入：从**机主个人组件库存**扣云/框架组件（1 组件 = 1 计数），发射后计入队伍公共计数。
- 基准节奏：**基础周期 10 秒，单轮最多 16 组件**（升级树可缩短周期、提升批量）。
- 类型选择：未解锁“双轨发射”时每周期只发射一种组件，按模块 GUI 的**云优先 / 框架优先**设置选择；
  优先类型无库存时不回退、不发射。解锁双轨后云与框架各自按批量独立发射（最高各 128，共 256）。
- 效果：`DysonSphereSystem.consumeComponentsOfPlayer(...)` + `addModules(teamId, cloudDelta=+1 或 frameDelta=+1)`，1 组件 = 1 计数。
- 成本：每个组件 `10,000` Orundum，**全额计入队伍 Orundum 账本**。
- 0 贴片门槛；**完工后永久失效**（`addModules` 返回 false）。
- 无需物品/流体舱室；多台发射模块可并行，共同推进本队计数器。

### 3. 接收模块

- **每队至多 1 台**（不限挂在哪位队员的核心上）：先被核心识别且条件满足的保持连接，后到的断开；
  已连接者失效后队内其他接收机可接管（防止叠接收机刷功率）。
- 输出：本队当前功率池全额，单位 **EU/t**，每 1 秒（20 tick）结算一次，单次入账 = `P × 20`：
  - 完工前：`P = cloudCount × 2^41 + pasteCount × 2^79`；
  - 完工后（仅占领者）：`P = 10^200` 固定。
- 结算：机器 GUI 里打开拆分窗口，输入 **Orundum 占比（0~100）**——如输入 40，则 40% 入 Orundum、60% 入无线 EU；
  默认 100（全 Orundum）。完工满功率同样按此拆分。两本账均为**团队账本**（Orundum 与无线 EU 都落到队长池）。
- 0 贴片门槛；戴森云无需框架即可发电，纯云路线可用。

### 4. 全量发射模块

- **使用权**：需队伍点亮“全量发射”大节点；未点亮时模块可成型但不工作。
- 节奏：**固定一轮 60 秒**，不受发射效率/批量升级影响；每轮把**机主个人名下的全部云/框架组件**一次性发射，
  计入队伍公共计数（1 组件 = 1 计数）。
- 上限保护：受队伍云 5 万 / 框架 50 万上限钳制，超出容量部分留在个人库存不扣。
- 成本：每个组件 `10,000` Orundum，**全额计入队伍 Orundum 账本**；算力需求 100,000。
- 完工后永久失效；无需物品/流体舱室。

## 六、完工后

- 发射模块与一切发射行为永久锁死（含占领者）。
- 后 12 槽解锁，供**接收模块与未来功能性模块**使用。
- 占领者剩余轨道云按每日掉落递减至 0；球壳以 10^200/tick 供能。

## 七、算力需求

戴森核心与模块是我们自有无线算力系统的消费者，需求按台结算（BigInteger）：

| 对象 | 算力需求 |
| --- | --- |
| 戴森核心 | 1,000,000 |
| 制造模块（每台） | 10,000 |
| 发射模块（每台） | 100,000 |
| 接收模块 | 0 |

- 需求从机器 owner 的个人算力网络结算（可经 `/ocgroup` 组内共享，沿用现有 `WirelessComputeHelper` 语义）。
- 核心算力不足 → 核心停机、全部模块断开；单台模块算力不足 → 该模块断开。
- 后续新增的功能性模块自行声明需求。

## 八、升级树

- 模仿 God Forge 的 `ForgeOfGodsUpgrade` + `UpgradeStorage` 结构：节点枚举声明前置/花费/UI，存储负责解锁与 NBT。
- **存储为队伍级**（`DysonTeamProgress.upgrades`，随存档持久化）：所有队员的核心/模块共享同一棵升级树。
- **货币**：升级需要**奇异物质**（普通节点 1、大节点 3），储存在解锁者的核心中，解锁时连同投料物品一起扣；
  两者是**独立判定**：物品够、物质不够，或反之，都无法点亮。解锁的是**团队树**，离队后不回退。
- 节点（17 个）：

| 节点 | 类型 | 前置 | 效果 |
| --- | --- | --- | --- |
| START 核心激活 | 基础 | 无 | 核心基础功能（默认激活） |
| 制造效率 I / II / III | 效率 | 逐级 | 一轮时间 30s → 15s → 10s → 5s |
| 制造并行 II / III | 并行 | 逐级（单独支线） | 基础并行 64 → 128 → 512；III 另有 20% 概率每轮额外产出 100~200 倍配方产物 |
| 发射效率 I / II | 效率 | 逐级 | 一轮时间 10s → 5s → 2s |
| 发射批量 I / II | 批量 | 逐级（单独支线） | 单轮批量 16 → 64 → 128 |
| 双轨发射 | 大节点 | 发射效率 II **且** 发射批量 II | 解锁云+框架同发（各自按批量） |
| 全量发射 | 大节点 | 双轨发射 | 解锁全量发射模块（60 秒一轮，一次性发射机主全部组件） |
| 贴片转化 | 效率（分叉） | START | 云→贴片结算由每天一次加快为每半天一次；需队伍核心开机 |
| 掉落减免 | 效率（分叉） | START | 每日掉落 10~64 → 8~48 |
| 接收强化 | 效率 | 贴片转化 或 掉落减免（二选一） | 每日掉落的云按 50% 回收为云组件，归正在工作的接收模块机主 |
| 能量分配 | 大节点 | 接收强化 | 解锁接收模块 EU/Orundum 百分比分配 |
| 自动喷出 | 大节点 | 能量分配 | 核心每 1 秒自动把奇异物质喷出到输出总线（无总线时留在核心） |

- 贴片转化与掉落减免为**互斥分叉**（最多激活一个）。
- 每日结算节奏：默认每天 0:00 一次（先贴片、后掉落）；点亮贴片转化后 0:00 与 12:00 各转化一次，掉落仍在 0:00 结算。
- **本段状态：升级树的机制、数值与运行效果均已定稿并接入；节点名称、效果文案与数值细节已于 2026-08-14 统一修订（含掉落减免、能量分配效果接入）。**
