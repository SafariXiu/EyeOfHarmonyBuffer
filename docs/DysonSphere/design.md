# 塔罗斯戴森球（Dyson Sphere）设计文档

> 本文件是戴森球系统的唯一设计记录，随开发实时更新。

## 一、概念

在塔罗斯维度围绕天上恒星建造戴森球。玩家/队伍通过发射机不断把戴森云组件与框架组件打上轨道，
天空盒中的恒星会随进度被逐步遮蔽；完工时全服公告，且该戴森球永久归属第一个占领者。

## 二、独占规则

- 第一个启动发射机的玩家/队伍（沿用 Orundum 电网的队伍语义）成为**占领者**。
- 其他玩家/队伍尝试建造时被拒绝，提示“戴森球已被 XX 占领”。
- 多个玩家可以同时建造：同队伍的玩家进度共享、可并行加速。
- **完工判定**：某组/玩家完成后：
  - 全服广播公告；
  - 其他所有未完成组的进度**瞬间清零**；
  - 未来不再允许任何人建造（发射机永久拒绝工作，包括占领者自己）。
- 完成后戴森云**不再提供发电**，也**不能再打云**；轨道上剩余的云组件会慢慢掉落（供回收/后续用途）。

## 三、机器（至少 3 台，均走 Orundum 无线多块机体系）

| 机器 | 职责 |
| --- | --- |
| 戴森组件制造机 | 原料 → 产出“戴森云组件”/“框架组件”中间物品 |
| 戴森发射机 | 消耗组件 + 无线 EU/Orundum → 增加云/框架数量；承担占领判定 |
| 戴森能量接收机 | 按进度接收恒星能量（未完工部分功率 / 完工后满功率，待定） |

后续规划：戴森云可**独立发电**，发电时**不定时掉落云组件**；纯戴森云路线**不需要打框架**。

## 四、数量模型（核心数值）

### 戴森云

- 至少 **30,000** 个才形成“3 级戴森云”（天空盒显示三个环）。
- 上限 **50,000** 个。
- 超过 30,000 的部分（即 30,000 ~ 50,000 之间的增量）才可以**向框架转换**（贴到戴森球框架上成为球体的一部分）。

### 框架

- 至少 **50,000** 个框架才能开始贴云（接收云 → 球体）。
- 框架阶段（中间 3 段 + 建成）：

| 框架数量 | 阶段 |
| --- | --- |
| 50,000 | 框架阶段 1 |
| 150,000 | 框架阶段 2 |
| 300,000 | 框架阶段 3 |
| 500,000 | **建成（完工）** |

- 建成后：恒星被完全遮蔽；戴森云停止发电、禁止再打；剩余云组件慢慢掉落。

## 五、天空盒动画阶段（当前测试用 `/dyson stage <1-5>`）

| 阶段 | 云 | 框架 | 视觉 |
| --- | --- | --- | --- |
| 1 | 1 环（赤道）100% | 无 | 全是戴森云 |
| 2 | 2 环（赤道 + 30°）100% | 25% | 云 + 少量框架 |
| 3 | 3 环（赤道 + 30° + 120°）50% 密度 | 50% | 半云半框架 |
| 4 | 1 环 15% 密度 | 80% | 框架为主 + 少量云 |
| 5 | 无 | 100%（球壳） | 完工：太阳完全遮蔽，缝隙漏幽暗蓝光 |

### 戴森云环（渲染）

- 环半径远大于球壳（`RING_RADIUS = 56`，球壳 `RADIUS = 29`，太阳距离 `SUN_DISTANCE = 100`），类似星环。
- 每个环：若干云组件扁片沿环绕恒星公转；组件转到背向玩家一侧时隐藏。
- 三环朝向：赤道环 → 与赤道成 30° → 与赤道成 120°。
- 各环公转速度不同，带相位偏移；速度倍率当前为原速的 **20%**（`CLOUD_SPEED_MULTIPLIER = 0.2`）。
- **环体（立体）**：组件径向漂浮 ±2.8、上下（环法线方向）漂浮 ±2.2（`RING_HALF_HEIGHT`），
  每片绕切线轴随机倾斜 ±34°、厚度 0.35~0.75，按“远 → 近”排序绘制形成前后遮挡。
- 所有旋转角度使用**连续世界时间**（不取模），避免游戏午夜时间回零导致跳变闪烁。

## 五·补充：云/框架双参数驱动渲染

渲染不再绑定固定阶段，而是由两个独立数量直接驱动（同一渲染器内的两个图层）：

### 戴森云 → 环数/密度

| 可见云数量（取 min(云, 30,000)） | 环数 |
| --- | --- |
| 0 | 无 |
| 1 ~ 9,999 | 1 环（赤道） |
| 10,000 ~ 19,999 | 2 环（+30°） |
| 20,000 ~ 30,000 | 3 环（+120°） |

- 组件密度 = 可见云数量 / 30,000（云越少越稀）。
- **超过 30,000 的部分视为已向框架转换，不再显示在环上**。

### 框架 → 覆盖率/球壳

| 框架数量 | 覆盖率 |
| --- | --- |
| < 50,000 | 0（无框架） |
| 50,000 ~ 150,000 | 0.25 → 0.5 |
| 150,000 ~ 300,000 | 0.5 → 0.8 |
| 300,000 ~ 500,000 | 0.8 → 1.0 |
| 500,000 | 完工球壳 + 蓝光缝隙 |

- 完工后云环强制不显示（剩余云按后续设计慢慢掉落）。

### 测试指令

```
/dyson stage <1-5>          # 数量预设（1: 云1万 / 2: 云2万+框架5万 / 3: 云3万+框架15万 /
                            #  4: 云5千+框架30万 / 5: 框架50万完工）
/dyson cloud <数量>          # 直接设云数量（0-50000）
/dyson frame <数量>          # 直接设框架数量（0-500000）
/dyson reset                # 重置
```

## 六、渲染技术要点

- 渲染器：`space/talos/client/render/DysonSphereRenderer.java`，挂在
  `HugePlanetSkyRenderer`（太阳光晕之后、塔罗斯星球之前）。
- 球心跟随太阳（太阳绘制在距离原点 100 处，绕 Z 旋转），球心世界坐标由角度实时计算。
- 球体姿态：极轴绕 Z 翻转 90° 后位于目视左右，赤道竖直正对玩家；
  叠加三轴慢速自转（每游戏日约 36° / 12° / 6°），有轻微翻滚。
- 天空盒禁用深度测试：所有结构按“前半球”逐顶点/面片裁剪，
  视线方向被变换到球体局部坐标系（与 GL 旋转顺序一致），线段跨边界做插值裁剪，
  避免戴森球背面穿帮。裁剪边界取球体真实可见轮廓线：以太阳为原点、指向玩家的
  单位向量为视线方向时，透明结构（框架/云环）采用“保守裁剪 + 边缘虚化”：
  硬边界取球体自身轮廓线再放宽一点，框架阈值 `FRAME_FRONT_CLIP ≈ 11.4`
  （虚化带 3.0），云环阈值 `CLOUD_FRONT_CLIP ≈ 39.4`（虚化带 8.0）；
  边界外不绘制，边界带内透明度渐变为 0，避免远半球边缘插进太阳盘。
  完工球壳是实心的，可见边界仍取球体自身轮廓线 `SHELL_FRONT_CLIP = R²/D ≈ 8.41`
  （单位向量阈值 `R/D = 0.29`）。
- 完工球壳：深蓝黑前半球壳 + 8 条经线 / 3 条纬线亮蓝缝隙 + 外围幽蓝光晕。
