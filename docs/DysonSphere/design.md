# 塔罗斯戴森球（Dyson Sphere）设计文档

> 本文件是戴森球系统的唯一设计记录，随开发实时更新。
> 机器系统（核心 + 模块 + 升级树）见同目录 [README.md](./README.md)。

## 一、概念

在塔罗斯维度围绕天上恒星建造戴森球。玩家/队伍通过发射机不断把戴森云组件与框架组件打上轨道：

- **戴森云组件**进入本队轨道云池：可见星环 + 基础发电 + 每日损耗；
- **框架组件**构成本队球壳骨架：只提供贴片容量，不发电；
- 每 128 个轨道云会在每日结算时自动“贴片”到骨架上，贴片是球壳的实际覆盖物，也是发电主体与完工进度条；
- 天空盒中的恒星随**领先队伍**的进度被逐步遮蔽；某队贴片打满时球壳完工，全服公告，戴森球永久归属该队。

## 二、赛跑规则（多队并行）

- 各玩家/队伍可同时建造、互不排斥；每队独立维护三份计数：`cloudCount / frameCount / pasteCount`。
- 队伍语义沿用 Orundum 电网：`OrundumEnergyService.getTeamIdForUser(playerUUID)`（空间工程队长）。不使用 `/ocgroup` 算力组。
- 天空盒全服共享，显示**当前领先队伍**的状态。领先者按贴片进度 `pasteCount / 2,000,000` 排序，并列按框架数，再并列按首次发射时间。
- **完工判定**：某队 `pasteCount >= 2,000,000` 即**自动完工**：
  - 全服广播公告；
  - 其他所有队伍的云/框架/贴片进度**瞬间清零**；
  - 全服永久锁死发射机（包括占领者自己）；
  - 占领者剩余轨道云继续按天掉落至 0，云停止发电，球壳改以完工功率供能。

## 三、机器（至少 3 台，均走 Orundum 无线多块机体系）

| 机器 | 职责 |
| --- | --- |
| 戴森组件制造机 | 原料 → 产出“戴森云组件”/“框架组件”中间物品 |
| 戴森发射机 | 消耗组件 + 无线 EU/Orundum → 增加本队云/框架计数（1 个组件 = 1 计数） |
| 戴森能量接收机 | 按本队云+贴片功率接收能量（结算逻辑待单独设计）；完工后以队级唯一通道输出完工功率 |

贴片不需要发射机单独操作：**云 → 贴片的转换发生在每日结算**（见第四节）。

## 四、数量模型与发电数值（定稿）

### 三计数器（每队）

| 池 | 语义 | 上限 |
| --- | --- | --- |
| 轨道云 | 发电 + 贴片原料 + 星环视觉 | 50,000 |
| 框架 | 只提供贴片容量 + 骨架视觉 | 500,000 |
| 贴片 | 完工进度条 + 发电主体 + 球壳视觉 | 4 × 框架（满 2,000,000） |

### 每日结算（每 MC 天 24,000 tick，按队独立）

顺序固定：**先贴片，后掉落**。

1. 贴片：`batches = min(cloudCount / 128, 4 × frameCount - pasteCount)`；`pasteCount += batches`，`cloudCount -= batches × 128`。
2. 掉落：若 `cloudCount > 0`，`cloudCount -= rand(10, 64)`（下限 0）。
3. 完工判定：`pasteCount >= 2,000,000` → 自动完工。

`4 × frameCount - pasteCount > 0` 蕴含 `frameCount > 0`：没建框架的纯云队不会被转走云，纯云发电玩法保留。

### 发电数值

| 单位 | 公式 | 数值（EU/t 等效） |
| --- | --- | --- |
| 1 片云 | 1024 × MAX | ≈ 2.199 × 10^12 |
| 完整云（5 万满池） | × 50,000 | ≈ 1.100 × 10^17 |
| 1 贴片 | 128 × 1024 × MAX² = 2^79 | ≈ 6.045 × 10^23 |
| 满贴片（200 万，完工前峰值） | ≈ 2^100 | ≈ 1.209 × 10^30 |
| 完整戴森球（完工后） | 固定常数 | 1 × 10^200 |

完工前每队每 tick：

```
P = cloudCount × 2^41 + pasteCount × 2^79
```

单位：**EU/t**；入账全部进 Orundum 账本（1 EU ≡ 1 Orundum），两套无线系统均为 BigInteger 记账；
接收侧每 1 秒（20 tick）批量结算一次：每秒入账 = 功率 × 20，完工每秒入账 2 × 10^201（接收模块专属结算逻辑后续单独设计）。
完工后输出为固定 10^200 EU/t 等效，队级唯一通道。完工功率常数为 `MainConfig` 字符串配置项。

## 五、天空盒动画阶段（测试用 `/dyson stage <1-5>`）

| 阶段 | 云 | 框架 | 贴片 | 视觉 |
| --- | --- | --- | --- | --- |
| 1 | 10,000 | 0 | 0 | 1 环（赤道）云 |
| 2 | 20,000 | 50,000 | 50,000 | 云 + 25% 骨架 |
| 3 | 30,000 | 150,000 | 300,000 | 半云半骨架 |
| 4 | 5,000 | 300,000 | 600,000 | 骨架为主 + 少量云 |
| 5 | 0 | 500,000 | 2,000,000 | 完工：太阳完全遮蔽，缝隙漏幽暗蓝光 |

### 戴森云环（渲染）

- 环半径远大于球壳（`RING_RADIUS = 56`，球壳 `RADIUS = 29`，太阳距离 `SUN_DISTANCE = 100`），类似星环。
- 每个环：若干云组件扁片沿环绕恒星公转；组件转到背向玩家一侧时隐藏。
- 三环朝向：赤道环 → 与赤道成 30° → 与赤道成 120°。
- 各环公转速度不同，带相位偏移；速度倍率当前为原速的 **20%**（`CLOUD_SPEED_MULTIPLIER = 0.2`）。
- **环体（立体）**：组件径向漂浮 ±2.8、上下（环法线方向）漂浮 ±2.2（`RING_HALF_HEIGHT`），
  每片绕切线轴随机倾斜 ±34°、厚度 0.35~0.75，按“远 → 近”排序绘制形成前后遮挡。
- 所有旋转角度使用**连续世界时间**（不取模），避免游戏午夜时间回零导致跳变闪烁。

## 五·补充：云/框架/贴片三参数驱动渲染

渲染不再绑定固定阶段，而是由三个独立数量直接驱动（同一渲染器内的三个图层）：

### 戴森云 → 环数/密度

| 可见云数量（取 min(云, 30,000)） | 环数 |
| --- | --- |
| 0 | 无 |
| 1 ~ 9,999 | 1 环（赤道） |
| 10,000 ~ 19,999 | 2 环（+30°） |
| 20,000 ~ 30,000 | 3 环（+120°） |

- 组件密度 = 可见云数量 / 30,000（云越少越稀）。
- 超过 30,000 的部分不显示在环上（仍在轨道池中，等待每日结算贴片）。

### 框架 → 骨架覆盖率

| 框架数量 | 骨架视觉 |
| --- | --- |
| < 50,000 | 棱/节点从节点向外生长 |
| >= 50,000 | 棱/节点全部铺完（纯骨架，等待贴片覆盖） |

- 骨架只是容量与视觉，**不再触发完工**；面板覆盖率由贴片率决定。

### 贴片 → 球壳覆盖与完工

| 贴片率（pasteCount / 2,000,000） | 视觉 |
| --- | --- |
| 0 | 无球壳面板 |
| 0 ~ 1 | 面板随贴片率逐渐铺满 |
| 1 | 完工球壳 + 蓝光缝隙；云环强制隐藏 |

- 完工触发由 `pasteCount >= 2,000,000` 判定（原 `frameCount >= 500,000` 条件作废）。
- 完工后云环强制不显示（剩余轨道云按每日掉落慢慢消失）。

### 测试指令

```
/dyson stage <1-5>          # 数量预设（云/框架/贴片三参数）
/dyson cloud <数量>          # 直接设云数量（0-50000）
/dyson frame <数量>          # 直接设框架数量（0-500000）
/dyson paste <数量>          # 直接设贴片数量（0-2000000）
/dyson reset                # 重置
```

## 六、渲染技术要点

- 渲染器：`space/talos/client/render/DysonSphereRenderer.java`，挂在
  `HugePlanetSkyRenderer`（太阳光晕之后、塔罗斯星球之前）。
- 球心跟随太阳（太阳绘制在距离原点 100 处，绕 Z 旋转），球心世界坐标由角度实时计算。
- 球体姿态：极轴绕 Z 翻转 90° 后位于目视左右，赤道竖直正对玩家；
  叠加三轴慢速自转（每游戏日约 36° / 12° / 6°），有轻微翻滚。
- 天空盒禁用深度测试：所有结构按“前半球”逐顶点/面片裁剪，
  视线方向被变换到球体局部坐标系（与 GL 旋转顺序一致），线段跨边界做插值裁剪，
  避免戴森球背面穿帮。裁剪边界取球体真实可见轮廓线：以太阳为原点、指向玩家的
  单位向量为视线方向时，透明结构（框架/云环）采用“保守裁剪 + 边缘虚化”：
  硬边界取球体自身轮廓线再放宽一点，框架阈值 `FRAME_FRONT_CLIP ≈ 11.4`
  （虚化带 3.0），云环阈值 `CLOUD_FRONT_CLIP ≈ 39.4`（虚化带 8.0）；
  边界外不绘制，边界带内透明度渐变为 0，避免远半球边缘插进太阳盘。
  完工球壳是实心的，可见边界仍取球体自身轮廓线 `SHELL_FRONT_CLIP = R²/D ≈ 8.41`
  （单位向量阈值 `R/D = 0.29`）。
- 完工球壳：深蓝黑前半球壳 + 8 条经线 / 3 条纬线亮蓝缝隙 + 外围幽蓝光晕
  （半径约 1.6 倍球壳，16 层由内向外透明度逐渐拉低的柔和光晕）。
- 框架棱上带有流动能量光斑：贴片覆盖过半（面板铺设过半）起才显示，外圈柔光 + 亮核两层，
  沿棱匀速流动，相位按黄金分割比例错开，走完整条棱约 2.5 秒。

### 天空变暗（戴森阴影）

- 框架数量越高，恒星被封锁越多，塔罗斯天空整体变暗（纯渲染，不改光照/地形）。
- 数值：`DysonSphereState.getSkyDarkness()`，按框架阈值连续插值：
  <5 万 → 0；5 万 → 0.12；15 万 → 0.32；30 万 → 0.55；50 万 → 0.85。
  定稿后改为 `max(框架率, 贴片率)` 驱动，完工由贴片满触发。
- 实现：`HugePlanetSkyRenderer` 在太阳/光晕之后、戴森球之前铺一层覆盖视口的
  深蓝黑色阴影；戴森球结构与其发光条纹保持亮度，气态行星按 45% 幅度随暗度变暗。
- 地形不受影响；后续如需整体“日食”效果，可再联动 fog / 光照。
